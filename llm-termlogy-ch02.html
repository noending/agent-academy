Transformer 架构：自注意力、多头注意力与位置编码

想象你在读一句话“小猫追着球跑，因为它很兴奋”。当读到“它”时，你的大脑会自动回指“小猫”，而不是“球”。Transformer 的自注意力机制就是在模拟这种“全局回看”的能力：序列中的每个词都能直接与所有其他词计算相关性，而不像 RNN 那样必须一步步传递信息。这种设计让模型可以并行处理整个序列，训练速度大幅提升。

具体来说，自注意力（Self-Attention）为每个词向量生成三个角色：Query（我在找什么）、Key（我能提供什么）、Value（我实际携带的信息）。用当前词的 Query 与所有词的 Key 做点积，得到注意力分数，再经过 Softmax 归一化，最后用这些权重对 Value 加权求和。公式为：Attention(Q, K, V) = softmax(QK^T / sqrt(d_k)) V。除以 sqrt(d_k) 是为了防止点积过大导致 Softmax 进入饱和区、梯度消失。举个例子：如果 d_k=64，点积结果可能达到几十甚至上百，除以 8 后数值更稳定，训练更容易收敛。

多头注意力（Multi-Head Attention）则是把自注意力并行做多次（比如 8 个头），每个头学习不同的关注模式——有的头可能关注语法依存，有的头关注指代关系，有的头关注相邻词。最后把所有头的输出拼接并线性变换。你可以把它理解为“八个专家同时从不同角度审阅同一句话，最后汇总意见”。

由于自注意力本身不包含顺序信息（打乱词序，计算结果只跟位置对应关系有关），Transformer 引入了位置编码（Positional Encoding）。原始论文使用正弦和余弦函数生成固定编码，后来也常用可学习的位置嵌入。位置编码与词嵌入相加，让模型知道“谁在前、谁在后”。如果没有位置编码，模型无法区分“狗咬人”和“人咬狗”。

下面是一个极简的自注意力实现，帮助你直观理解计算过程。输入是一个形状为 (1, 3, 4) 的随机张量（batch=1，序列长度=3，维度=4），输出形状保持不变，但每个位置的向量已经融合了全局信息：

python
import torch
import torch.nn.functional as F

# 假设 batch=1, 序列长度=3, 维度=4
torch.manual_seed(0)
x = torch.randn(1, 3, 4)  # 输入序列
W_q = torch.nn.Linear(4, 4)
W_k = torch.nn.Linear(4, 4)
W_v = torch.nn.Linear(4, 4)

Q = W_q(x)  # (1, 3, 4)
K = W_k(x)
V = W_v(x)

scores = torch.matmul(Q, K.transpose(-2, -1)) / (4 ** 0.5)  # (1, 3, 3)
attn = F.softmax(scores, dim=-1)
out = torch.matmul(attn, V)  # (1, 3, 4)
print(out.shape)  # torch.Size([1, 3, 4])

记住：Transformer = 自注意力 + 多头 + 位置编码 + 前馈网络 + 残差连接 + 层归一化。这些组件堆叠起来，就构成了 GPT、BERT 等模型的基础。残差连接让梯度可以绕过深层网络直接回传，层归一化则稳定每层的输入分布，两者共同保证深层模型可训练。

Token 与 Tokenization：子词切分、BPE 与 WordPiece

LLM 不直接处理文字，而是处理 Token——可以理解为“词片”或“子词”。你可以把 Tokenization 想象成把一整块乐高拆成标准零件：零件太大（整词）则组合不灵活、遇到新词就傻眼；零件太小（单字符）则序列太长、计算成本高。子词切分正好在两者之间取得平衡。

BPE（Byte Pair Encoding）是最常用的子词算法之一。它从字符开始，反复合并出现频率最高的相邻字符对，直到达到预设的词表大小。例如，语料中“low”和“lower”频繁出现，BPE 可能先合并出 low，再单独保留 er 作为后缀。GPT 系列、RoBERTa 都使用 BPE 的变体。词表大小通常设为 3 万到 5 万，既能覆盖常见词，又能用子词拼出罕见词。

WordPiece 是 BERT 使用的算法，与 BPE 类似，但合并时选择能最大化语言模型似然的字符对，而不是单纯看频率。它用 ## 前缀表示子词是词的延续，比如 playing 可能切成 play + ##ing。这种标记方式让模型能区分“词首”和“词中”的子词。

Tokenization 直接影响模型的行为：同样的句子，不同 tokenizer 切出的 Token 数量不同，进而影响上下文长度、推理成本和生成质量。例如，英文句子“Tokenization is fun!”在 BERT 的 WordPiece 下可能切成 5 个 Token，而中文句子“今天天气很好”可能每个汉字对应一个 Token 或更少。Token 数越多，同样的上下文窗口能容纳的内容越少，API 计费也越高。

下面用 Hugging Face 的 tokenizer 观察实际切分效果。输入是句子 "Tokenization is fun!"，输出是切分后的 Token 列表和对应的 ID：

python
from transformers import AutoTokenizer

tokenizer = AutoTokenizer.from_pretrained("bert-base-uncased")
text = "Tokenization is fun!"
tokens = tokenizer.tokenize(text)
print(tokens)  # ['token', '##ization', 'is', 'fun', '!']
ids = tokenizer.convert_tokens_to_ids(tokens)
print(ids)

关键结论：Token 是模型处理文本的最小单位，Tokenization 策略决定了词表大小、序列长度和模型对罕见词的泛化能力。理解这一点，你就能明白为什么同样的提示词在不同模型上消耗的 Token 数不同，以及为什么某些拼写错误会导致模型表现异常。

嵌入与向量表示：词嵌入、位置嵌入与上下文嵌入

嵌入（Embedding）是把离散的 Token 映射到连续向量空间的技术。你可以把它想象成给每个词在一个高维地图上分配一个坐标：语义相近的词，坐标也相近。比如“猫”和“狗”的向量距离会比“猫”和“汽车”更近。这个向量通常是几百到几千维的稠密数组，模型后续的所有计算都基于这些向量。

词嵌入（Word Embedding）是静态的，每个词只有一个向量，与上下文无关。Word2Vec、GloVe 是经典方法。但同一个词在不同句子中含义可能不同——比如“苹果”指水果还是公司，静态嵌入无法区分。这就好比给每个词发了一张固定身份证，不管它出现在什么场合。

位置嵌入（Position Embedding）为每个位置生成一个向量，加到词嵌入上，让 Transformer 感知顺序。它可以是固定的正弦函数，也可以是可学习的参数。位置嵌入不关心词是什么，只关心它在第几位。

上下文嵌入（Contextual Embedding）则根据整个句子动态生成每个词的向量。BERT、GPT 等模型输出的就是上下文嵌入。同一个词在不同上下文中会有不同的向量表示，从而解决一词多义问题。例如，“bank”在“river bank”和“bank account”中的向量会明显不同。

下面演示如何用 BERT 获取上下文嵌入。输入句子 "I love apples."，输出是每个 Token 的 768 维向量，形状为 (1, seq_len, 768)：

python
from transformers import BertTokenizer, BertModel
import torch

tokenizer = BertTokenizer.from_pretrained("bert-base-uncased")
model = BertModel.from_pretrained("bert-base-uncased")

inputs = tokenizer("I love apples.", return_tensors="pt")
with torch.no_grad():
    outputs = model(**inputs)

last_hidden = outputs.last_hidden_state  # (1, seq_len, 768)
print(last_hidden.shape)

记住：词嵌入是静态的，上下文嵌入是动态的；位置嵌入负责注入顺序信息。三者共同构成了 LLM 的输入表示层。理解它们的区别，你就能明白为什么 BERT 适合做语义相似度任务，而 Word2Vec 更适合做快速检索。

训练与推理术语：批处理、学习率、温度与 Top-p 采样

训练和推理阶段有一堆术语，理解它们才能调参和读懂技术文档。先建立直觉：训练就像学生刷题，批处理是每次做几道题，学习率是每次订正时改多少；推理就像考试答题，温度决定你多大胆地选答案，Top-p 决定你从几个候选中挑。

批处理（Batch Size）指一次前向/反向传播处理的样本数量。大批量训练更稳定、GPU 利用率高，但需要更多显存；小批量则噪声大，可能有助于泛化。例如，批大小从 8 增加到 64，梯度估计更准，但显存占用可能翻几倍，需要配合学习率调整。

学习率（Learning Rate）控制参数更新的步长。太大容易震荡不收敛，太小则训练缓慢。常用预热（warmup）和衰减策略：训练初期用小学习率预热，避免早期梯度爆炸；后期逐步衰减，让模型精细收敛。

推理阶段，温度（Temperature）用于调整 Softmax 输出的概率分布。温度越低（如 0.1），分布越尖锐，模型更倾向于选择概率最高的词，输出更确定；温度越高（如 1.5），分布越平坦，输出更随机、有创意。公式为 softmax(logits / T)。举个例子：原始 logits 为 [2.0, 1.0, 0.5]，T=0.5 时最高概率可能超过 0.9，T=1.5 时最高概率可能降到 0.5 左右。

Top-p 采样（Nucleus Sampling）又称核采样。它从累积概率达到 p（如 0.9）的最小词集合中采样，动态截断尾部。相比 Top-k 固定截断，Top-p 能根据分布形状自适应：分布尖锐时候选集小，分布平坦时候选集大，避免生成不连贯的文本。

下面用代码模拟温度与 Top-p 对采样分布的影响。输入是一组 logits，输出是采样得到的 Token 索引：

python
import torch
import torch.nn.functional as F

logits = torch.tensor([2.0, 1.0, 0.5, 0.1, -1.0])

def sample(logits, temperature=1.0, top_p=1.0):
    probs = F.softmax(logits / temperature, dim=-1)
    sorted_probs, sorted_idx = torch.sort(probs, descending=True)
    cumulative = torch.cumsum(sorted_probs, dim=-1)
    mask = cumulative > top_p
    mask[1:] = mask[:-1].clone()
    mask[0] = False
    sorted_probs[mask] = 0.0
    sorted_probs /= sorted_probs.sum()
    idx = torch.multinomial(sorted_probs, 1)
    return sorted_idx[idx].item()

print("T=0.5, top_p=0.9:", sample(logits, 0.5, 0.9))
print("T=1.5, top_p=0.9:", sample(logits, 1.5, 0.9))

总结：温度控制随机性，Top-p 控制候选集大小；两者常配合使用，例如 temperature=0.7, top_p=0.9。温度太低会让输出重复乏味，温度太高则可能胡言乱语；Top-p 太小会限制创意，太大则引入低质量候选。

常见误区

  • 错误理解：自注意力机制中，每个词只关注相邻的词。→ 后果：会误以为 Transformer 和 RNN 一样依赖局部窗口，无法理解长距离依赖，从而低估其在长文本任务上的能力。→ 正确做法：自注意力允许每个词关注序列中的所有词（包括它自己），注意力权重由 Query 和 Key 的点积决定，与距离无关。
  • 错误理解：Token 就是单词。→ 后果：会错误估算上下文长度和 API 成本，比如以为 1000 个单词就是 1000 个 Token，实际可能多出 30% 以上；也会困惑为什么模型对拼写错误敏感。→ 正确做法：一个单词可能被切分成多个 Token，一个 Token 也可能是一个子词或字符，具体取决于 tokenizer 的词表和切分算法。
  • 错误理解：温度越高，模型输出越准确。→ 后果：在需要事实准确的任务中调高温度，会导致模型随机选择低概率词，输出不准确甚至矛盾的内容。→ 正确做法：温度越高输出越随机、有创意，但可能不准确；温度越低输出越确定，但可能缺乏多样性。应根据任务选择：事实问答用低温（如 0.1~0.3），创意写作用高温（如 0.8~1.2）。

自测

请解释 Transformer 中多头注意力的作用，以及为什么需要位置编码？

答案：多头注意力让模型并行地从多个子空间学习不同的注意力模式。推理过程：单个注意力头只能输出一种加权组合，容易只关注某一种关系（比如相邻词）；把自注意力复制成 8 个头，每个头有独立的 Q/K/V 投影矩阵，就能分别捕捉语法依存、指代关系、语义相似等不同模式，最后拼接并线性变换，信息更丰富。位置编码的必要性在于：自注意力的计算是排列等变的——打乱输入顺序，输出只是跟着打乱，模型本身无法感知“谁在前谁在后”。如果不加位置编码，“狗咬人”和“人咬狗”的注意力分数集合相同，模型无法区分语义。位置编码与词嵌入相加，为每个位置注入唯一信号，模型才能利用顺序信息。

温度（Temperature）和 Top-p 采样在文本生成中分别起什么作用？

答案：温度调整 Softmax 输出的概率分布。推理过程：Softmax 的输入是 logits，除以温度 T 后再归一化。T<1 时，logits 差距被放大，高概率词更高、低概率词更低，分布更尖锐，输出更确定；T>1 时，差距被缩小，分布更平坦，输出更随机。Top-p 采样则从累积概率达到 p 的最小词集合中采样。推理过程：先把概率降序排列并累加，当累加和首次超过 p 时截断，只保留前面的词并重新归一化。这样候选集大小随分布形状自适应——分布尖锐时候选少，分布平坦时候选多。两者常结合使用：温度控制整体随机性，Top-p 控制候选集边界，共同平衡确定性和多样性。

词嵌入和上下文嵌入有什么区别？请结合“bank”这个词举例说明。

答案：词嵌入是静态的，每个词只有一个固定向量，与上下文无关；上下文嵌入是动态的，根据整个句子生成每个词的向量。推理过程：Word2Vec 训练完后，“bank”只有一个向量，无法区分“river bank”和“bank account”。BERT 等模型在每一层都让词与句子中其他词做注意力交互，因此“bank”在“I sat on the river bank.”中会吸收“river”的信息，在“I went to the bank to deposit money.”中会吸收“deposit”的信息，最终两个向量不同。实际计算余弦相似度时，两个“bank”向量的相似度通常低于 0.9，说明上下文嵌入确实区分了一词多义。

动手练习（带参考方案）

练习 · 使用 Hugging Face transformers 库，加载 bert-base-uncased 模型和 toke…

任务：使用 Hugging Face transformers 库，加载 bert-base-uncased 模型和 tokenizer，对句子 "The bank can guarantee deposits will eventually cover future tuition costs." 进行 Tokenization，并获取每个 Token 的上下文嵌入。然后比较单词 "bank" 在另一个句子 "I sat on the river bank." 中的嵌入向量，计算余弦相似度，观察上下文嵌入是否不同。验收标准：程序能正确输出两个句子中 "bank" 的向量形状（均为 768 维）以及余弦相似度数值，并打印 Token 列表。

参考方案：

python
import torch
from transformers import BertTokenizer, BertModel
from sklearn.metrics.pairwise import cosine_similarity

tokenizer = BertTokenizer.from_pretrained('bert-base-uncased')
model = BertModel.from_pretrained('bert-base-uncased')

def get_embedding(sentence, word):
    inputs = tokenizer(sentence, return_tensors='pt')
    with torch.no_grad():
        outputs = model(**inputs)
    tokens = tokenizer.convert_ids_to_tokens(inputs['input_ids'][0])
    print('Tokens:', tokens)
    idx = tokens.index(word)
    return outputs.last_hidden_state[0, idx].numpy()

emb1 = get_embedding('The bank can guarantee deposits will eventually cover future tuition costs.', 'bank')
emb2 = get_embedding('I sat on the river bank.', 'bank')
print('emb1 shape:', emb1.shape)  # (768,)
print('emb2 shape:', emb2.shape)  # (768,)
sim = cosine_similarity([emb1], [emb2])[0][0]
print(f'Cosine similarity: {sim:.4f}')
# 输出相似度通常低于 0.9，说明上下文嵌入不同。
