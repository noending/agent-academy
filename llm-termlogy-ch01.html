1.1 什么是语言模型：从统计到神经网络

想象你在玩一个“接龙”游戏：朋友说“今天天气”，你要猜下一个词最可能是什么。你可能会说“好”“不错”“真热”。语言模型（Language Model）做的就是这件事——给一个词序列打分，计算它出现的概率。概率越高，说明这个序列越“像人话”。比如，模型会给“今天天气好”打高分，给“今天天气吃”打低分。这个看似简单的任务，正是所有大语言模型（LLM）的根基。

最早的语言模型是统计语言模型，代表是 N-gram 模型。它基于马尔可夫假设：一个词出现的概率只与前面 N-1 个词有关。例如，二元语法（Bigram）只看前一个词。假设训练语料里“天气”后面出现过 100 次“好”、20 次“坏”，那么 P(好|天气) ≈ 100/120 ≈ 0.83。这种模型简单直接，但有两个致命伤：一是数据稀疏，很多词组合在训练语料里根本没出现，概率就是 0，比如“天气”后面接“量子”可能从未出现；二是无法捕捉长距离依赖，比如“我出生在法国，所以我会说一口流利的____”，要填“法语”，需要看到很远的“法国”，N-gram 只看前一个词，完全无能为力。

后来，神经网络语言模型出现了。它用词向量（Word Embedding）表示词，把每个词映射成一个稠密向量，语义相近的词在向量空间里也相近。比如“猫”和“狗”的向量距离会比“猫”和“汽车”近得多。这样，即使“天气”后面接“量子”在训练集里没出现过，模型也能根据“量子”和“好”在语义空间中的相似性给出一个合理的概率，缓解了稀疏问题。接着，用神经网络（如 RNN、LSTM）来建模整个序列的概率。RNN 理论上能记住任意长的历史，但实际中会有梯度消失，记不住太远的信息。直到 Transformer 出现，才真正解决了长距离依赖问题。

下面是一个用 Python 和 PyTorch 实现的最简单的 Bigram 神经网络语言模型，帮你直观感受一下“用神经网络预测下一个词”是怎么回事。代码假设词表只有 5 个词，训练数据是 4 个“输入词→下一个词”对。运行后，你会看到损失从初始值逐渐下降，最后打印出输入词 0 时下一个词的概率分布。虽然简单，但它已经包含了现代语言模型的基本思想：把词映射成向量，用神经网络学习概率分布。

python
import torch
import torch.nn as nn
import torch.optim as optim

# 假设词表只有 5 个词，用整数表示
vocab_size = 5
embedding_dim = 3

# 一个简单的 Bigram 模型：输入当前词，预测下一个词
class BigramLM(nn.Module):
    def __init__(self):
        super().__init__()
        self.embedding = nn.Embedding(vocab_size, embedding_dim)
        self.linear = nn.Linear(embedding_dim, vocab_size)
    def forward(self, x):
        emb = self.embedding(x)  # (batch, embed_dim)
        logits = self.linear(emb)  # (batch, vocab_size)
        return logits

model = BigramLM()
criterion = nn.CrossEntropyLoss()
optimizer = optim.Adam(model.parameters(), lr=0.01)

# 训练数据：输入词 -> 下一个词
inputs = torch.tensor([0, 1, 2, 3])
targets = torch.tensor([1, 2, 3, 4])

for epoch in range(100):
    optimizer.zero_grad()
    logits = model(inputs)
    loss = criterion(logits, targets)
    loss.backward()
    optimizer.step()
    if (epoch+1) % 20 == 0:
        print(f'Epoch {epoch+1}, Loss: {loss.item():.4f}')

# 预测：输入词 0，看下一个词概率
with torch.no_grad():
    logits = model(torch.tensor([0]))
    probs = torch.softmax(logits, dim=-1)
    print('下一个词概率分布:', probs.numpy())

运行这段代码，你会看到类似“Epoch 20, Loss: 1.2”的输出，损失逐渐下降，说明模型学会了根据当前词预测下一个词。最后打印的概率分布是一个 5 维向量，每个元素对应一个词的概率，总和为 1。这个例子虽然只有 5 个词，但它和 GPT 系列在本质上是同一套逻辑：用神经网络把输入词映射成向量，再映射回词表上的概率分布。区别只在于规模、数据和架构的复杂度。

1.2 LLM 的定义与特点：大规模、预训练、微调

如果把 1.1 节的 Bigram 模型比作一个只会接龙的小学生，那么大语言模型（Large Language Model, LLM）就是一个读过万卷书、能写会算的博学者。它的定义可以概括为：在海量文本上预训练、拥有超大规模参数（通常数十亿到数千亿）、能处理多种自然语言任务的神经网络模型。这个定义里有三个关键词：大规模、预训练、多任务。

先说大规模参数。参数越多，模型容量越大，越能记住复杂的语言模式和世界知识。比如 GPT-3 有 1750 亿参数，GPT-4 据传更大（具体数字未公开，待核实）。你可以把参数想象成大脑里的突触连接：连接越多，能记住和关联的信息就越多。但参数不是唯一因素，数据质量和训练方法同样关键。再说预训练（Pre-training）：先在大规模无标注文本上训练一个通用模型。预训练任务通常是“预测下一个词”（自回归，如 GPT 系列）或“完形填空”（掩码语言模型，如 BERT）。这一步让模型学到语法、语义和常识。最后是微调（Fine-tuning）：预训练后，用少量标注数据在特定任务上继续训练，让模型适应具体场景，比如情感分类、问答系统。微调就像让一个通才变成专才。

为什么预训练+微调这么有效？因为预训练让模型学到了通用的语言表示，微调只需要调整一点点参数就能适配新任务，大大减少了对标注数据的依赖。举个例子：从零训练一个情感分类器可能需要数万条标注数据，而基于预训练模型微调，几百条数据就能达到不错的效果。这也是 LLM 能“一个模型打天下”的基础。下面是一个用 Hugging Face Transformers 加载预训练模型并做简单微调（文本分类）的示例。注意：运行需要安装 transformers 和 datasets 库，并且需要下载模型，代码仅展示核心流程。

python
from transformers import AutoTokenizer, AutoModelForSequenceClassification, Trainer, TrainingArguments
from datasets import load_dataset

# 加载预训练模型和分词器（这里用一个小模型演示）
model_name = 'distilbert-base-uncased'
tokenizer = AutoTokenizer.from_pretrained(model_name)
model = AutoModelForSequenceClassification.from_pretrained(model_name, num_labels=2)

# 加载一个情感分类数据集
dataset = load_dataset('imdb', split='train[:100]')  # 只取100条演示

def tokenize(examples):
    return tokenizer(examples['text'], padding='max_length', truncation=True, max_length=128)

tokenized_dataset = dataset.map(tokenize, batched=True)

# 设置训练参数
training_args = TrainingArguments(
    output_dir='./results',
    num_train_epochs=1,
    per_device_train_batch_size=8,
    logging_steps=10,
)

trainer = Trainer(
    model=model,
    args=training_args,
    train_dataset=tokenized_dataset,
)

trainer.train()
print('微调完成！')

这段代码展示了微调的标准流程：加载预训练模型 → 准备数据 → 设置训练参数 → 训练。实际中，微调可能需要更多数据和计算资源，但核心思想不变：站在预训练的肩膀上，用少量数据解决具体问题。理解这一点，你就理解了现代 LLM 应用开发的基本范式。

1.3 LLM 的发展里程碑与核心能力

LLM 的发展史就像一部“架构进化史”，了解几个关键里程碑，能帮你读懂技术文档里的“行话”。首先是 GPT 系列（Generative Pre-trained Transformer）：OpenAI 出品，采用自回归（Autoregressive）方式，即从左到右预测下一个词。GPT-1、GPT-2、GPT-3 逐步扩大规模，GPT-3 展示了强大的少样本学习能力。GPT-4 支持多模态（图像+文本）。然后是 BERT（Bidirectional Encoder Representations from Transformers）：Google 出品，采用双向编码器，通过掩码语言模型（Masked Language Model, MLM）预训练，即随机遮住一些词让模型猜。BERT 擅长理解任务，如分类、问答。最后是 T5（Text-to-Text Transfer Transformer）：Google 出品，把所有任务都统一成“文本到文本”的格式，比如翻译是“翻译成英文: ...”，分类是“分类: ...”。这种统一框架影响深远。这些模型都基于 Transformer 架构，核心是自注意力机制（Self-Attention），能并行处理序列并捕捉长距离依赖。

LLM 的核心能力可以归纳为四点：生成（根据输入生成连贯的文本，如写文章、写代码）、理解（理解文本含义，如情感分析、实体识别）、推理（进行逻辑推理，如数学题、常识推理。虽然 LLM 的推理能力有限，但已经能解决不少问题）、上下文学习（In-context Learning）。上下文学习是 LLM 的“超能力”：不需要更新参数，只要在输入里给几个例子（Few-shot），模型就能学会新任务。比如给两个“英语→法语”的翻译例子，模型就能翻译新的英语句子。这大大降低了使用门槛——你不需要训练模型，只需要“教”它几个例子。

下面是一个用 GPT-2 演示上下文学习的例子（需要 transformers 库）。代码构造了一个包含两个翻译示例的提示，让模型续写第三个。运行后，模型可能会输出“fromage”之类的词。虽然 GPT-2 能力有限，但已经展示了上下文学习的雏形。在 GPT-3 等更大模型上，这种能力会更强。注意：GPT-2 的输出可能不完美，这正好说明上下文学习的效果与模型规模密切相关。

python
from transformers import pipeline

# 加载文本生成管道
generator = pipeline('text-generation', model='gpt2')

# 上下文学习：给两个例子，让模型续写第三个
prompt = """Translate English to French:
sea otter => loutre de mer
peppermint => menthe poivrée
cheese =>"""

# 生成结果
result = generator(prompt, max_length=50, num_return_sequences=1)
print(result[0]['generated_text'])

运行这段代码，你会看到模型在“cheese =>”后面续写的内容。如果输出是“fromage”，说明模型成功利用了上下文中的翻译模式；如果输出不理想，也不要灰心，因为 GPT-2 只有 15 亿参数，而 GPT-3 有 1750 亿参数，规模差距巨大。这个例子告诉我们：上下文学习不是魔法，而是规模带来的涌现能力。理解这一点，你就能理性看待各种“LLM 神奇表现”的宣传。

常见误区

  • 误区：LLM 只是“更大的 N-gram 模型”。错误理解：认为 LLM 和 N-gram 没有本质区别，只是参数更多。会导致什么后果：低估 LLM 的泛化能力和上下文学习能力，在设计应用时错误地依赖局部词频统计，忽视提示工程和语义理解。正确做法：认识到 LLM 基于神经网络和注意力机制，能捕捉长距离依赖和复杂语义，与 N-gram 有本质区别；N-gram 是统计方法，LLM 是表示学习方法。
  • 误区：预训练和微调是一回事。错误理解：把预训练和微调混为一谈，认为都是“训练模型”。会导致什么后果：在需要快速适配新任务时，错误地从零训练模型，浪费大量数据和算力；或者误以为微调可以替代预训练。正确做法：预训练是在海量无标注数据上学习通用表示，微调是在特定任务上用小规模标注数据调整参数，两者目标和数据都不同；实际应用中应先加载预训练模型再微调。
  • 误区：上下文学习需要更新模型参数。错误理解：认为模型在上下文中“学会”新任务是因为内部参数发生了变化。会导致什么后果：担心每次使用都要重新训练，不敢灵活使用 Few-shot 提示；或者错误地认为上下文学习的效果可以永久保存。正确做法：上下文学习是在推理时通过输入中的示例让模型临时“学会”任务，不改变任何参数；效果仅限于当前对话或请求，不会持久化。

自测

请简要说明统计语言模型和神经网络语言模型的主要区别，并各举一个具体例子说明它们的局限性或优势。

答案：统计语言模型（如 N-gram）基于马尔可夫假设，只依赖前 N-1 个词，存在数据稀疏和无法捕捉长距离依赖的问题。例如，二元语法在“我出生在法国，所以我会说一口流利的____”中，只看前一个词“的”，无法利用远处的“法国”来预测“法语”。神经网络语言模型使用词向量和神经网络（如 RNN、Transformer）来建模序列概率，能缓解稀疏问题并捕捉更长距离的依赖。例如，词向量让“猫”和“狗”距离相近，即使某个词组合没出现过，模型也能根据语义相似性给出合理概率；Transformer 的自注意力机制可以直接关联“法国”和“法语”，不受距离限制。

什么是上下文学习（In-context Learning）？它有什么优势？请结合一个具体场景说明它和微调的区别。

答案：上下文学习是指 LLM 在不更新参数的情况下，仅通过输入中提供的少量示例（Few-shot）就能学会并执行新任务。优势是无需微调，使用灵活，大大降低了适配新任务的门槛。例如，要让模型做“英文单词转复数”任务，上下文学习只需在提示里给两个例子“cat => cats, dog => dogs”，然后输入“book =>”，模型就能输出“books”；而微调需要准备大量标注数据，重新训练模型参数，耗时耗力。区别在于：上下文学习的效果仅限于当前请求，不改变模型本身；微调会永久改变模型参数，效果持久但成本高。

为什么说“LLM 的上下文学习能力与模型规模密切相关”？请结合 GPT-2 和 GPT-3 的对比说明。

答案：上下文学习不是魔法，而是规模带来的涌现能力。GPT-2 只有约 15 亿参数，在 Few-shot 翻译任务中可能输出不准确或不相关的内容；GPT-3 有 1750 亿参数，同样的提示下能更准确地利用示例模式完成翻译。这说明模型规模越大，从上下文中捕捉任务模式的能力越强。推理过程：小模型容量有限，难以在少量示例中归纳出任务规律；大模型有更多参数和更丰富的预训练知识，能更好地“理解”示例并泛化到新输入。因此，上下文学习的效果与模型规模密切相关，不能简单认为任何 LLM 都能完美执行 Few-shot 任务。
