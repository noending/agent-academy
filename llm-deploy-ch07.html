实战：微调与部署LLM

本章目标：完成一个LLM微调、量化并部署为API的完整项目

项目规划：选择基座模型与数据集

做任何LLM项目，第一步永远是明确目标：你要解决什么任务？是让模型学会特定领域的问答，还是遵循某种输出格式？目标决定了基座模型和数据集的选择。

基座模型选择：对于中文场景，推荐从以下模型入手：

  • Qwen2.5-7B：中文能力强，社区活跃，LoRA微调资料多。
  • Llama-3.1-8B：英文生态好，工具链成熟。
  • ChatGLM3-6B：轻量，适合消费级显卡。

选择时考虑：参数量（7B模型LoRA微调需约16GB显存）、许可证（商用是否允许）、社区支持（是否有现成的微调脚本）。

数据集准备：微调数据通常为指令格式，例如：

{
  "instruction": "将以下文本翻译成英文",
  "input": "今天天气真好",
  "output": "The weather is nice today."
}

数据量建议至少1000条，质量比数量更重要。可以使用开源数据集（如Alpaca、Firefly）或自己标注。

下面是一个最小示例，展示如何加载数据集并查看格式：

from datasets import load_dataset

# 加载一个开源指令数据集
dataset = load_dataset("yahma/alpaca-cleaned", split="train")
print(dataset[0])
# 输出: {'instruction': '...', 'input': '...', 'output': '...'}

使用LoRA微调模型

LoRA（Low-Rank Adaptation）是一种参数高效微调方法，它冻结原模型参数，只在Transformer层的注意力模块中注入可训练的低秩矩阵。这样可训练参数减少到原来的0.1%~1%，显存需求大幅降低。

使用Hugging Face的peft库可以轻松实现LoRA微调。关键参数：

  • r：低秩矩阵的秩，通常8~32。
  • lora_alpha：缩放因子，一般设为r的2倍。
  • target_modules：要注入的模块，如["q_proj", "v_proj"]。

下面是一个完整的微调脚本（以Qwen2.5-7B为例）：

from transformers import AutoModelForCausalLM, AutoTokenizer, TrainingArguments
from peft import LoraConfig, get_peft_model
from trl import SFTTrainer
from datasets import load_dataset

model_name = "Qwen/Qwen2.5-7B"
tokenizer = AutoTokenizer.from_pretrained(model_name)
model = AutoModelForCausalLM.from_pretrained(model_name, device_map="auto")

# 配置LoRA
lora_config = LoraConfig(
    r=16,
    lora_alpha=32,
    target_modules=["q_proj", "v_proj"],
    lora_dropout=0.05,
    bias="none",
    task_type="CAUSAL_LM"
)
model = get_peft_model(model, lora_config)
model.print_trainable_parameters()  # 查看可训练参数比例

# 加载数据集
dataset = load_dataset("yahma/alpaca-cleaned", split="train[:1000]")

# 训练参数
training_args = TrainingArguments(
    output_dir="./lora_output",
    per_device_train_batch_size=4,
    gradient_accumulation_steps=4,
    learning_rate=2e-4,
    num_train_epochs=3,
    logging_steps=10,
    save_strategy="epoch",
    fp16=True,
)

# 使用SFTTrainer
trainer = SFTTrainer(
    model=model,
    args=training_args,
    train_dataset=dataset,
    tokenizer=tokenizer,
    dataset_text_field="text",  # 需要将数据格式化为文本
    max_seq_length=512,
)
trainer.train()
model.save_pretrained("./lora_adapter")

注意：实际使用时需要将数据集格式化为包含instruction、input、output的文本，例如：### Instruction:\n{instruction}\n### Input:\n{input}\n### Response:\n{output}。

模型量化与导出

微调后，为了部署，通常需要将模型量化以减小显存占用和加速推理。常见的量化方法有：

  • GPTQ：训练后量化，4-bit，精度损失小。
  • AWQ：激活感知权重量化，适合LLM。
  • GGUF：llama.cpp使用的格式，适合CPU推理。

这里以GPTQ为例，使用auto-gptq库进行量化：

from transformers import AutoModelForCausalLM, AutoTokenizer
from auto_gptq import AutoGPTQForCausalLM, BaseQuantizeConfig

model_name = "Qwen/Qwen2.5-7B"
tokenizer = AutoTokenizer.from_pretrained(model_name)

# 量化配置
quantize_config = BaseQuantizeConfig(
    bits=4,
    group_size=128,
    desc_act=False,
)

# 加载模型并量化
model = AutoGPTQForCausalLM.from_pretrained(model_name, quantize_config)

# 准备校准数据（少量样本）
calibration_dataset = ["示例文本1", "示例文本2"]  # 实际需更多

# 执行量化
model.quantize(calibration_dataset)
model.save_quantized("./qwen2.5-7b-gptq")
tokenizer.save_pretrained("./qwen2.5-7b-gptq")

量化后模型大小约为原模型的1/4，显存需求从~14GB降至~4GB。

如果使用LoRA微调，也可以将LoRA权重合并到基座模型后再量化：

from peft import PeftModel

base_model = AutoModelForCausalLM.from_pretrained("Qwen/Qwen2.5-7B")
lora_model = PeftModel.from_pretrained(base_model, "./lora_adapter")
merged_model = lora_model.merge_and_unload()
merged_model.save_pretrained("./merged_model")

使用vLLM部署并测试API

vLLM是一个高效推理引擎，支持PagedAttention，吞吐量比Hugging Face高数倍。部署API只需几行命令：

# 启动OpenAI兼容的API服务
python -m vllm.entrypoints.openai.api_server \
    --model ./qwen2.5-7b-gptq \
    --quantization gptq \
    --port 8000 \
    --host 0.0.0.0

然后就可以像调用OpenAI API一样调用：

import openai

client = openai.OpenAI(base_url="http://localhost:8000/v1", api_key="token-abc123")

response = client.chat.completions.create(
    model="qwen2.5-7b-gptq",
    messages=[{"role": "user", "content": "你好，介绍一下你自己"}],
    temperature=0.7,
    max_tokens=100
)
print(response.choices[0].message.content)

测试时注意：并发测试可以使用locust或wrk；监控可以查看vLLM的日志和GPU利用率。

如果使用LoRA适配器，vLLM也支持动态加载：

python -m vllm.entrypoints.openai.api_server \
    --model Qwen/Qwen2.5-7B \
    --enable-lora \
    --lora-modules my-lora=./lora_adapter

调用时指定model="my-lora"即可。

常见误区

  • LoRA微调后必须合并权重才能部署，实际上vLLM等框架支持直接加载LoRA适配器，无需合并。
  • 量化一定会显著降低模型精度，实际上4-bit GPTQ/AWQ在多数任务上精度损失很小（<1%），且推理速度更快。
  • 微调数据越多越好，实际上数据质量比数量更重要，1000条高质量数据可能胜过10万条低质量数据。

自测

LoRA微调中，参数r和lora_alpha分别代表什么？它们如何影响微调效果？

答案：r是低秩矩阵的秩，控制可训练参数的数量和表达能力，r越大模型容量越大但可能过拟合；lora_alpha是缩放因子，通常设为r的2倍，用于调整LoRA权重对原模型的影响程度。

使用vLLM部署模型时，如何支持多个LoRA适配器？

答案：启动vLLM时添加--enable-lora参数，并通过--lora-modules指定多个适配器，格式为name=path。调用时在请求中指定model为对应的适配器名称即可。
