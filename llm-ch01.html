LLM基础概念

本章目标：理解LLM核心概念与工作原理

Token与Embedding文本切块转成向量表示→Transformer注意力机制建模上下文→预训练海量语料预测下一词→微调与对齐指令微调贴合人类意图→推理生成逐词采样输出回答
从文本到向量、经预训练与对齐，最终逐词生成回答的完整链路。

从统计语言模型到神经网络语言模型

想象你在玩一个“接龙”游戏：给你前几个词，你要猜下一个词最可能是什么。语言模型（Language Model）做的就是这件事——计算一个词序列出现的概率。比如“今天天气真不错”这句话，语言模型会给出它作为一个合法句子的概率。早期我们用统计方法，比如 N-gram：假设每个词只依赖前面 N-1 个词。N=2 时，“不错”只依赖“真”。这种方法简单，但有两个致命问题：数据稀疏（很多词组合在语料里根本没出现过，概率为 0）和上下文窗口太短（无法捕捉长距离依赖）。举个例子，假设语料里从未出现“真不错”这个组合，N-gram 模型会直接给它分配概率 0，导致整个句子概率为 0——这显然不合理。

神经网络语言模型改变了游戏规则。它把词映射成稠密向量（词嵌入），然后用神经网络根据前面的词预测下一个词。这样即使没见过“真不错”这个组合，模型也能从“真好”“很棒”等相似语境中泛化。具体来说，词嵌入让“真”和“很”在向量空间中距离很近，模型学到的是“程度副词 + 正面形容词”的模式，而不是死记硬背每个组合。2017 年 Transformer 的出现，让模型可以并行处理整个序列，并且通过自注意力机制直接建模任意两个词之间的关系，这才有了今天的大语言模型（LLM）。

下面是一个用 PyTorch 实现的最简神经网络语言模型（Bigram 版），帮你直观感受“用神经网络预测下一个词”是怎么回事。输入是词索引序列 [0, 1, 2]（对应“我 爱 学习”），输出是每个位置对下一个词的预测概率分布。运行后你会看到类似 tensor([0.1, 0.2, 0.3, 0.3, 0.1]) 的输出，5 个概率值之和为 1：

python
import torch
import torch.nn as nn
import torch.nn.functional as F

# 假设词表只有 5 个词：我, 爱, 学习, 人工智能, &lt;eos&gt;
vocab_size = 5
embed_dim = 8

class BigramLM(nn.Module):
    def __init__(self):
        super().__init__()
        # 输入词索引 -&gt; 嵌入向量
        self.embed = nn.Embedding(vocab_size, embed_dim)
        # 嵌入向量 -&gt; 下一个词的 logits
        self.linear = nn.Linear(embed_dim, vocab_size)

    def forward(self, x):
        # x: (batch, seq_len) 词索引
        emb = self.embed(x)          # (batch, seq_len, embed_dim)
        logits = self.linear(emb)    # (batch, seq_len, vocab_size)
        return logits

model = BigramLM()
# 输入序列：我 爱 学习
x = torch.tensor([[0, 1, 2]])
logits = model(x)
# 对最后一个位置的输出做 softmax，得到下一个词的概率分布
probs = F.softmax(logits[0, -1], dim=-1)
print(probs)  # 例如 tensor([0.1, 0.2, 0.3, 0.3, 0.1])

这个模型只根据当前词预测下一个词，非常简陋，但已经包含了现代 LLM 的基本要素：词嵌入 + 神经网络 + 概率输出。真正的 LLM 只是把这个结构堆叠得极深、极宽，并用海量文本训练。对比一下：这个 Bigram 模型只有约 100 个参数，而 GPT-3 有 1750 亿参数——差距在 9 个数量级以上，但核心思想一脉相承。

Transformer 与自注意力机制

想象你在读一句话：“小明把苹果给了小红，因为她饿了。”当读到“她”时，你需要知道“她”指代的是“小红”而不是“小明”。自注意力（Self-Attention）就是让模型自动学会这种指代关系的机制：对于序列中的每个词，计算它与其他所有词的关联程度，然后加权求和，得到新的表示。这样，每个词都能“看到”整个句子，并动态决定关注哪些部分。

自注意力的计算可以概括为三步：

  1. 把每个词的向量分别投影成 Query（查询）、Key（键）、Value（值）三个向量。你可以把 Query 理解为“我想找什么”，Key 理解为“我有什么标签”，Value 理解为“我实际的内容”。
  2. 用 Query 和所有 Key 做点积，得到注意力分数，再除以 √d 防止梯度消失，然后 softmax 归一化。除以 √d 的原因很直观：当 d=64 时，点积结果的方差会随维度增大而增大，导致 softmax 输出过于尖锐（接近 one-hot），梯度几乎为零。
  3. 用归一化后的分数对 Value 加权求和，得到输出。

用公式表示就是：Attention(Q, K, V) = softmax(QK^T / √d) V。多头注意力（Multi-Head Attention）则是并行做多组这样的计算，让模型从不同子空间捕捉信息。比如一个头关注语法关系，另一个头关注语义相似性。

下面是一个可运行的单头自注意力最小实现。输入是形状为 (1, 3, 4) 的随机张量（batch=1，序列长度=3，嵌入维度=4），运行后你会看到输出形状为 (1, 3, 4)，注意力权重形状为 (1, 3, 3)，且每一行的三个权重之和为 1：

python
import torch
import torch.nn as nn
import torch.nn.functional as F
import math

class SelfAttention(nn.Module):
    def __init__(self, embed_dim):
        super().__init__()
        self.embed_dim = embed_dim
        self.q_proj = nn.Linear(embed_dim, embed_dim)
        self.k_proj = nn.Linear(embed_dim, embed_dim)
        self.v_proj = nn.Linear(embed_dim, embed_dim)

    def forward(self, x):
        # x: (batch, seq_len, embed_dim)
        Q = self.q_proj(x)
        K = self.k_proj(x)
        V = self.v_proj(x)
        # 计算注意力分数
        scores = torch.matmul(Q, K.transpose(-2, -1)) / math.sqrt(self.embed_dim)
        attn = F.softmax(scores, dim=-1)
        out = torch.matmul(attn, V)
        return out, attn

# 模拟一个 batch=1, seq_len=3, embed_dim=4 的输入
x = torch.randn(1, 3, 4)
attn_layer = SelfAttention(embed_dim=4)
out, attn_weights = attn_layer(x)
print('输出形状:', out.shape)          # torch.Size([1, 3, 4])
print('注意力权重形状:', attn_weights.shape)  # torch.Size([1, 3, 3])
print('注意力权重（每行和为1）:\n', attn_weights)

运行后你会看到，每个位置对三个位置的注意力权重加起来是 1。这就是自注意力的直观含义：每个词都在问“我应该关注谁？”。Transformer 还包含前馈网络、残差连接、层归一化等组件，但自注意力是它区别于 RNN/CNN 的关键。RNN 必须按顺序逐个处理词，无法并行；CNN 只能捕捉局部窗口；而自注意力一步就能建模任意两个位置的关系，这也是 Transformer 能扩展到千亿参数的根本原因。

预训练与微调范式

你可以把 LLM 的训练想象成培养一个学生：预训练像是让他读遍图书馆的所有书，建立通用的语言能力和世界知识；微调像是针对某个岗位做岗前培训，让他快速适应具体工作。现代 LLM 的训练正是分为这两个阶段。

预训练是在海量无标注文本上进行的自监督学习。最常见的任务是“预测下一个词”（自回归语言建模，如 GPT 系列）或“完形填空”（掩码语言建模，如 BERT）。模型通过反复预测被遮住或接下来的词，学会了语法、事实知识、推理能力等。这个阶段计算量极大，通常需要数千 GPU/TPU 训练数周，成本极高。以 GPT-3 为例，其预训练使用了约 3000 亿 token（待核实），训练成本估计在数百万美元量级。

微调是在预训练模型的基础上，用少量标注数据（或指令数据）继续训练，让模型适应特定任务或领域。比如用医疗问答数据微调，模型就能更好地回答医学问题。微调需要的计算资源远小于预训练——通常单卡几小时到几天即可完成，是开发者最常接触的环节。近年来还出现了参数高效微调（PEFT），如 LoRA、Prefix Tuning，只训练极少量参数就能达到接近全量微调的效果。以 LoRA 为例，它只训练原模型 0.1%~1% 的参数，显存需求可降低数倍，大大降低了门槛。

下面用 Hugging Face Transformers 演示一个极简的微调流程（以文本分类为例）。输入是 4 条英文影评和对应的情感标签（1 正面，0 负面），运行后会打印训练日志并输出“微调完成！”。注意：首次运行需要联网下载 distilbert-base-uncased 模型（约 250MB）：

python
from transformers import AutoTokenizer, AutoModelForSequenceClassification, Trainer, TrainingArguments
import torch
from torch.utils.data import Dataset

# 加载预训练模型和分词器（这里用一个小模型演示）
model_name = 'distilbert-base-uncased'
tokenizer = AutoTokenizer.from_pretrained(model_name)
model = AutoModelForSequenceClassification.from_pretrained(model_name, num_labels=2)

# 模拟一些训练数据
texts = ['I love this movie', 'This is terrible', 'Great film', 'Awful experience']
labels = [1, 0, 1, 0]

class SimpleDataset(Dataset):
    def __init__(self, texts, labels):
        self.encodings = tokenizer(texts, truncation=True, padding=True, return_tensors='pt')
        self.labels = labels
    def __len__(self):
        return len(self.labels)
    def __getitem__(self, idx):
        item = {key: val[idx] for key, val in self.encodings.items()}
        item['labels'] = torch.tensor(self.labels[idx])
        return item

dataset = SimpleDataset(texts, labels)

training_args = TrainingArguments(
    output_dir='./results',
    num_train_epochs=3,
    per_device_train_batch_size=2,
    logging_steps=1,
    save_steps=10,
)

trainer = Trainer(
    model=model,
    args=training_args,
    train_dataset=dataset,
)

trainer.train()
print('微调完成！')

这段代码展示了微调的标准流程：加载预训练模型 → 准备数据 → 配置训练参数 → 训练。实际项目中，你会用更大的模型和更多数据，但核心逻辑不变。关键对比：预训练从随机初始化开始，需要万亿级 token；微调从预训练权重开始，通常只需几千到几万条样本。

LLM 的能力与局限性

LLM 展现出了令人惊讶的能力，这些能力大致可以分为四类：

  • 语言理解与生成：流畅地写文章、翻译、总结、问答。例如给定一段中文新闻，模型能生成英文摘要。
  • 上下文学习（In-Context Learning）：给几个例子，模型就能学会新任务，无需更新参数。比如在提示中给 3 个“情感分类”示例，模型就能对第 4 条新评论正确分类。
  • 推理与代码：能进行一定程度的逻辑推理，并生成可运行的代码。例如根据自然语言描述生成 Python 函数。
  • 知识存储：预训练过程中“记住”了大量事实知识。例如能回答“法国的首都是哪里”。

但 LLM 也有明显的局限性，理解这些局限性比记住能力清单更重要：

  • 幻觉（Hallucination）：模型会自信地编造不存在的事实。例如问它“某篇论文的作者是谁”，它可能给出一个看似合理但完全虚构的名字。这是因为它的目标是预测下一个词，而不是追求真理。
  • 上下文窗口有限：虽然现在有 128K 甚至更长的上下文，但依然无法处理无限长的输入，且长上下文中的信息检索能力会下降。例如在 100K token 的文档中找一句话，模型可能漏掉。
  • 知识截止：预训练数据有时间截止点，模型不知道之后发生的事情。例如问它“昨天的新闻”，它无法回答。
  • 推理能力不稳定：在复杂数学、多步逻辑上容易出错。例如简单的两位数乘法可能算错，但换个问法又可能算对。
  • 计算成本高：训练和推理都需要大量算力，部署时需要考虑延迟和吞吐。例如一个 70B 参数的模型，推理时仅加载权重就需要约 140GB 显存（FP16 精度）。

理解这些局限性，才能在后续章节中设计出更可靠的系统，比如用 RAG（检索增强生成）缓解幻觉，用缓存和量化优化推理速度。一个具体的对比：纯 LLM 回答“公司最新政策”时可能编造，而 RAG 系统会先检索真实文档再回答，幻觉率显著降低。

常见误区

  • 错误理解：LLM 真的“理解”语言，像人一样思考。→ 后果：过度信任模型输出，在医疗、法律等高风险场景直接采用未经验证的答案，导致严重错误。→ 正确做法：认识到 LLM 本质是基于统计规律预测下一个词，它的“理解”与人类不同，缺乏真实世界的体验和常识；对关键结论应交叉验证或引入检索增强。
  • 错误理解：预训练和微调是一回事，只是数据量不同。→ 后果：低估预训练成本，或误以为微调可以替代预训练从零构建模型，导致资源规划严重失误。→ 正确做法：明确预训练是在海量无标注数据上通过自监督学习通用表示（成本极高），微调是在预训练权重基础上用少量标注数据适配下游任务（成本低得多），两者目标、数据、成本都不同。
  • 错误理解：自注意力机制中每个词只关注自己，或者注意力权重是固定的。→ 后果：无法理解模型为何能捕捉长距离依赖，调试时误判问题根源，比如以为模型看不到远处的词。→ 正确做法：自注意力让每个词关注序列中所有词（包括自己），权重由 Query 和 Key 的点积经 softmax 动态计算得到，并非固定，且不同头可以关注不同位置。

自测

请解释自注意力机制中 Query、Key、Value 的作用，并说明为什么要除以 √d。

答案：Query 代表当前词的查询需求，Key 代表其他词提供的索引信息，Value 代表其他词的实际内容。推理过程：先用 Query 和所有 Key 做点积得到相关性分数，分数越高说明两个词越相关；然后 softmax 归一化成权重；最后用权重对 Value 加权求和，得到当前词融合了上下文的新表示。除以 √d 是因为点积结果的方差随维度 d 增大而增大，若不缩放，softmax 输出会过于尖锐（接近 one-hot），导致梯度几乎为零、训练困难；除以 √d 可以把方差拉回合理范围，保持梯度稳定。

预训练和微调的主要区别是什么？请从数据、目标、成本三个角度说明。

答案：推理过程：先看数据——预训练用海量无标注文本（万亿级 token），微调用少量标注数据（几千到几万条）；再看目标——预训练通过自监督任务（如预测下一个词）学习通用语言表示，微调让模型适配特定任务或领域；最后看成本——预训练需要数千 GPU/TPU 训练数周、成本数百万美元量级，微调通常单卡几小时到几天即可完成。因此两者不是程度差异，而是性质不同的两个阶段，微调必须建立在预训练权重之上。

LLM 为什么会产生幻觉？请结合它的训练目标解释，并给出一种缓解思路。

答案：推理过程：LLM 的训练目标是预测下一个词，即最大化训练语料中词序列的似然，而不是追求事实正确性。当模型遇到训练数据中罕见或不存在的问题时，它仍会按统计规律生成“看起来合理”的词序列，从而编造出不存在的事实，这就是幻觉。缓解思路：引入 RAG（检索增强生成），先检索真实文档，再让模型基于检索到的内容回答，把“凭记忆生成”变成“有据可依地生成”，从而显著降低幻觉率。

动手练习（带参考方案）

练习 · 使用 PyTorch 实现一个简单的多头自注意力模块（Multi-Head Self-Attention），输入形状为 …

任务：使用 PyTorch 实现一个简单的多头自注意力模块（Multi-Head Self-Attention），输入形状为 (batch_size, seq_len, embed_dim)，输出形状相同。要求包含线性投影、分头、缩放点积注意力、合并头等步骤。验收标准：用 batch_size=2, seq_len=5, embed_dim=16, num_heads=4 测试，输出形状必须为 torch.Size([2, 5, 16])。

参考方案：

python
import torch
import torch.nn as nn
import torch.nn.functional as F
import math

class MultiHeadSelfAttention(nn.Module):
    def __init__(self, embed_dim, num_heads):
        super().__init__()
        assert embed_dim % num_heads == 0, 'embed_dim 必须能被 num_heads 整除'
        self.embed_dim = embed_dim
        self.num_heads = num_heads
        self.head_dim = embed_dim // num_heads
        self.q_proj = nn.Linear(embed_dim, embed_dim)
        self.k_proj = nn.Linear(embed_dim, embed_dim)
        self.v_proj = nn.Linear(embed_dim, embed_dim)
        self.out_proj = nn.Linear(embed_dim, embed_dim)

    def forward(self, x):
        batch_size, seq_len, _ = x.shape
        # 线性投影
        Q = self.q_proj(x)  # (batch, seq_len, embed_dim)
        K = self.k_proj(x)
        V = self.v_proj(x)
        # 分头: (batch, seq_len, num_heads, head_dim) -> (batch, num_heads, seq_len, head_dim)
        Q = Q.view(batch_size, seq_len, self.num_heads, self.head_dim).transpose(1, 2)
        K = K.view(batch_size, seq_len, self.num_heads, self.head_dim).transpose(1, 2)
        V = V.view(batch_size, seq_len, self.num_heads, self.head_dim).transpose(1, 2)
        # 缩放点积注意力
        scores = torch.matmul(Q, K.transpose(-2, -1)) / math.sqrt(self.head_dim)
        attn = F.softmax(scores, dim=-1)
        out = torch.matmul(attn, V)  # (batch, num_heads, seq_len, head_dim)
        # 合并头
        out = out.transpose(1, 2).contiguous().view(batch_size, seq_len, self.embed_dim)
        out = self.out_proj(out)
        return out

# 测试
x = torch.randn(2, 5, 16)
mha = MultiHeadSelfAttention(embed_dim=16, num_heads=4)
out = mha(x)
print(out.shape)  # torch.Size([2, 5, 16])
