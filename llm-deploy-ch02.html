数据工程与预处理

本章目标：掌握LLM训练数据的收集、清洗、去重与格式化方法

数据收集多源采集原始语料→清洗过滤去噪去害保质量→去重消除重复防过拟合→格式化转成训练样本格式→质量反馈评估回流再优化
数据从采集到可用，经清洗去重格式化，再由质量反馈闭环迭代。

数据来源与采集：网页、书籍、代码、对话

如果把训练LLM比作做一顿大餐，那么数据工程就是去菜市场采购、挑菜、洗菜、切菜的全过程。模型架构和训练算法是菜谱和厨艺，但食材不新鲜，再好的厨艺也做不出好菜。这就是数据工程里那句老话：垃圾进，垃圾出（Garbage In, Garbage Out）。一个模型的知识广度、代码能力、对话流畅度，几乎在数据采集阶段就已经被决定了上限。

LLM训练数据主要有四大来源，它们各自扮演不同角色。网页是体量最大的来源，Common Crawl这类项目每月抓取数十亿网页，但原始HTML里混杂着导航栏、广告、模板文字，需要正文提取、语言过滤和质量打分。以Common Crawl为例，原始抓取数据经过清洗后，真正能用于训练的比例往往不到10%（待核实）。书籍提供长文本和连贯逻辑，Project Gutenberg等公共版权书库是常见来源，但版权和获取难度始终是约束。代码来自GitHub、Stack Overflow等，对代码生成和推理能力至关重要，采集时要按许可证过滤、去重并尽量保留语法结构。对话数据来自论坛、客服记录和多轮对话，主要用于指令微调和对话能力，格式五花八门，需要统一成对话模板。

采集时最重要的原则是来源多样性决定能力广度。只喂网页，模型可能知识面广但不会写代码；只喂代码，模型可能代码强但不会聊天。所以采集阶段就要有意识地保留多来源数据，并在元数据里记录来源标签，为后面的数据配比做准备。下面这个最小示例演示如何从本地JSONL文件加载三种来源的数据，并统一成包含source、text、meta的字典格式。假设当前目录下有web.jsonl、books.jsonl、code.jsonl三个文件，每行是一个JSON对象，运行后会打印总样本数和第一条样本的结构。

python
import json
from pathlib import Path

def load_jsonl(path):
    # 逐行读取JSONL，每行一个JSON对象
    with open(path, 'r', encoding='utf-8') as f:
        return [json.loads(line) for line in f]

# 假设三个文件都存在；若不存在可先创建空文件测试
web_data = load_jsonl('web.jsonl')
book_data = load_jsonl('books.jsonl')
code_data = load_jsonl('code.jsonl')

def normalize(item, source):
    # 统一格式：source + text + 其余字段放入meta
    return {
        'source': source,
        'text': item.get('text', ''),
        'meta': {k: v for k, v in item.items() if k != 'text'}
    }

all_data = []
for item in web_data:
    all_data.append(normalize(item, 'web'))
for item in book_data:
    all_data.append(normalize(item, 'book'))
for item in code_data:
    all_data.append(normalize(item, 'code'))

print(f'Total samples: {len(all_data)}')
if all_data:
    print(all_data[0])

这个例子虽然简单，却体现了数据工程的第一步：统一数据格式，让后续清洗、去重、配比都能在同一个数据结构上操作。如果每个来源各用一套字段名，后面的流水线会变得非常脆弱。

数据清洗：去噪、去重与质量过滤

原始数据就像刚从河里捞上来的沙子，里面混着石子、贝壳和泥。清洗的目标不是把沙子洗成金子，而是保留高质量、多样化的文本，去掉噪声和冗余。这一步做得好不好，直接体现在模型是否爱重复、是否容易输出乱码、是否记住训练集里的广告语。

去噪主要处理HTML标签、特殊控制字符、多余空白和页眉页脚。简单场景可以用正则表达式，复杂网页正文提取可以用trafilatura这类专门库。比如一段原始HTML `

Hello world!

` 经过去标签和空白压缩后会变成 `Hello world!`，长度从24个字符降到12个字符，噪声比例明显下降。去重分三个层次：精确去重用哈希去掉完全相同的文本；近似去重用MinHash+LSH或SimHash找出“换几个词、调一下语序”的重复；子串去重针对长文档中重复的段落，用后缀数组或n-gram重叠检测。工业级流水线通常以近似去重为主，因为网页数据里完全相同的文本反而是少数。质量过滤则用规则或模型打分，规则包括文本长度、平均词长、符号与词的比例、是否包含禁用词，模型方法如用fastText分类器判断文本是否像维基百科。

下面这个综合示例把去噪、质量过滤和精确去重串成一条小流水线。输入是5条模拟原始文本，其中包含HTML标签、短文本、符号堆砌和重复文本；运行后会依次打印清洗后、过滤后和去重后的结果。你可以清楚看到 `Short` 因为长度不足被过滤，符号堆砌的文本因为符号比例过高被过滤，而两条清洗后相同的 `Hello world!` 只保留一条。

python
import re
import hashlib

def clean_text(text):
    # 去HTML标签、压缩空白、去控制字符
    text = re.sub(r'<[^>]+>', '', text)
    text = re.sub(r'\s+', ' ', text).strip()
    text = re.sub(r'[\x00-\x1f\x7f]', '', text)
    return text

def quality_filter(text, min_len=50, max_symbol_ratio=0.1):
    if len(text) < min_len:
        return False
    symbol_count = sum(1 for c in text if not c.isalnum() and not c.isspace())
    if symbol_count / len(text) > max_symbol_ratio:
        return False
    return True

def deduplicate(texts):
    seen = set()
    unique = []
    for t in texts:
        h = hashlib.md5(t.encode('utf-8')).hexdigest()
        if h not in seen:
            seen.add(h)
            unique.append(t)
    return unique

raw_texts = [
    '
Hello   world!
',
    'Hello world!',
    'This is a much longer text that should pass the quality filter because it has enough characters and not too many symbols.',
    'Short',
    '!!!!!@@@@@#####$$$$$%%%%%^^^^^&&&&&*****((((()))))',
]

cleaned = [clean_text(t) for t in raw_texts]
filtered = [t for t in cleaned if quality_filter(t)]
unique = deduplicate(filtered)

print('Cleaned:', cleaned)
print('Filtered:', filtered)
print('Unique:', unique)

需要特别强调：精确去重只能去掉完全一样的文本，近似去重才能解决“换几个词”的重复。如果只做精确去重，模型仍然会反复看到语义相同的段落，导致记忆和过拟合。实际项目中，近似去重往往能再砍掉相当比例的重复数据（待核实具体比例），是数据清洗里性价比最高的一步。

数据格式化：指令微调与对话模板

预训练数据是纯文本，模型只需要学会“接着写”。但指令微调和对话模型需要模型理解“谁在说、说到哪、该谁接”，这就必须把数据整理成结构化模板。可以把模板想象成剧本格式：没有角色标记，演员就不知道哪句是自己的台词；模板就是给模型看的剧本。

指令微调数据通常包含三部分：instruction（指令）、input（可选输入）、output（期望输出）。例如一条翻译任务：instruction是“将以下句子翻译成英文”，input是“今天天气真好”，output是“The weather is really nice today.”。对话模板则把多轮对话组织成带角色标记的序列，常见格式有Alpaca、ShareGPT、ChatML等。以ChatML为例，每条消息用 `<|im_start|>角色` 开头、`<|im_end|>` 结尾，system、user、assistant依次排列。格式化时有一条铁律：训练和推理必须使用完全相同的模板，否则模型会“精神分裂”，输出格式混乱。另外，训练时要正确处理padding和attention mask，把padding token的loss忽略掉，并且通常只对assistant部分的token计算loss，system和user部分mask掉。

下面这个示例把一条Alpaca格式数据转成ChatML格式。输入是一个包含instruction、input、output的字典，运行后会打印出带角色标记的完整文本。注意当input为空时，user内容只保留instruction，避免出现多余空行。

python
def alpaca_to_chatml(example):
    instruction = example.get('instruction', '')
    input_text = example.get('input', '')
    output = example.get('output', '')
    if input_text:
        user_content = f"{instruction}\n\n{input_text}"
    else:
        user_content = instruction
    chatml = (
        "<|im_start|>system\nYou are a helpful assistant.<|im_end|>\n"
        f"<|im_start|>user\n{user_content}<|im_end|>\n"
        f"<|im_start|>assistant\n{output}<|im_end|>\n"
    )
    return {'text': chatml}

example = {
    'instruction': '将以下句子翻译成英文',
    'input': '今天天气真好',
    'output': 'The weather is really nice today.'
}
print(alpaca_to_chatml(example)['text'])

实际训练时，模板转换只是第一步，后面还要接tokenizer把文本变成token id，并构造labels：assistant回复部分保留真实token id，其余位置设为-100（PyTorch的ignore_index）。这样模型才是在学习“给定上下文生成回复”，而不是学习复述用户的问题。

数据配比与课程学习策略

数据配比（Data Mixture）是指不同来源数据在训练集中的比例，它直接决定模型的能力偏向。可以把它类比成营养配餐：蛋白质、碳水、脂肪都要有，比例不同，长出来的体格就不同。网页数据多，模型知识面广但可能废话多；代码数据多，代码能力强但可能不会聊天；书籍数据多，长文本理解好但可能缺乏时效性。

常见做法是先按经验设定初始比例，再通过小规模实验和评测结果迭代调整。例如Llama 2的预训练数据中，代码占比约5%，网页占比在80%以上（待核实具体数字）。指令微调数据则更注重质量而非数量，通常几万到几百万条。另一种策略是课程学习（Curriculum Learning）：先喂简单数据再喂难数据，比如先短文本后长文本、先通用后专业。但在LLM预训练中，课程学习的效果仍有争议，因为数据量太大，很难稳定定义“简单”和“难”。更常见的替代是动态数据配比，在训练过程中调整不同来源的采样权重。

下面这个示例演示按比例采样。输入是模拟的1000条web、500条book、300条code数据，比例设为web:book:code = 7:2:1，总采样1000条。运行后会打印实际采样总数和各来源数量。注意当某个来源样本不足时，代码会打印警告并降级到该来源的全部样本，这在实际流水线里是必须处理的边界情况。

python
import random
from collections import defaultdict, Counter

def sample_by_ratio(data, ratios, total_samples):
    by_source = defaultdict(list)
    for item in data:
        by_source[item['source']].append(item)
    sampled = []
    for source, ratio in ratios.items():
        n = int(total_samples * ratio)
        pool = by_source[source]
        if len(pool) < n:
            print(f'Warning: {source} only has {len(pool)} samples, requested {n}')
            n = len(pool)
        sampled.extend(random.sample(pool, n))
    random.shuffle(sampled)
    return sampled

data = [{'source': 'web', 'text': f'web_{i}'} for i in range(1000)]
data += [{'source': 'book', 'text': f'book_{i}'} for i in range(500)]
data += [{'source': 'code', 'text': f'code_{i}'} for i in range(300)]

ratios = {'web': 0.7, 'book': 0.2, 'code': 0.1}
sampled = sample_by_ratio(data, ratios, 1000)
print(f'Sampled {len(sampled)} items')
print(Counter(item['source'] for item in sampled))

记住：数据配比没有银弹，必须结合评测结果反复迭代。建议先跑小规模消融实验，观察不同配比在验证集上的表现，再放大到全量训练，而不是一次性拍脑袋定比例。

常见误区

  • 错误理解：数据去重只需要精确去重，近似去重没必要。→ 后果：网页数据中“换几个词、调一下语序”的近似重复非常普遍，只做精确去重会让模型反复看到语义相同的段落，导致记忆和过拟合，降低泛化能力。→ 正确做法：精确去重做快速兜底，近似去重（MinHash+LSH或SimHash）作为主力，长文档再补子串去重。
  • 错误理解：指令微调数据越多越好。→ 后果：低质量或重复的指令数据会稀释高质量信号，损害模型性能，还浪费训练算力。→ 正确做法：指令微调更看重质量而非数量，先做严格清洗和去重，通常几万条高质量数据就能有不错效果，再按评测结果决定是否扩充。
  • 错误理解：训练和推理可以使用不同的对话模板。→ 后果：模板不一致会让模型输出格式混乱，出现角色标记错位、该停不停等问题，表现为“精神分裂”。→ 正确做法：训练、验证、推理全链路使用同一套模板，并把模板版本纳入配置管理。

自测

数据去重通常分为哪几个层次？各自适用什么场景？为什么工业级流水线通常以近似去重为主？

答案：分为精确去重、近似去重和子串去重。精确去重用哈希去除完全相同的文本，速度快，适合做第一道快速过滤；近似去重用MinHash+LSH或SimHash去除相似但不完全相同的文本，适合大规模网页数据；子串去重针对长文档中重复的段落，用后缀数组或n-gram重叠检测，适合书籍等长文本。工业级流水线以近似去重为主，是因为网页数据里完全相同的文本反而是少数，大量重复是“换几个词、调一下语序”的近似重复，只做精确去重会漏掉大部分冗余，导致模型记忆和过拟合。

为什么数据配比很重要？调整配比时应该注意什么？请结合网页、代码、书籍三种来源说明能力偏向。

答案：数据配比决定模型的能力偏向：网页数据多，模型知识面广但可能废话多；代码数据多，代码能力强但可能不会聊天；书籍数据多，长文本理解好但可能缺乏时效性。调整配比时应注意：先按经验设定初始比例，通过小规模实验和评测结果迭代调整；避免某一来源过多导致能力失衡；当某个来源样本不足时要处理降级情况；动态调整采样权重可能比固定配比更有效。核心是配比没有银弹，必须结合评测反复迭代。

训练对话模型时，为什么通常只对assistant部分的token计算loss？如果对全部token计算loss会有什么问题？

答案：对话训练的目标是让模型学会“给定上下文生成回复”，所以只对assistant回复部分计算loss，system和user部分mask掉（设为-100）。如果对全部token计算loss，模型会同时学习复述用户的问题和system提示，相当于把“输入”也当成“要预测的目标”，这会分散学习信号，让模型倾向于模仿用户措辞而不是生成回复，降低指令遵循能力。正确做法是在构造labels时，只保留assistant回复段的真实token id，其余位置设为ignore_index。
