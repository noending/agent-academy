术语表

智能体 Agent
LLM 动态决定自身处理过程与工具使用的系统。四要素：LLM 大脑、工具、循环、记忆。判定标准：控制流由模型而非代码决定。
智能体循环 Agent Loop
「思考 → 行动 → 观察 →（未完成则回到思考）」的核心循环，一切 Agent 框架的心脏。终止条件由模型判断。
推理 + 行动 ReAct
Yao et al. 2022 提出的范式：让模型在行动前显式写出推理（Thought），交替进行 Reason 与 Act。现代 Function Calling 是它的接口化形态。
工具调用 / 函数调用 Function Calling
用 JSON Schema 声明工具 → 模型返回调用意图（名称 + JSON 字符串参数）→ 运行时代码执行 → 结果以 role=tool 消息回填。模型从不执行工具。
工作流 Workflow
步骤顺序由开发者代码写死的 LLM 应用。可预测、便宜、易调试；能用 Workflow 就别用 Agent（Anthropic 建议）。
上下文工程 Context Engineering
管理「循环每一轮模型能看到什么」的工程：裁剪、压缩、外置、结构化四大策略。Agent 工程中杠杆最大的主题。
上下文窗口 Context Window
模型一次能处理的 token 上限。稀缺资源：历史与工具结果都会消耗它。
上下文腐烂 Context Rot
长上下文中模型对内容的注意力随位置与密度衰减的现象：塞得越满、越靠中间，越容易被忽略。对策见第 5 章上下文工程（裁剪 / 压缩 / 外置 / 结构化）与第 4 章片段排序。
幻觉 Hallucination
模型以笃定语气输出编造内容。对实时/私有信息尤为严重——工具（给出真实 Observation）是对抗它的根本手段。
提示注入 Prompt Injection
在输入中夹带恶意指令劫持模型。间接注入（藏在工具返回的网页/邮件/文件里）对 Agent 危害最大，因为会触发执行。
检索增强生成 RAG
先从知识库检索相关片段、再据此生成回答。在 Agent 中通常包装为检索工具。多跳推理是它的天然盲区。
思维链 CoT / Chain-of-Thought
让模型逐步写出中间推理再给答案。思考模型（如 deepseek-reasoner）在接口层直接返回思维链（reasoning_content）。
思考模型 Reasoning Model
先进行长内部推理再输出的模型。适合规划、反思等重决策，延迟与成本更高；与执行型模型（deepseek-chat）混用是典型架构。
人类在环 Human-in-the-loop
高危操作（删除、转账、发送）执行前必须由人确认。Harness 权限分级的 confirm 级。
智能体框架 Harness / Scaffold
围绕 LLM 的全部运行时脚手架：系统提示、工具层、主循环、上下文管理、权限沙箱、子 Agent 调度、Trace、持久化。模型是引擎，Harness 是整车；模型决定上限，Harness 决定下限。
前缀缓存 Context Caching
对请求中重复的相同前缀（系统提示、历史）按大幅折扣计费。Agent 循环的消息数组只增不改，是前缀缓存的理想客户。
编排者–工人 Orchestrator–Workers
最实用的多智能体拓扑：主 Agent 拆解并派发任务给独立上下文的子 Agent，汇总结论。核心收益是上下文隔离与并行。
本体 Ontology
共享概念化的形式化、明确的规范说明（Gruber 1993 / Studer 1998）。构成：类、实例、属性、关系、公理。源自哲学的「存在研究」（亚里士多德范畴论）。
类 / 实例 Class / Instance
类是事物的抽象（Tool），实例是具体个体（WebSearch）。类层级由 is-a 连接，具有传递性。
三元组 Triple
RDF 的最小知识单元：主语–谓语–宾语。类属、关系、属性统一成同一形态，整个知识库因此是一张图。
术语层 / 断言层 TBox / ABox
TBox 是类与关系的定义（schema），ABox 是实例断言（数据）。知识图谱 = TBox + ABox。
网络本体语言 OWL
W3C 的强表达力本体语言：等价、互斥、基数、传递/对称属性等。基于开放世界假设（未写 ≠ 假）。配套：RDF（存）、RDFS（继承与定义域值域）、SPARQL（查）、SHACL（校验）。
开放世界假设 OWA / Open World Assumption
OWL 的语义立场：图中没有的事实是「未知」而非「不存在」，因为知识可被分布式补充。与数据库的封闭世界假设（没查到 = 假）相对。
知识图谱 Knowledge Graph
本体作骨架 + 海量实例作血肉的可查询语义网络。作为 Agent 长期记忆时支持多跳查询、一致性校验与幻觉检测。
模型上下文协议 MCP
开放标准，标准化 Harness 连接工具与数据源的接口（JSON-RPC）。MCP 管「怎么连」，本体管「连来的东西是什么意思」——互补而非竞争。
少样本示例 Few-shot
在提示词中放 2~5 个「输入→理想输出」示例，让模型模仿格式、风格与边界判断。选例原则：覆盖典型 + 边界、彼此多样、数量克制。
结构化输出 Structured Output
让模型输出机器可读的 JSON。三层防线：JSON 模式（语法合法）→ Schema 校验（字段类型合法）→ 带错误重试（校验失败把错误喂回模型）。闭环由 Harness 负责。
评估集 Evals
一组带判定标准的测试用例（能力层 / 边界层 / 回归层），任何改动前后各跑一遍。Agent 工程中复利最高的资产。
LLM-as-Judge
开放性任务无法用关键词断言时，请另一个模型按评分标准（rubric）打分。防三坑：偏爱长回答、自我偏好、rubric 含糊——并定期人工抽样复核。
调用轨迹 Trace
Agent 运行的全量记录：每次 LLM 调用的消息数组、工具调用、token 用量。调试的第一现场；没有 Trace 的 Agent 无法调试。
指数退避 Exponential Backoff
失败重试时按 2^n 秒等待（加随机抖动），避免在限流时雪上加霜。只适用于无副作用的调用；有副作用的工具执行不可盲目重试。
嵌入 Embedding
把文本映射为高维向量，语义相近则向量相近——向量检索（RAG）的基础。教学上接口只有 add / search 两个词，实现可从词频一路升级到嵌入模型 + 向量库。
切块 Chunking
把文档切成适合检索的小块。检索的粒度 = 命中的粒度：固定长度会拦腰斩断语义，结构感知切块（按标题）+ 块内细分是生产标准做法；每块必带元数据（来源、日期、类别）。
重排序 Rerank
检索的「粗召回 + 精排」架构：先宽召回 Top-20，再用交叉编码器按相关性精排出 Top-3。多一次廉价调用换检索精度大幅提升。
对象·链接·动作 Palantir Ontology
Palantir Foundry 的工业级本体三件套：对象类型（业务实体）、链接类型（关系本体）、动作类型（唯一合法写入口：校验+权限+副作用）。与语义网本体对比：前者运营业务、支持安全写回，后者描述世界、支持推理——Agent 时代 Action 类型就是模型的高危工具闸门。

毕业寄语

Agent 领域的「框架」每月都在翻新，但第一性原理五年内不会变：循环、工具、上下文、共同语言、运行时。本站教你的就是这五样。剩下的，去读源码、跑 Evals、造你自己的 Harness 吧。
