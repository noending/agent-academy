LLM基础与生态

本章目标：理解LLM核心概念、发展历程与主流模型架构

1.1 什么是大语言模型：从“接龙”到通用智能

你可以把大语言模型（LLM）想象成一个超级“文字接龙”高手：给它一段上文，它预测下一个最可能出现的词。但神奇的是，当这个“接龙”游戏玩到千亿参数、万亿token的规模时，模型就涌现出了生成、理解、推理三大核心能力。

  • 生成：写文章、写代码、翻译、总结，本质是条件概率建模 P(下一个词 | 上文)。
  • 理解：能回答“这段话在说什么”“这句话是正面还是负面”，靠的是预训练中学到的语义表示。
  • 推理：做数学题、逻辑推断、多步规划，这是规模带来的“涌现能力”（Emergent Ability）。

LLM 的底座是 Transformer 架构，核心是 自注意力机制（Self-Attention）：每个词都能“看到”序列中所有其他词，并动态决定关注谁。相比 RNN 的顺序处理，自注意力可以并行计算，这让训练超大模型成为可能。

训练流程通常分两步：预训练（Pre-training） 在海量无标注文本上学习语言规律，然后通过指令微调（SFT）、RLHF 等对齐技术，让模型学会“听懂人话”。

下面是一个最小可运行的“下一个词预测”示例，用 Hugging Face 加载一个小模型，直观感受 LLM 的生成过程：

from transformers import pipeline

# 加载一个小型因果语言模型（首次运行会自动下载）
generator = pipeline("text-generation", model="gpt2")

prompt = "Large language models are"
output = generator(prompt, max_new_tokens=20, do_sample=True, temperature=0.8)

print(output[0]["generated_text"])
# 示例输出：Large language models are becoming increasingly powerful...

运行后你会发现，模型只是根据上文“续写”，但续写质量已经能支撑很多实际应用。记住：LLM 的一切能力，都建立在对下一个 token 的预测之上。

1.2 发展简史：从 Transformer 到 GPT、LLaMA、DeepSeek

LLM 的爆发不是一夜之间发生的，关键节点可以串成一条线：

  1. 2017 · Transformer：Google 发表《Attention Is All You Need》，提出完全基于自注意力的架构，抛弃 RNN，奠定一切基础。
  2. 2018 · BERT & GPT-1：BERT 用 Encoder 做理解，GPT 用 Decoder 做生成，两条路线分道扬镳。
  3. 2020 · GPT-3：1750 亿参数，首次展示“少样本学习”（Few-shot Learning），提示词工程开始流行。
  4. 2022 · ChatGPT：引入 RLHF，把 GPT-3.5 变成对话助手，LLM 正式出圈。
  5. 2023 · LLaMA 系列：Meta 开源 LLaMA、Llama 2，引爆开源社区，让“自己微调大模型”成为可能。
  6. 2024-2025 · Qwen、DeepSeek：国产模型崛起，DeepSeek 用 MoE（混合专家）和高效训练把成本打下来，性能对标一线闭源模型。

这条线背后有两个趋势：一是模型越来越大、越来越强；二是开源与闭源的差距在快速缩小。对工程师来说，这意味着你既可以用 API 快速上线，也可以基于开源模型做私有化部署和深度定制。

下面用代码查看一个开源模型的架构配置，理解“Decoder-only”长什么样：

from transformers import AutoConfig

config = AutoConfig.from_pretrained("Qwen/Qwen2.5-0.5B")
print("模型类型:", config.model_type)          # qwen2
print("隐藏层维度:", config.hidden_size)      # 896
print("层数:", config.num_hidden_layers)      # 24
print("注意力头数:", config.num_attention_heads)  # 14
print("是否使用 MoE:", getattr(config, "num_experts", None))

通过配置你能看到：现代 LLM 基本都是 Decoder-only 结构，堆叠几十层 Transformer Block，每层包含自注意力和前馈网络。

1.3 主流模型对比：GPT、Claude、LLaMA、Qwen 怎么选

选模型就像选车：没有最好的，只有最适合场景的。下面从几个维度对比主流模型：

模型开源/闭源特点典型场景
GPT 系列闭源综合能力最强，生态最成熟通用对话、Agent、复杂推理
Claude 系列闭源长上下文、安全性好、写作强长文档分析、代码、合规场景
LLaMA 系列开源社区生态庞大，微调资源多私有化部署、学术研究
Qwen 系列开源中文强、尺寸全、工具调用好中文应用、RAG、Agent

选择时问自己三个问题：1）数据能不能出内网？不能就选开源私有化。2）预算多少？闭源 API 按量付费，开源要算 GPU 成本。3）任务难度？简单任务小模型够用，复杂推理才上大模型。

实际工程中常用“路由”策略：简单请求走小模型，复杂请求走大模型，兼顾成本和效果。下面是一个极简的模型路由示例：

def route_model(query: str) -> str:
    """根据问题复杂度选择模型"""
    complex_keywords = ["推理", "证明", "代码", "分析", "为什么"]
    if any(kw in query for kw in complex_keywords) or len(query) > 100:
        return "gpt-4o"          # 复杂任务用大模型
    return "qwen2.5-7b"          # 简单任务用小模型

queries = ["今天天气怎么样", "请证明勾股定理并给出代码实现"]
for q in queries:
    print(f"问题: {q} -> 路由到: {route_model(q)}")

核心原则：不要用大炮打蚊子，也不要用弹弓打坦克。

1.4 典型应用场景：对话、编程、RAG、Agent

LLM 落地主要有四大场景，难度和工程复杂度依次递增：

  • 对话（Chat）：最基础，客服、助手、陪聊。核心是提示词设计和多轮上下文管理。
  • 编程（Coding）：代码补全、生成、审查、单测。代表产品 GitHub Copilot、Cursor。
  • RAG（检索增强生成）：先检索知识库，再让 LLM 基于检索结果回答。解决“模型不知道私有知识”和“幻觉”问题，是企业落地最火的方案。
  • Agent（智能体）：让 LLM 自主规划、调用工具、多步执行。比如“帮我订机票并安排行程”，需要 LLM + 工具 + 记忆 + 规划。

这四者不是互斥的，而是层层叠加：对话是交互层，RAG 是知识层，Agent 是行动层，编程是垂直应用。一个成熟的 AI 产品往往是“Agent 调度 + RAG 供知识 + 对话做交互”。

下面用 20 行代码实现一个最小 RAG 流程，感受“检索 + 生成”的威力：

from sklearn.feature_extraction.text import TfidfVectorizer
from sklearn.metrics.pairwise import cosine_similarity

# 模拟知识库
knowledge = [
    "LLM 全链路包括预训练、微调、部署和运维。",
    "RAG 通过检索外部知识来增强生成，减少幻觉。",
    "Agent 能调用工具并自主规划任务步骤。",
]

# 1. 检索：用 TF-IDF 找最相关的知识
def retrieve(query, docs, top_k=1):
    vectorizer = TfidfVectorizer()
    tfidf = vectorizer.fit_transform(docs + [query])
    sims = cosine_similarity(tfidf[-1], tfidf[:-1])[0]
    top_idx = sims.argsort()[::-1][:top_k]
    return [docs[i] for i in top_idx]

# 2. 生成：把检索结果拼进提示词（这里用模拟输出）
query = "RAG 是怎么减少幻觉的？"
context = retrieve(query, knowledge)
prompt = f"基于以下资料回答问题：\n{context[0]}\n\n问题：{query}\n回答："
print(prompt)
# 实际项目中把 prompt 发给 LLM 即可

这个例子虽然简单，但已经包含了 RAG 的核心思想：先检索、后生成，让模型“有据可依”。后续章节会深入向量数据库、Embedding、重排序等工程细节。

常见误区

  • 误区：LLM 真的“理解”了语言。实际上模型是在做概率预测，它的“理解”是统计规律的高维表示，并不具备人类意义上的意识和常识，所以会出现幻觉。
  • 误区：参数越大模型一定越好。模型效果还取决于数据质量、训练方法、对齐策略和推理优化；小模型在特定领域微调后完全可以超过通用大模型。
  • 误区：开源模型等于免费。开源模型省的是授权费，但 GPU 推理成本、部署运维、微调人力都是真金白银，规模大时可能比 API 更贵。

自测

LLM 的三大核心能力是什么？它们和“预测下一个词”有什么关系？

答案：三大核心能力是生成、理解、推理。它们都建立在“预测下一个词”的自监督训练目标之上：生成是直接续写；理解是通过预测任务学到的语义表示；推理是模型规模增大后从预测任务中涌现出的多步能力。

什么场景下你会优先选择开源模型而不是闭源 API？请至少说出两个理由。

答案：1）数据隐私和合规要求高，数据不能出内网，必须私有化部署；2）需要深度定制，比如领域微调、修改模型结构、控制推理成本；3）长期高频调用，自建推理集群可能比按量付费更划算；4）需要离线或边缘部署。

动手练习（带参考方案）

动手练习 · 搭建一个最小可运行的 LLM 调用脚本：使用 Hugging Face transformers 加…

任务：搭建一个最小可运行的 LLM 调用脚本：使用 Hugging Face transformers 加载一个开源小模型（如 Qwen/Qwen2.5-0.5B-Instruct 或 gpt2），实现一个命令行对话循环，支持多轮上下文，并打印每轮耗时。要求：1）能连续对话；2）输入 'exit' 退出；3）记录并输出每轮生成耗时。

参考方案：

import time from transformers import pipeline # 加载对话模型（首次运行会自动下载，约 1GB） generator = pipeline( "text-generation", model="Qwen/Qwen2.5-0.5B-Instruct", device_map="auto" # 有 GPU 自动用 GPU ) messages = [] print("输入 exit 退出对话。") while True: user_input = input("\n你: ").strip() if user_input.lower() == "exit": print("再见！") break messages.append({"role": "user", "content": user_input}) start = time.time() output = generator( messages, max_new_tokens=256, do_sample=True, temperature=0.7, return_full_text=False ) elapsed = time.time() - start reply = output[0]["generated_text"] messages.append({"role": "assistant", "content": reply}) print(f"助手: {reply}") print(f"[本轮耗时: {elapsed:.2f}s]") # 说明： # 1. messages 列表保存多轮上下文，实现连续对话； # 2. time.time() 记录生成前后时间差； # 3. 生产环境需加入上下文长度截断、异常处理和流式输出。
