① Attention Is All You Need（Transformer）—— 一切的起点

元信息

Vaswani et al., NeurIPS 2017 · arXiv:1706.03762 · 原文 PDF（本站） · 中文精读版 · 全文翻译

它解决什么问题：2017 年之前的序列模型（RNN/LSTM）逐词处理文本，长距离依赖记不住、训练没法并行。机器翻译的质量与速度都卡在这里。

核心思想：彻底扔掉循环结构，只靠自注意力（self-attention）：序列中每个词直接「看」所有其他词并按相关性加权聚合信息——任意两个位置之间的信息路径长度从 O(n) 变成 O(1)。

原句精读 1 · 摘要的第一句
"We propose a new simple network architecture, the Transformer, based solely on attention mechanisms, dispensing with recurrence and convolutions entirely."
「我们提出一个新的简单网络架构 Transformer，它完全基于注意力机制，彻底摒弃循环与卷积。」
小白解析：注意两个词。"简单"——AI 史上最成功的架构自我介绍居然是 simple，这是领域审美的信号：能用更少假设解释同样现象的方案，长期会赢。"完全摒弃循环"——RNN 的逐词处理正是当时并行化的死结，"摈弃"意味着作者赌的是：注意力本身足以表达序列的全部结构。这个赌注定义了之后十年。
和你的关系：你调用的大模型全是它的后代；它给你的两个日常约束——上下文窗口与注意力衰减——会在第 4 章反复出现。

结果怎么读：翻译质量刷新纪录固然重要，真正改变世界的是可并行训练——从此模型大小可以野蛮堆叠，才有后来的 GPT 与 DeepSeek 系列。

对 Builder 的启示

你不需要读懂全部数学（真的）。但要带走两个直接影响日常决策的遗产：① 上下文窗口就是注意力矩阵的物理边界——第 4 章的上下文工程全部源自这个约束；② 注意力会衰减（position bias）——「重要内容放窗口前后、避免中间塞满」（context rot 对策）不是玄学，是架构性质。

② Chain-of-Thought（思维链）—— 让模型把中间步骤写出来

元信息

Wei et al., NeurIPS 2022 · arXiv:2201.11903 · 原文 PDF（本站） · 中文精读版 · 全文翻译

它解决什么问题：模型直接回答多步推理题时错误率很高——输出一步到位，错了不知道错在哪，更没机会纠。

核心思想：在提示词里给几个带完整推理步骤的示例，模型就会模仿着先输出中间推导、再给最终答案。没有改任何模型参数。

原句精读 · 论文标题本身
"Chain-of-thought prompting elicits a series of intermediate reasoning steps that significantly improves the ability of large language models to perform complex reasoning."
「思维链提示引导出一系列中间推理步骤，显著提升大语言模型执行复杂推理的能力。」
小白解析：动词 "elicits"（引导出）很讲究——这些推理能力原本就在模型里，只是平时不拿出来；提示的作用不是"教会"，而是"引出"。和你的关系：第 3 章写提示词时永远记住这个前提：你在设计的是"引出条件"，不是"灌输知识"。所以五区结构里最关键的是边界与示例，而不是长篇说教。

结果怎么读：GSM8K 数学题上 PaLM 540B 从约 18% 跳到约 57%，且模型越大收益越大（小模型学思维链反而可能变差）——这解释了为什么推理模型（deepseek-reasoner）都是大模型，「能力涌现」这个词也由此进入主流。

对 Builder 的启示

① 提示词工程的威力第一次被严格证明：不改模型，只改上下文，表现天差地别；② 「先写理由再下结论」成为一切 Agent 推理设计的模板——ReAct 是它的行动版；③ 代价是输出变长（token 成本），所以 CoT 用在「值得想」的步骤上，这是第 8 章模型路由的依据。

③ ReAct—— 智能体范式的原点（逐节精读）

元信息

Yao et al., ICLR 2023 · arXiv:2210.03629 · 原文 PDF（本站） · 中文精读版 · 全文翻译 · 课程第 1 章的主角

它解决什么问题：两条路线各有硬伤：只会推理（CoT）的模型没有真实世界信息，幻觉频发；只会行动（行为 agent）不会规划，动作随机。问答、操作、游戏三类任务都在等统一范式。

§1 引言：范式宣言

原句精读 · 摘要核心句（全篇最重要的一句）
"Reasoning helps the model to induce, track, and update action plans as well as handle exceptions, while actions allow the model to gather additional information from external sources and update the reasoning trace."
「推理帮助模型归纳、跟踪并更新行动计划、处理例外；而行动让模型从外部来源收集额外信息、更新推理轨迹。」
小白解析：拆开看这个"闭环"：左边（推理→行动）解决了"做什么"，右边（行动→推理）解决了"想错了怎么办"。两个方向缺一不可——只有左半边就是 CoT（会想不会查），只有右半边就是当时的行动 agent（会做不会想）。
和你的关系：第 1 章模拟器里"思考气泡决定调用什么、观察气泡修正思考"的画面，就是这句话的可视化。你以后审视任何 Agent 产品，都可以问：它的推理和行动，真的互相喂养吗？

§2 方法：一条轨迹长什么样

ReAct 的全部"方法"就是设计轨迹格式：Thought / Action / Observation 三种符号交替，用少量手写范例（few-shot）喂给模型。没有新算法、没有训练——这恰恰是它影响力惊人的原因：任何人一天就能照着实现（你第 2 章已经做过）。

原句精读 · 为什么用 few-shot 而不是微调
"On tasks... where in-context learning is effective, ReAct uses a fixed number of handcrafted prompts... We also explore fine-tuning, which allows smaller models to achieve competitive performance."
「在上下文学习有效的任务上，ReAct 使用固定数量的手工范例……我们也探索了微调，使更小的模型达到有竞争力的表现。」
小白解析：两层意思。① 主体方案零训练：只要模型会"照葫芦画瓢"就能跑，这就是为什么 Agent 突然人人可做；② 作者顺手做了蒸馏实验：把 ReAct 轨迹拿去微调小模型，小模型也能学到这个范式——预告了后来"用大模型轨迹训练小模型"的整条产业路线。
和你的关系：你在第 3 章学的 few-shot 选例三原则，源头就是这里的"handcrafted prompts"——范例质量决定范式质量。

§3 实验：两类任务、三个基准

知识密集型（HotpotQA 多跳问答、FEVER 事实验证）：ReAct 的答案幻觉显著少于 CoT——因为它可以去查证。决策型（ALFWorld 家务模拟、WebShop 网页购物）：ReAct 大幅超越纯行动基线（ALFWorld 上约 71% vs 45%）——因为"先想再做"避免了乱试。

原句精读 · 关于幻觉的关键发现
"On HotpotQA and FEVER, we observe that ReAct falls into reasoning hallucination less than baseline... as it relies more on retrieved information."
「在 HotpotQA 与 FEVER 上，我们观察到 ReAct 比基线更少陷入推理幻觉……因为它更依赖检索到的信息。」
小白解析："更依赖检索到的信息"是全文最工程化的一句洞见：幻觉不是靠"让模型更聪明"解决的，是靠"让模型多看真实数据"解决的。Observation 就是给模型的"现实锚点"。
和你的关系：第 4 章知识库存在的根本理由、第 3 章"信息不足时怎么办"的边界规则，全部可以追溯到这句话。当你的 Agent 胡说八道时，第一反应应该是"它的 Observation 够不够、好不好"，而不是"换个更大的模型"。

局限（论文自己也承认）：few-shot 范例限制了轨迹结构的灵活性；逐步串行推理延迟高。后续十年的 Function Calling、并行工具调用、思维模型，都是在补这两个短板。

对 Builder 的启示

① 你在第 1 章模拟器里逐帧看过的循环，就是这篇论文；② 「Observation 质量决定下一轮决策质量」——第 6 章工具设计五原则第一条的出处；③ 现代 Function Calling 只是给 Thought/Action 换了 JSON 外衣，范式内核五年未变——读懂这篇，所有 Agent 框架对你都是透明外壳。

④ Toolformer—— 模型自学用工具

元信息

Schick et al., NeurIPS 2023 · arXiv:2302.04761 · 原文 PDF（本站） · 中文精读版 · 全文翻译

它解决什么问题：教模型用工具需要人工标注"这里该调哪个 API、参数是什么"——贵到不可扩展。

核心思想：让模型自监督地给自己造训练数据：海量插入"可能的 API 调用"候选 → 执行 → 只保留"调用确实有帮助"的样本 → 用它们微调模型自身。

原句精读 · 自监督筛选的判据
"We filter the generated API calls using a simple loss-based criterion: keep a call only if the language model finds it easier to predict future tokens when the API result is provided."
「我们用一个基于损失的简单判据筛选生成的 API 调用：只有当模型在拿到 API 结果后，更容易预测后续文本时，才保留这次调用。」
小白解析：这是全文最妙的设计："有没有用"不需要人来判断，看预测损失降没降就行——调用结果让模型"猜后续"更轻松，说明这次调用真的提供了信息。一个纯统计判据替代了昂贵的人工标注。
和你的关系：它回答了一个你终将面对的问题："该给我的 Agent 配哪些工具？"——Toolformer 的答案是"看哪个工具真的降低模型的困惑"。第 6 章"少而正交"的工具选型原则、以及用评估集验证工具价值的做法，精神同源。

结果怎么读：一个 6.7B 的小模型配上五个简单工具（计算器、检索、日历、翻译、问答），在相应任务上超越了体量约十倍的大模型裸考——「小模型 + 正确工具」打赢「大模型空手」。

对 Builder 的启示

① 现代函数调用接口的精神源头（第 2 章）；② 给模型配工具宁缺毋滥——Toolformer 学的是 5 个工具不是 50 个（第 6 章选型原则同源）；③ 它还预告了一个方向：工具使用能力可以内化进模型——今天的思考模型已经内化了大量工具规划能力。

⑤ RAG—— 知识库链路的奠基之作（逐节精读）

元信息

Lewis et al., NeurIPS 2020 · arXiv:2005.11401 · 原文 PDF（本站） · 中文精读版 · 全文翻译 · 课程第 4 章的源头

它解决什么问题：模型的知识全部冻在参数里：过时、无法更新、无法溯源、私有知识根本没有。「把知识塞进参数」（微调）成本高且依然会幻觉。

§1 引言：两种记忆

原句精读 · 参数记忆 vs 非参数记忆
"RAG models combine a pre-trained retriever (query encoder + document index) with a pre-trained seq2seq model (generator), and fine-tune end-to-end... The knowledge is stored in two sources: the parametric memory of the generator, and the non-parametric memory of the retriever."
「RAG 把预训练的检索器（查询编码器 + 文档索引）与预训练的序列到序列生成器组合，端到端微调……知识存储在两处：生成器的参数记忆，与检索器的非参数记忆。」
小白解析："参数记忆"= 烙在模型权重里的知识（改起来要重新训练）；"非参数记忆"= 一个可以随时增删改的外部文档索引（改起来是分钟级）。这个二分法是整个知识库行业的地基：第 4 章开篇"四种知识来源"表格里的第一行和第二行，就是这两个词。
和你的关系：当业务方问"能不能微调一个我们公司专用的模型"，你用这句话就能解释为什么 90% 的场景应该建知识库而不是微调——除非知识需要改变模型的"行为方式"而非"事实内容"。

§2 方法：两个变体、三个组件

检索器用 DPR（双塔向量检索：问题、文档各自编码成向量再算相似度——第 4 章 TinyVectorMemory 的"生产版原型"）；生成器用 BART；两个变体：RAG-Sequence（整段答案共用同一组检索文档）与 RAG-Token（每个 token 可以看向不同文档）。工程上几乎都用 RAG-Sequence。

§4 实验：检索真的有用吗？

原句精读 · 消融实验的结论
"We find that removing access to the retriever during generation substantially degrades performance... the generator effectively relies on the retrieved documents."
「我们发现，在生成时切断检索器会显著降低性能……生成器实际上依赖检索到的文档。」
小白解析：消融实验（ablation）= 把系统的某个零件拆掉看性能掉多少，是论文里最值得 Builder 关注的部分——它直接告诉你"哪个零件是真的在干活"。这里拆掉检索器性能大跌，证明 RAG 的收益来自检索而非生成器的容量。
和你的关系：这就是第 4 章"先看检索层还是生成层"二分法的实验依据：既然收益主要来自检索，故障诊断当然先查检索。你自己的 RAG 也应该做这个消融——把检索结果替换成随机片段，看回答掉多少。

结果怎么读：开放域问答（NQ、TriviaQA 等）刷新当时 SOTA（NQ 上 44.5 vs 此前最强约 36.6）；Jeopardy 问题生成的人类评估显示生成内容更具体、可溯源到具体维基条目——"可溯源"在今天依然是知识库系统的合规刚需。

对 Builder 的启示

① 你不需要端到端联合训练——现成嵌入 + 生成模型已够用，但「检索管找对材料、生成管忠实转述」的分工永不过时（第 4 章诊断二分法的出处）；② 「知识更新 = 更新索引而非更新参数」从此成为行业默认架构；③ 它的天花板（多跳、全局汇总）正是 GraphRAG 与本体介入的入口。

⑥ Reflexion—— 失败后用语言自我改进

元信息

Shinn et al., NeurIPS 2023 · arXiv:2303.11366 · 原文 PDF（本站） · 中文精读版 · 全文翻译 · 课程第 5 章反思机制的源头

它解决什么问题：强化学习微调又贵又慢；Agent 失败后，下一次尝试通常原样再错一遍。

核心思想：失败后让模型用自然语言反思（"我错在没考虑 X"），存进情景记忆；下次尝试同一任务时把反思注入上下文。用「语言」替代「梯度」做自我改进。

原句精读 · 语言即强化信号
"Reflexion is a simple psychological idea: verbal reinforcement... an agent dynamically reflects on its own experiences and stores these reflections in an episodic memory buffer in natural language."
「Reflexion 是一个简单的心理学思想：语言化的强化……智能体对自身经验动态反思，并把反思以自然语言存进情景记忆缓冲区。」
小白解析：强化学习用"奖励数字"改权重，Reflexion 用"一段话"改上下文——信息量更大（包含因果解释：错在"为什么"）、成本更低（无需训练）、但只对"同任务重试"生效。
和你的关系：第 5 章反思机制的实现就是这篇：失败 → 追问根因 → 教训写进记忆文件 → 重试带上。注意它定义的三角角色（执行者 / 评估者 / 反思者）——你的 Harness 里加两个提示词模板就能拥有它。

结果怎么读：ALFWorld 任务成功率 60% → 97%（134 题对 130）；HumanEval 代码生成 91%（超过当时 GPT-4 裸考的 80%）。记忆系统的价值从此有了硬数字：第 4、5 章讲的"记忆 = 改进"不只是记用户偏好，更是 Agent 自我进化的载体。

⑦ GraphRAG—— 知识库与知识图谱合流

元信息

Microsoft Research, 2024 · arXiv:2404.16130 · 原文 PDF（本站） · 中文精读版 · 全文翻译 · 课程第 4、6 章的交汇点

它解决什么问题：向量 RAG 擅长"这个问题在哪段话里说过"，答不了全局性、汇总性问题："这批文档的核心主题是什么？"——答案不存在于任何一个片段里，Top-K 检索注定残缺。

核心思想：离线用 LLM 从全部文档抽取实体关系建图 → 社区检测聚成主题 → 逐社区生成摘要（层级化）→ 在线按问题粒度选层级做 map-reduce 汇总。本质：用 LLM 把文档预消化成多层"理解产物"，查询时拿消化过的理解替代原始片段。

原句精读 · local to global 的含义
"Query-focused summarization (QFS) tasks... differ from explicit retrieval tasks such as 'what does X say about Y'... Our approach transforms the corpus into a hierarchical community structure and summarizes communities at increasing levels of abstraction."
「查询聚焦式摘要类任务……不同于『X 关于 Y 说了什么』这类显式检索任务……我们的方法把语料转成层级化社区结构，并在越来越高的抽象层级上做社区摘要。」
小白解析：作者一开始就划清了两类问题的界线："X 关于 Y 说了什么"= 局部检索（向量 RAG 的主场）；"这批材料整体在讲什么"= 全局摘要（向量 RAG 的盲区，因为答案不在任何一段里）。
和你的关系：第 4 章 4.6 节的分流策略（向量管相似、图谱管关系）在这里升级成了三级火箭：检索片段 → 图谱关系 → 社区摘要。判断你的知识库该建哪层，就看业务问题落在哪一类。

结果怎么读：全局性问题上全面性与多样性大幅超越基线向量 RAG；代价是离线索引成本高一个数量级（海量抽取调用）——典型「离线贵、在线强」的架构权衡，与第 6 章 LLM 抽取管线（你的毕业项目已实现其最小版）直接衔接。

⑧ SWE-agent—— 接口设计 = 被低估的性能杠杆

元信息

Yang et al., NeurIPS 2024 · arXiv:2405.15793 · 原文 PDF（本站） · 中文精读版 · 全文翻译 · 课程第 7 章的核心论据

它解决什么问题：给模型一台"电脑"让它修真实 GitHub issue，成功率一开始很低。问题出在哪：模型？还是它面对的那套"键盘和屏幕"？

核心思想：提出 ACI（Agent-Computer Interface）：为模型设计命令与反馈格式要像 HCI 为人类设计 UI 一样严肃。三条原则：① 反馈回路（编辑后立刻 lint 报错行，模型当场自纠）；② 高效交互（专用文件查看器替代裸 cat）；③ 不让模型做人类也做不好的事。

原句精读 · 全文论点的一句话版
"SWE-agent... achieving a resolve rate of 12.47%... We show that design decisions in the agent-computer interface (ACI) substantially impact performance: agents with well-designed interfaces substantially outperform those without."
「SWE-agent……取得 12.47% 的解决率……我们证明智能体-计算机接口（ACI）中的设计决策对性能影响巨大：设计良好的接口让智能体显著超越没有设计接口的版本。」
小白解析：注意实验设计：模型不变，只变接口，成功率显著波动——所以"模型决定上限，Harness 决定下限"这句口号的实验证据就是它。12% 看似不高，但这是"无人干预修真实 GitHub bug"的通过率，当时是记录。
和你的关系：你的工具 JSON Schema、错误信息、返回格式就是你的 ACI。调优顺序应当是"先磨接口，再换模型"——接口优化的收益成本比远高于换更大模型（第 7 章 Harness 的立论）。

结果怎么读：SWE-bench 当时 SOTA（12.47%），且消融显示去掉 lint 反馈回路等接口特性后通过率明显下滑——每一个接口细节都在贡献分数。方法论部分（如何迭代 ACI）本身就是一份 Harness 工程的实验设计模板。

怎么读论文：三遍读法

  1. 第一遍 · 5 分钟（决定要不要读）

    只看标题、摘要、所有图表。回答三个问题：解决什么问题？核心主张一句话是什么？和我的项目有关吗？90% 的论文在这一步就该放下，这是效率而非偷懒。

  2. 第二遍 · 30 分钟（读懂主张）

    通读引言、方法框架图、实验主表，跳过证明与附录。目标：能向同事复述「它怎么做到的」。本页每篇的「核心思想 + 关键设计 + 原句精读」就是第二遍该产出的东西。

  3. 第三遍 · 按需（复现级）

    只有要落地或做研究时才进行：推公式、抠实验细节、跑开源实现。先问「我要用它改变哪个设计决策」再进入第三遍——没有决策要改，就不值得第三遍。

Builder 的论文观

应用层开发者读论文的目的不是追前沿，而是为自己的设计决策找到依据与边界：为什么工具描述要这样写（ReAct/Toolformer）？为什么检索要先于提示词调优（RAG）？为什么接口值得花一周打磨（SWE-agent）？——每篇论文都是某个「行业默认做法」的第一性解释。
