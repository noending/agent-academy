硬件参数与算力评估

本章目标：读懂硬件规格表，解释显存、带宽、算力对推理的影响。

硬件组成：GPU、CPU、内存、存储、互联与网络

把一台推理服务器想象成一家餐厅：GPU 是后厨的灶台，负责真正“炒菜”（矩阵乘法）；CPU 是前台和调度员，负责接单、拆解任务、启动 GPU；内存（RAM）是备菜台，存放还没下锅的食材（模型权重、中间数据）；显存（VRAM）是灶台旁边的操作台，离 GPU 最近，放正在炒的菜；存储（SSD/HDD）是仓库，放冷鲜食材（模型文件、日志）；互联（PCIe/NVLink）是传菜通道，决定食材从备菜台到灶台的速度；网络（以太网/InfiniBand）是外卖通道，决定多台机器之间怎么协作。

不同场景对硬件的需求不同：

  • 消费级 GPU（如 RTX 4090）：显存 24GB 左右，适合个人开发、小模型推理、微调。优点是便宜、功耗低；缺点是显存小、没有 NVLink、多卡通信走 PCIe。
  • 数据中心 GPU（如 A100/H100）：显存 40GB~80GB，支持 NVLink，带宽极高，适合大模型训练和推理。缺点是贵、功耗高、需要专业散热和供电。
  • Apple Silicon（M 系列）：统一内存架构，CPU 和 GPU 共享内存，内存可达 128GB 甚至 192GB，适合本地跑大模型。缺点是 GPU 算力相对弱，生态不如 CUDA 成熟。

关键结论：选硬件不是只看 GPU，而是看整个数据通路是否匹配你的任务。如果模型权重放不进显存，再强的算力也发挥不出来；如果互联带宽太低，多卡并行反而会拖慢速度。

关键参数：显存、带宽、算力、互联与功耗

读懂硬件规格表，核心看这几个参数：

参数含义对推理的影响
显存容量（VRAM）GPU 能直接访问的内存大小决定模型能不能装下；装不下就要切分或换卡
显存带宽（Memory Bandwidth）每秒能从显存读写多少数据，单位 GB/s决定 token 生成速度；带宽越高，解码越快
计算单元 / Tensor CoreGPU 里做矩阵乘法的专用硬件决定预填充（prefill）阶段的吞吐
频率GPU 核心运行时钟，单位 GHz影响单次计算延迟，但不如带宽和核心数关键
PCIe / NVLinkGPU 与 CPU、GPU 与 GPU 之间的通信通道决定多卡并行效率；NVLink 比 PCIe 快数倍
功耗（TDP）满载时的热设计功耗，单位 W决定供电和散热成本；数据中心卡可达 700W

一个具体例子：RTX 4090 有 24GB 显存、约 1008 GB/s 带宽、FP16 算力约 330 TFLOPS。A100 80GB 有 80GB 显存、约 2039 GB/s 带宽、FP16 算力约 312 TFLOPS。虽然两者 FP16 峰值算力接近，但 A100 显存更大、带宽更高，所以能跑更大的模型，且解码速度更快。

关键结论：推理速度往往受显存带宽限制，而不是峰值算力。因为自回归生成时，每生成一个 token 都要把整个模型权重读一遍，这是典型的“内存带宽瓶颈”场景。

单位与口径：FLOPs、TFLOPS、TOPS、GB 与 GiB、精度

硬件规格表里单位很多，容易混淆。先记住几个核心换算：

  • FLOPs：浮点运算次数，是“工作量”。比如一次矩阵乘法做了多少 FLOPs。
  • FLOP/s：每秒浮点运算次数，是“速度”。TFLOPS = 10^12 FLOP/s，PFLOPS = 10^15 FLOP/s。
  • TOPS：每秒万亿次操作，通常用于整数运算（INT8/INT4）。TOPS 和 TFLOPS 不能直接比，因为操作类型和精度不同。
  • GB vs GiB：GB 是十进制（10^9 字节），GiB 是二进制（2^30 字节）。1 GiB ≈ 1.074 GB。厂商标注的“80GB”通常是十进制，系统里看到的是 GiB，所以会“缩水”。
  • GB/s vs Gb/s：GB/s 是字节，Gb/s 是比特。1 GB/s = 8 Gb/s。网络带宽常用 Gb/s，显存带宽常用 GB/s。

精度方面，不同精度占用的显存和算力不同：

精度每参数字节特点
FP324最精确，训练常用，推理慢
FP162推理常用，范围较小
BF162范围与 FP32 相同，训练/推理都常用
FP81新卡支持，速度快，精度损失可控
INT81量化推理常用，速度快
INT40.5极致压缩，精度损失较大

下面是一个最小示例，计算模型权重占用的显存：

def vram_for_weights(num_params_billion, bytes_per_param):
    """计算模型权重占用的显存（GB，十进制）"""
    num_params = num_params_billion * 1e9
    bytes_total = num_params * bytes_per_param
    return bytes_total / 1e9

# 7B 模型在不同精度下的权重显存
for name, bpp in [("FP32", 4), ("FP16/BF16", 2), ("INT8", 1), ("INT4", 0.5)]:
    print(f"7B {name}: {vram_for_weights(7, bpp):.2f} GB")

# 输出：
# 7B FP32: 28.00 GB
# 7B FP16/BF16: 14.00 GB
# 7B INT8: 7.00 GB
# 7B INT4: 3.50 GB

关键结论：精度每降一半，显存占用也大约减半，但精度损失需要评测验证。实际推理还要加上 KV Cache、激活值等开销，通常比权重多 10%~30%。

常见误区与实战选型思路

这一节把最容易踩的坑集中讲清楚：

  • 只看显存选卡：显存大不代表推理快。如果带宽低，生成 token 会很慢。比如某些大显存但低带宽的卡，跑大模型时吞吐可能不如小显存高带宽的卡。
  • 峰值算力高不等于推理快：推理分预填充和解码两个阶段。预填充吃算力，解码吃带宽。很多场景解码是瓶颈，所以带宽比峰值算力更重要。
  • 不同精度 TOPS 不能直接比：INT8 的 TOPS 和 FP16 的 TFLOPS 不是一回事。比较时要看同一精度下的数据，或者看实际任务吞吐。
  • 多卡显存不能无条件合并：多卡不会自动把显存拼成一块。需要模型并行、张量并行等技术，而且通信开销可能抵消收益。NVLink 比 PCIe 更适合多卡并行。
  • 统一内存不等于全部可用：Apple Silicon 的统一内存虽然大，但系统和其他应用也要占用，实际能给模型的通常只有 70%~80%。

实战选型可以按这个顺序问自己：

  1. 模型多大？权重 + KV Cache 需要多少显存？
  2. 目标吞吐和延迟是多少？解码阶段带宽够不够？
  3. 单卡装不下，要不要多卡？互联带宽够不够？
  4. 功耗和散热能不能满足？
  5. 预算和生态（CUDA/ROCm/Metal）是否匹配？

关键结论：硬件选型是“显存容量、带宽、算力、互联、功耗”的联合优化，任何单一指标都不能决定成败。

常见误区

  • 只看显存容量选卡，忽略显存带宽和互联能力，导致大模型能装下但生成速度极慢。
  • 把不同精度的 TOPS 和 TFLOPS 直接比较，误以为 INT8 的 TOPS 高就代表所有任务都更快。
  • 认为多卡显存会自动合并成一块大显存，实际上需要模型并行且通信开销可能很大。
  • 把统一内存的全部容量都算作可用显存，忽略系统和应用占用，导致实际能跑的模型比预期小。

自测

某模型权重为 13B 参数，使用 INT8 量化，权重显存大约是多少？如果显存带宽为 500 GB/s，解码阶段每生成一个 token 大约需要读多少数据？

答案：13B INT8 权重显存约 13 GB（13e9 * 1 字节 = 13e9 字节 = 13 GB）。解码阶段每生成一个 token 需要读取全部权重，约 13 GB 数据。在 500 GB/s 带宽下，理论最短时间约 13/500 = 0.026 秒，即约 38 tokens/s（不考虑 KV Cache 和开销）。

为什么说“峰值算力高不等于推理快”？请从预填充和解码两个阶段解释。

答案：推理分两个阶段：预填充阶段一次性处理输入 prompt，计算密集，吃峰值算力；解码阶段逐 token 生成，每步都要读取全部模型权重，是内存带宽瓶颈。如果显存带宽低，即使峰值算力很高，解码速度也会很慢。因此推理速度是算力和带宽共同决定的，很多场景下带宽才是瓶颈。
