深入理解 Harness（智能体框架）

「Harness」是 Agent 圈近年来最重要的词之一，却几乎没有中文社区把它讲透。 本章把它彻底讲透：它是什么、为什么它决定 Agent 的下限、由哪些部件组成、DeepSeek 在其中扮演什么角色。

目标：能设计自己的 Harness 交互实验：Harness 实验室 含 mini-harness 代码 流式拼接 · 成本核算 · 模型路由 练习：4 题（带参考答案）

7.1 什么是 Harness？

Harness 的本义是「马具」——套在马身上的那套皮革与缰绳，把马的蛮力转化为可驾驭的前进动力。 软件工程里早有先例：测试领域的 test harness，指驱动被测代码运行的一整套脚手架。 在 LLM 时代，这个词经由评测项目（如 EleutherAI 的 lm-evaluation-harness）进入大众视野，随后被 Agent 社区接管：

定义

Agent Harness（智能体框架 / 运行时）= 围绕 LLM 构建的全部运行时脚手架：系统提示、工具实现、Agent 主循环、上下文管理、权限与安全、子 Agent 调度、日志追踪、持久化恢复……
一句话：模型是引擎，Harness 是整辆车。你也可能见到同义的说法 scaffold（脚手架）或 agent runtime。

由这个定义直接推出 Agent 工程中最重要的经验公式：

模型决定上限，Harness 决定下限

同一个 deepseek-chat，放在裸循环里（第 2 章的最小版）和放在精心设计的 Harness 里，完成真实任务的成功率可以是天壤之别——模型没变，变的是它每一步能看到什么、能做什么、犯错后会被如何兜住。Harness 不是模型的附属品，而是把模型能力「兑现」出来的兑现器。

这不是空话：有论文实证

2024 年的 SWE-agent 论文（Yang et al., NeurIPS）专门研究了「智能体–计算机接口」（ACI，本质上就是 Harness 的工具层）对性能的影响： 同一个模型，仅改变工具接口的设计（比如给编辑工具加上「改完必须重新读文件」的反馈回路），在真实 GitHub issue 修复基准上的成功率就有显著差异。 结论与第 2 章的「工具描述五原则」互相印证：接口设计是被低估的性能杠杆。

7.2 解剖：Harness 的八大组件

任何生产级 Harness（包括 Claude Code、Devin、 Manus 这类产品）都能拆成下面八个部件。每个部件都给你「是什么 + 设计要点」：

  1. 系统提示层

    模型的人格、规则与输出契约。要点：分区排版；规则用祈使句与正例；把「完成标准」显式写出；控制篇幅——系统提示本身也是上下文，塞满例外条款会让模型顾此失彼。

  2. 工具层

    工具实现 + JSON Schema 声明 + 注册表。要点（SWE-agent 论文背书）：少而正交（能组合出复杂操作）；幂等；返回信息密集的结果（模型最需要的不是 "success"，而是它能据此决策的内容）；错误信息写给「模型」看，不是写给人看。

  3. 主循环

    第 2 章那个 while 循环。要点：最大步数保险丝；并行工具调用支持；每轮决定「继续 / 求助 / 终止」的策略；重试与指数退避。

  4. 上下文管理器

    第 5 章四大策略（裁剪 / 压缩 / 外置 / 结构化）的落地组件。要点：给「不可丢」的信息（验收标准、用户偏好）设计独立的存活通道。

  5. 权限与安全层

    工具按风险分级：auto（自动执行）/ confirm（要用户点头）/ deny（禁止）。外加路径白名单、网络隔离、注入内容隔离。要点：执行权永远在 Harness 手里——这是整个 Agent 安全模型的基石。

  6. 子 Agent 调度器

    按需生成携带独立上下文的子 Agent（fan-out），回收时只取结论。要点：子 Agent 的提示里要给足背景，因为它看不到主对话。

  7. 可观测性

    全量 Trace + 成本计量 + Evals。要点：没有 Trace 的 Harness 无法调试，没有 Evals 的 Harness 无法进化。

  8. 持久化与恢复

    会话状态落盘，崩溃后能从断点续跑。长任务（数小时的自主运行）没有这一条等于裸奔。

第 1 章四要素 → 八大组件

还记得四要素吗？LLM 是引擎（不在 Harness 内）；工具、循环、记忆分别对应组件 2/3/4+6；而系统提示、权限、可观测、持久化，是「让要素能安全高效协作」的骨架。两张清单合起来 = 完整的 Agent。

7.3 DeepSeek 作为 Harness 的引擎

Harness 决定下限，但引擎依然决定上限的一部分。DeepSeek 作为引擎有几个鲜明的工程特征：

🔌

OpenAI 兼容 = 可插拔

改一个 base_url 就接入（第 2 章已做）。Harness 与引擎解耦，你可以随时给同一套 Harness 换引擎做 A/B 对比。

上下文缓存

DeepSeek 自动做前缀缓存：Agent 循环每轮都重复发送的大段相同前缀（系统提示、历史消息）命中缓存后按大幅折扣计费。Agent 越是「连续作业」，省得越多——这是它对 Agent 经济学的直接贡献。

双档引擎

deepseek-chat 干高频执行，deepseek-reasoner 干重规划与反思（思维链经 reasoning_content 可观测）。「便宜引擎跑循环 + 强引擎做关键决策」是性价比最高的 Harness 架构之一。

开源权重

V3 / R1 系列开放权重，允许自托管：数据不出域、延迟可控、可微调。对合规敏感场景，这让 DeepSeek 成为少数能把整个 Harness 连同引擎都锁在自己机房里的选择。

7.5 实战：把第 2 章的 Agent 升级成 mini-harness

纸上谈完，动手兑现。下面把第 2 章的最小版升级：加入工具注册表、权限分级、Trace 日志——八大组件里的 2、5、7 号就位：

python · mini_harness.py（核心部分）
"""mini_harness.py —— 从 Agent 到 Harness 的第一次进化"""
import json, os, time
from openai import OpenAI

client = OpenAI(api_key=os.environ["DEEPSEEK_API_KEY"],
                base_url="https://api.deepseek.com")
MODEL = "deepseek-chat"

# ── 组件 2：工具注册表（含声明 / 实现 / 权限级）──────────────
class ToolRegistry:
    def __init__(self):
        self._tools = {}

    def register(self, spec, impl, permission="auto"):
        """permission: auto=直接执行 | confirm=需人工确认"""
        self._tools[spec["function"]["name"]] = (spec, impl, permission)

    def specs(self):
        return [t[0] for t in self._tools.values()]

    def call(self, name, args, confirm_fn):
        if name not in self._tools:
            return {"error": f"未知工具 {name}，可用: {list(self._tools)}"}
        _, impl, perm = self._tools[name]
        if perm == "confirm" and not confirm_fn(f"执行 {name}({args})?"):
            return {"error": "用户拒绝执行该操作，请换一种方案。"}
        try:
            return impl(**args)
        except Exception as e:
            return {"error": f"{type(e).__name__}: {e}"}

# ── 组件 7：可观测性（Trace 日志）────────────────────────
class Trace:
    def __init__(self, path="trace.jsonl"):
        self.path = path; self.t0 = time.time()
    def log(self, kind, **kw):
        rec = {"t": round(time.time() - self.t0, 2), "kind": kind, **kw}
        print("·", kind, {k: v for k, v in kw.items() if k != "messages"})
        with open(self.path, "a", encoding="utf-8") as f:
            f.write(json.dumps(rec, ensure_ascii=False) + "\n")

# ── Harness 主体：循环不变，周边增厚 ─────────────────────
class Harness:
    def __init__(self, registry, system_prompt, max_steps=10):
        self.registry = registry
        self.system_prompt = system_prompt
        self.max_steps = max_steps

    def confirm(self, question):           # 生产中接到 UI；教学里用命令行
        return input(f"  {question} [y/N] ").strip().lower() == "y"

    def run(self, user_input):
        trace = Trace()
        messages = [{"role": "system", "content": self.system_prompt},
                    {"role": "user", "content": user_input}]
        for step in range(self.max_steps):
            resp = client.chat.completions.create(
                model=MODEL, messages=messages,
                tools=self.registry.specs())
            msg = resp.choices[0].message
            usage = resp.usage
            trace.log("llm_call", step=step,
                      tokens=usage.total_tokens)
            if not msg.tool_calls:
                trace.log("final")
                return msg.content
            messages.append(msg)
            for tc in msg.tool_calls:
                args = json.loads(tc.function.arguments or "{}")
                trace.log("tool_call", step=step, name=tc.function.name, args=args)
                result = self.registry.call(
                    tc.function.name, args, confirm_fn=self.confirm)
                messages.append({"role": "tool", "tool_call_id": tc.id,
                                 "content": json.dumps(result, ensure_ascii=False)})
        return "已达最大步数。"

# ── 组装与运行 ─────────────────────────────────────────
if __name__ == "__main__":
    reg = ToolRegistry()
    reg.register(SPEC_GET_WEATHER, impl_get_weather, permission="auto")
    reg.register(SPEC_DELETE_FILE, impl_delete_file, permission="confirm")  # 高危！
    h = Harness(reg, "你是一个严谨的生活助理，实时信息必须调用工具。")

① 流式模式下把「分片」拼回完整工具调用

第 2 章提过：流式时 tool_calls 是碎着来的。拼接是所有流式 Agent UI 的必经之路：

python · stream_tools.py
def stream_with_tools(client, messages, tools_spec):
    """流式输出正文 + 实时拼装工具调用。返回 (全文, 完整的 tool_calls)"""
    content, calls = "", {}          # calls: index -> {id, name, args}

    stream = client.chat.completions.create(
        model="deepseek-chat", messages=messages,
        tools=tools_spec, stream=True,
    )
    for chunk in stream:
        delta = chunk.choices[0].delta
        if delta.content:                          # 正文增量：立即上屏
            print(delta.content, end="", flush=True)
            content += delta.content
        for tc in (delta.tool_calls or []):        # 工具调用增量：按 index 拼接
            slot = calls.setdefault(tc.index, {"id": "", "name": "", "args": ""})
            if tc.id:    slot["id"] += tc.id
            if tc.function and tc.function.name:
                slot["name"] += tc.function.name
            if tc.function and tc.function.arguments:
                slot["args"] += tc.function.arguments

    print()
    return content, list(calls.values())

② 成本核算：每个 Agent 都该有一个 CostMeter

python · cost_meter.py
class CostMeter:
    """单价表按官方文档维护（元/百万token）；缓存命中价更低，可分档登记"""
    PRICES = {                       # (输入价, 输出价) 元/百万 token —— 示意值
        "deepseek-chat":     (2.0, 8.0),
        "deepseek-reasoner": (4.0, 16.0),
    }

    def __init__(self, model="deepseek-chat"):
        self.model = model
        self.in_toks = self.out_toks = 0
        self.in_cached = 0           # 命中前缀缓存的部分，单价更低

    def add(self, usage):
        self.in_toks += usage.prompt_tokens
        self.out_toks += usage.completion_tokens
        if getattr(usage, "prompt_cache_hit_tokens", 0):
            self.in_cached += usage.prompt_cache_hit_tokens

    @property
    def cost(self) -> float:
        pin, pout = self.PRICES[self.model]
        return (self.in_toks * pin + self.out_toks * pout) / 1_000_000

    def report(self) -> str:
        hit = f"（缓存命中 {self.in_cached}）" if self.in_cached else ""
        return f"{self.model}：{self.in_toks} in{hit} / {self.out_toks} out ≈ ¥{self.cost:.4f}"

# 用法：Harness 每轮循环里 meter.add(resp.usage)，结束时 print(meter.report())
为什么非要一块钱一块钱地记

Agent 的成本是按步数复利的：历史每轮重发，第 20 步的输入 token 远大于第 1 步。有了 CostMeter，你才能回答「这个任务平均花多少钱」「哪个工具最烧钱」「换 reasoner 值不值」——这些都是第 8 章上线前的必答题。而 DeepSeek 的前缀缓存（自动命中、按大幅折扣计费）会让 in_cached 随循环轮数快速增长——同一套 Harness 越连续作业越便宜。

import json, os, time, random
from openai import OpenAI, RateLimitError, APITimeoutError, APIConnectionError

client = OpenAI(api_key=os.environ["DEEPSEEK_API_KEY"],
                base_url="https://api.deepseek.com")

# ── 传输层韧性：重试 + 退避（第 2 章 2.7）────────────────
def call_llm(max_retries=3, **kw):
    for attempt in range(max_retries):
        try:
            return client.chat.completions.create(**kw)
        except RateLimitError:
            time.sleep(min(2 ** attempt + random.random(), 30))
        except (APITimeoutError, APIConnectionError):
            if attempt == max_retries - 1: raise
            time.sleep(2 ** attempt)
    raise RuntimeError("重试耗尽")

            + "\n".join(f"[{m['role']}] {str(m.get('content') or '')[:400]}"
                        for m in head if m.get("content"))}])
    return [messages[0],
            {"role": "user",
             "content": f"[此前对话摘要]{summary.choices[0].message.content}"},
            *tail]

# ── 模型路由（7.6）──────────────────────────────────
def route(mode):
    return "deepseek-reasoner" if mode in ("plan", "reflect") else "deepseek-chat"

# ── 主循环：全部组件在这里汇合 ───────────────────────
class Harness:
    def __init__(self, registry, system_prompt, max_steps=12):
        self.reg, self.sys, self.max_steps = registry, system_prompt, max_steps
        self.trace = open("trace.jsonl", "a", encoding="utf-8")

    def confirm(self, q):                       # CLI 确认；Web 版换审批队列
        return input(f"  {q} [y/N] ").strip().lower() == "y"

    def run(self, task, mode="execute"):
        model, meter = route(mode), None
        messages = [{"role": "system", "content": self.sys},
                    {"role": "user", "content": task}]
        for step in range(self.max_steps):
            resp = call_llm(model=model, temperature=0,
                            messages=maybe_compact(messages),
                            tools=self.reg.specs())
            if meter is None:
                meter = CostMeter(model)
            meter.add(resp.usage)
            msg = resp.choices[0].message
            self.trace.write(json.dumps(
                {"step": step, "model": model,
                 "tools": [tc.function.name for tc in (msg.tool_calls or [])]},
                ensure_ascii=False) + "\n")
            if not msg.tool_calls:                          # 终止信号
                return msg.content, meter.report()
            messages.append(msg)
            for tc in msg.tool_calls:
                args = json.loads(tc.function.arguments or "{}")
                result = self.reg.call(tc.function.name, args, self.confirm)
                messages.append({"role": "tool", "tool_call_id": tc.id,
                                 "content": json.dumps(result, ensure_ascii=False)})
        return "已达最大步数。", meter.report()

7.9 沙箱：把执行关进笼子（20 行最小实现）

第 5 章安全防线里「沙箱」讲了概念，这里给出进程级的最小实现——目录白名单 + 超时熔断 + 输出截断：

python · sandbox.py —— 可直接运行
"""sandbox.py —— 最小命令沙箱：教学版，生产请上容器"""
import shlex, subprocess
from pathlib import Path

class Sandbox:
    def __init__(self, root="./workspace", timeout=30, max_output=4000):
        self.root = Path(root).resolve()
        self.root.mkdir(exist_ok=True)
        self.timeout, self.max_output = timeout, max_output

    def run(self, cmd: str) -> dict:
        parts = shlex.split(cmd)
        if not parts:
            return {"error": "空命令"}
        # ① 路径白名单：命令参数必须落在 workspace/ 内
        for a in parts[1:]:
            try:
                (self.root / a.lstrip("./")).resolve().relative_to(self.root)
            except ValueError:
                return {"error": f"路径越界，只允许访问 {self.root.name}/ 内的文件"}
        # ② 受控执行：限时 + 工作目录锁定 + 输出截断
        try:
            p = subprocess.run(parts, cwd=self.root, shell=False,
                               timeout=self.timeout, capture_output=True,
                               text=True)
        except subprocess.TimeoutExpired:
            return {"error": f"执行超过 {self.timeout}s，已终止"}
        except FileNotFoundError:
            return {"error": f"命令不存在: {parts[0]}"}
        return {"exit_code": p.returncode,
                "output": (p.stdout + p.stderr)[:self.max_output] or "(无输出)"}

# sb = Sandbox()
# sb.run("ls .")            → 正常返回
# sb.run("cat /etc/passwd") → {"error": "路径越界..."}
# sb.run("sleep 999")       → {"error": "执行超过 30s，已终止"}
沙箱的三层强度

① 进程级（本例）：白名单 + 超时 + 输出上限——挡住绝大多数事故，实现成本最低；② 容器级：docker run --network none + 只读根文件系统 + 资源配额——生产默认档；③ 系统级：gVisor / Firecracker 微虚拟机——运行不可信生成代码时的选择。原则与第 5 章一致：权限决定「能不能」，沙箱决定「出事了损失多大」。

7.10 MCP 实操：把你的工具变成标准件（30 行）

全课程多次提到 MCP，现在动手。先理清它在链路里的位置——MCP 和 Function Calling 不是竞争关系，而是两段接口：模型 ↔ Harness 之间只有 Function Calling（模型只会输出 tool_calls JSON）；Harness ↔ 工具/数据源 之间才是 MCP——它解决工具的发现、接入与跨产品复用（写一次工具，Claude Code、你的 Harness、Palantir 都能接）。

模型 ↔（Function Calling）↔ 你的 Harness ↔（MCP）↔ 工具与数据源。所以「接了 MCP 仍离不开 Function Calling」：模型侧的对话协议不会变。MCP 的价值在 Harness 右侧——工具的标准化发现与复用；第 6 章 Palantir 的 MCP toolkit 与本节的 FastMCP，是同一思想的两端。

自测

「模型决定上限，Harness 决定下限」——用八大组件中的三个，各举一个「拉低下限」的具体方式。

示例答案：工具层：报错只返回 exit code 1，模型无法据此修正，反复盲试烧 token；上下文管理：历史不压缩，关键验收标准被挤出窗口，模型「忘了目标」；权限层：无确认机制，一条 rm -rf 毁掉全部进度。三条对应实验室里的三个开关——现象一致。

为什么 OpenAI 兼容接口对 Harness 设计是重大利好？

答案：它把引擎从 Harness 中解耦：同一套工具、循环、权限、Trace 可以在 deepseek-chat / deepseek-reasoner / 其他兼容引擎之间即插即换，用配置而非代码切换。于是你可以：按任务混用引擎档位、做引擎 A/B 评测、在厂商涨价或故障时快速迁移——骨架不随引擎生死。

前缀缓存为什么恰好对 Agent 场景特别有效？

答案：Agent 循环的消息数组是只增不改的：每轮 = 上一轮 + 新消息，前缀完全相同。前缀缓存命中后，重复部分按大幅折扣计费。循环步数越多、系统提示与历史越长，折扣红利越大——Agent 是前缀缓存的最理想客户。

MCP 和 Function Calling 是什么关系？为什么接了 MCP 仍然离不开 Function Calling？

答案：两者处在链路的不同段：Function Calling 是「模型 ↔ Harness」的接口——模型只会输出 tool_calls JSON，这由模型能力决定；MCP 是「Harness ↔ 工具/数据源」的协议——解决工具的发现、接入与跨产品复用。因此接入 MCP 后，Harness 仍要把 MCP 工具转成 tools_spec 发给模型、把模型的调用意图经桥接层转发给 MCP server（7.10 节）。一句话：MCP 管连接，Function Calling 管对话，缺一不可。

练习 2 · 症状诊断：哪个组件缺失？

任务：三位开发者的 Agent 出了以下症状，各指出最可能是八大组件中的哪一个缺失：

  1. A 的 Agent 第 30 步时开始重复做已完成的事，且忘了最初的验收要求。
  2. B 的 Agent 在一次搜索后突然开始执行提示里从未出现过的操作。
  3. C 的 Agent 在网络抖动后直接崩溃退出，没有降级输出。

参考答案：

  1. 上下文管理器缺失：历史滚到窗口边缘，早期约束被挤出（context rot + 无压缩/外置）。
  2. 安全层 / 内容隔离缺失：搜索结果里几乎必然带着外部文本，提示注入最可能的入口；也可能是权限分级缺失让危险动作直接执行——两层都要查。
  3. 主循环的韧性缺失：没有重试/降级（第 2 章 2.7 节的十行防御）；顺带检查持久化——崩溃后能不能从断点恢复？

这个练习的元技能：把「Agent 表现诡异」翻译成「哪个组件的哪个职责没兑现」——这就是 Harness 思维的日常用法。
