第1章 · LLM基础概念

本章目标：理解LLM基本定义、发展历程与核心能力

1.1 什么是语言模型：从统计到神经网络

语言模型（Language Model）听起来很玄，其实它的核心任务就一句话：计算一个词序列出现的概率。比如，给定前几个词“今天天气”，语言模型要能算出下一个词是“好”的概率有多大，是“坏”的概率有多大。这个概率越大，说明模型越认为这个句子“像人话”。

最早的语言模型是统计语言模型，比如 N-gram 模型。它基于马尔可夫假设：一个词出现的概率只与前面 N-1 个词有关。例如，二元语法（Bigram）只依赖前一个词。这种模型简单，但有两个大问题：一是数据稀疏，很多词组合在训练语料里根本没出现过，概率就是 0；二是无法捕捉长距离依赖，比如“我出生在法国，所以我会说一口流利的____”，要填“法语”，需要看到很远的“法国”，N-gram 就无能为力了。

后来，神经网络语言模型出现了。它用词向量（Word Embedding）表示词，用神经网络（如 RNN、LSTM）来建模整个序列的概率。词向量让语义相近的词在向量空间里也相近，缓解了稀疏问题；RNN 理论上能记住任意长的历史，但实际中会有梯度消失，记不住太远的信息。

下面是一个用 Python 和 PyTorch 实现的最简单的 Bigram 神经网络语言模型，帮你直观感受一下“用神经网络预测下一个词”是怎么回事：

import torch
import torch.nn as nn
import torch.optim as optim

# 假设词表只有 5 个词，用整数表示
vocab_size = 5
embedding_dim = 3

# 一个简单的 Bigram 模型：输入当前词，预测下一个词
class BigramLM(nn.Module):
    def __init__(self):
        super().__init__()
        self.embedding = nn.Embedding(vocab_size, embedding_dim)
        self.linear = nn.Linear(embedding_dim, vocab_size)
    def forward(self, x):
        emb = self.embedding(x)  # (batch, embed_dim)
        logits = self.linear(emb)  # (batch, vocab_size)
        return logits

model = BigramLM()
criterion = nn.CrossEntropyLoss()
optimizer = optim.Adam(model.parameters(), lr=0.01)

# 训练数据：输入词 -> 下一个词
inputs = torch.tensor([0, 1, 2, 3])
targets = torch.tensor([1, 2, 3, 4])

for epoch in range(100):
    optimizer.zero_grad()
    logits = model(inputs)
    loss = criterion(logits, targets)
    loss.backward()
    optimizer.step()
    if (epoch+1) % 20 == 0:
        print(f'Epoch {epoch+1}, Loss: {loss.item():.4f}')

# 预测：输入词 0，看下一个词概率
with torch.no_grad():
    logits = model(torch.tensor([0]))
    probs = torch.softmax(logits, dim=-1)
    print('下一个词概率分布:', probs.numpy())

运行这段代码，你会看到损失逐渐下降，模型学会了根据当前词预测下一个词。虽然简单，但它已经包含了现代语言模型的基本思想：把词映射成向量，用神经网络学习概率分布。

1.2 LLM 的定义与特点：大规模、预训练、微调

大语言模型（Large Language Model, LLM）是神经网络语言模型的“超级进化版”。它的定义可以概括为：在海量文本上预训练、拥有超大规模参数（通常数十亿到数千亿）、能处理多种自然语言任务的神经网络模型。

LLM 有三个关键特点：

  • 大规模参数：参数越多，模型容量越大，越能记住复杂的语言模式和世界知识。比如 GPT-3 有 1750 亿参数，GPT-4 据传更大。
  • 预训练（Pre-training）：先在大规模无标注文本上训练一个通用模型。预训练任务通常是“预测下一个词”（自回归）或“完形填空”（掩码语言模型）。这一步让模型学到语法、语义和常识。
  • 微调（Fine-tuning）：预训练后，用少量标注数据在特定任务上继续训练，让模型适应具体场景，比如情感分类、问答系统。微调就像让一个通才变成专才。

为什么预训练+微调这么有效？因为预训练让模型学到了通用的语言表示，微调只需要调整一点点参数就能适配新任务，大大减少了对标注数据的依赖。这也是 LLM 能“一个模型打天下”的基础。

下面是一个用 Hugging Face Transformers 加载预训练模型并做简单微调（文本分类）的示例。注意：运行需要安装 transformers 和 datasets 库，并且需要下载模型，代码仅展示核心流程。

from transformers import AutoTokenizer, AutoModelForSequenceClassification, Trainer, TrainingArguments
from datasets import load_dataset

# 加载预训练模型和分词器（这里用一个小模型演示）
model_name = 'distilbert-base-uncased'
tokenizer = AutoTokenizer.from_pretrained(model_name)
model = AutoModelForSequenceClassification.from_pretrained(model_name, num_labels=2)

# 加载一个情感分类数据集
dataset = load_dataset('imdb', split='train[:100]')  # 只取100条演示

def tokenize(examples):
    return tokenizer(examples['text'], padding='max_length', truncation=True, max_length=128)

tokenized_dataset = dataset.map(tokenize, batched=True)

# 设置训练参数
training_args = TrainingArguments(
    output_dir='./results',
    num_train_epochs=1,
    per_device_train_batch_size=8,
    logging_steps=10,
)

trainer = Trainer(
    model=model,
    args=training_args,
    train_dataset=tokenized_dataset,
)

trainer.train()
print('微调完成！')

这段代码展示了微调的标准流程：加载预训练模型 → 准备数据 → 设置训练参数 → 训练。实际中，微调可能需要更多数据和计算资源，但核心思想不变。

1.3 LLM 的发展里程碑与核心能力

LLM 的发展有几个关键里程碑，了解它们能帮你读懂技术文档里的“行话”：

  • GPT 系列（Generative Pre-trained Transformer）：OpenAI 出品，采用自回归（Autoregressive）方式，即从左到右预测下一个词。GPT-1、GPT-2、GPT-3 逐步扩大规模，GPT-3 展示了强大的少样本学习能力。GPT-4 支持多模态。
  • BERT（Bidirectional Encoder Representations from Transformers）：Google 出品，采用双向编码器，通过掩码语言模型（Masked Language Model, MLM）预训练，即随机遮住一些词让模型猜。BERT 擅长理解任务，如分类、问答。
  • T5（Text-to-Text Transfer Transformer）：Google 出品，把所有任务都统一成“文本到文本”的格式，比如翻译是“翻译成英文: ...”，分类是“分类: ...”。这种统一框架影响深远。

这些模型都基于 Transformer 架构，核心是自注意力机制（Self-Attention），能并行处理序列并捕捉长距离依赖。

LLM 的核心能力可以归纳为四点：

  • 生成：根据输入生成连贯的文本，如写文章、写代码。
  • 理解：理解文本含义，如情感分析、实体识别。
  • 推理：进行逻辑推理，如数学题、常识推理。虽然 LLM 的推理能力有限，但已经能解决不少问题。
  • 上下文学习（In-context Learning）：这是 LLM 的“超能力”。不需要更新参数，只要在输入里给几个例子（Few-shot），模型就能学会新任务。比如给两个“英语→法语”的翻译例子，模型就能翻译新的英语句子。这大大降低了使用门槛。

下面是一个用 GPT-2 演示上下文学习的例子（需要 transformers 库）：

from transformers import pipeline

# 加载文本生成管道
generator = pipeline('text-generation', model='gpt2')

# 上下文学习：给两个例子，让模型续写第三个
prompt = """Translate English to French:
sea otter => loutre de mer
peppermint => menthe poivrée
cheese =>"""

# 生成结果
result = generator(prompt, max_length=50, num_return_sequences=1)
print(result[0]['generated_text'])

运行后，模型可能会输出“fromage”之类的词。虽然 GPT-2 能力有限，但已经展示了上下文学习的雏形。在 GPT-3 等更大模型上，这种能力会更强。

常见误区

  • 误区：LLM 只是“更大的 N-gram 模型”。实际上，LLM 基于神经网络和注意力机制，能捕捉长距离依赖和复杂语义，与 N-gram 有本质区别。
  • 误区：预训练和微调是一回事。预训练是在海量无标注数据上学习通用表示，微调是在特定任务上用小规模标注数据调整参数，两者目标和数据都不同。
  • 误区：上下文学习需要更新模型参数。上下文学习是在推理时通过输入中的示例让模型临时“学会”任务，不改变任何参数。

答案：统计语言模型（如 N-gram）基于马尔可夫假设，只依赖前 N-1 个词，存在数据稀疏和无法捕捉长距离依赖的问题；神经网络语言模型使用词向量和神经网络（如 RNN、Transformer）来建模序列概率，能缓解稀疏问题并捕捉更长距离的依赖。

答案：上下文学习是指 LLM 在不更新参数的情况下，仅通过输入中提供的少量示例（Few-shot）就能学会并执行新任务。优势是无需微调，使用灵活，大大降低了适配新任务的门槛。

本章目标：掌握LLM常见术语如Transformer、注意力机制等

Transformer 架构：自注意力、多头注意力与位置编码

Transformer 是几乎所有现代大语言模型（LLM）的骨架。它抛弃了循环神经网络（RNN）的时序递归，完全依赖注意力机制来捕捉序列中任意两个位置的关系。你可以把它想象成一个“全局信息路由器”：每个词都能直接看到句子里的其他所有词，并根据相关性分配注意力权重。

自注意力（Self-Attention）是核心。对于输入序列的每个词向量，我们生成三个向量：Query（查询）、Key（键）、Value（值）。计算时，用当前词的 Query 与所有词的 Key 做点积，得到注意力分数，再经过 Softmax 归一化，最后用这些权重对 Value 加权求和。公式为：Attention(Q, K, V) = softmax(QK^T / sqrt(d_k)) V。除以 sqrt(d_k) 是为了防止点积过大导致梯度消失。

多头注意力（Multi-Head Attention）则是把自注意力并行做多次（比如 8 个头），每个头学习不同的关注模式（如语法、语义、指代等），最后拼接并线性变换。这让模型能同时从多个“视角”理解句子。

由于自注意力本身不包含顺序信息，Transformer 引入了位置编码（Positional Encoding）。原始论文使用正弦和余弦函数生成固定编码，后来也常用可学习的位置嵌入。位置编码与词嵌入相加，让模型知道“谁在前、谁在后”。

下面是一个极简的自注意力实现，帮助你直观理解计算过程：

import torch
import torch.nn.functional as F

# 假设 batch=1, 序列长度=3, 维度=4
torch.manual_seed(0)
x = torch.randn(1, 3, 4)  # 输入序列
W_q = torch.nn.Linear(4, 4)
W_k = torch.nn.Linear(4, 4)
W_v = torch.nn.Linear(4, 4)

Q = W_q(x)  # (1, 3, 4)
K = W_k(x)
V = W_v(x)

scores = torch.matmul(Q, K.transpose(-2, -1)) / (4 ** 0.5)  # (1, 3, 3)
attn = F.softmax(scores, dim=-1)
out = torch.matmul(attn, V)  # (1, 3, 4)
print(out.shape)  # torch.Size([1, 3, 4])

记住：Transformer = 自注意力 + 多头 + 位置编码 + 前馈网络 + 残差连接 + 层归一化。这些组件堆叠起来，就构成了 GPT、BERT 等模型的基础。

Token 与 Tokenization：子词切分、BPE 与 WordPiece

LLM 不直接处理文字，而是处理 Token——可以理解为“词片”或“子词”。Tokenization 就是把原始文本切分成 Token 序列的过程。为什么不用整词？因为词汇表会爆炸，而且遇到未登录词（OOV）就束手无策。子词切分在“词”和“字符”之间取得平衡，既能控制词表大小，又能处理罕见词。

BPE（Byte Pair Encoding）是最常用的子词算法之一。它从字符开始，反复合并出现频率最高的相邻字符对，直到达到预设的词表大小。例如，“low”和“lower”可能被切分为 low 和 er。GPT 系列、RoBERTa 都使用 BPE 的变体。

WordPiece 是 BERT 使用的算法，与 BPE 类似，但合并时选择能最大化语言模型似然的字符对，而不是单纯看频率。它用 ## 前缀表示子词是词的延续，比如 playing 可能切成 play + ##ing。

Tokenization 直接影响模型的行为：同样的句子，不同 tokenizer 切出的 Token 数量不同，进而影响上下文长度、推理成本和生成质量。例如，中文通常一个汉字可能对应一个或多个 Token，而英文一个单词可能被切成多个子词。

下面用 Hugging Face 的 tokenizer 观察实际切分效果：

from transformers import AutoTokenizer

tokenizer = AutoTokenizer.from_pretrained("bert-base-uncased")
text = "Tokenization is fun!"
tokens = tokenizer.tokenize(text)
print(tokens)  # ['token', '##ization', 'is', 'fun', '!']
ids = tokenizer.convert_tokens_to_ids(tokens)
print(ids)

关键结论：Token 是模型处理文本的最小单位，Tokenization 策略决定了词表大小、序列长度和模型对罕见词的泛化能力。

嵌入与向量表示：词嵌入、位置嵌入与上下文嵌入

嵌入（Embedding）是把离散的 Token 映射到连续向量空间的技术。每个 Token 对应一个稠密向量，语义相近的词在向量空间中距离更近。比如“猫”和“狗”的向量会比“猫”和“汽车”更接近。

词嵌入（Word Embedding）是静态的，每个词只有一个向量，与上下文无关。Word2Vec、GloVe 是经典方法。但同一个词在不同句子中含义可能不同（如“苹果”指水果还是公司），静态嵌入无法区分。

位置嵌入（Position Embedding）为每个位置生成一个向量，加到词嵌入上，让 Transformer 感知顺序。它可以是固定的正弦函数，也可以是可学习的参数。

上下文嵌入（Contextual Embedding）则根据整个句子动态生成每个词的向量。BERT、GPT 等模型输出的就是上下文嵌入。同一个词在不同上下文中会有不同的向量表示，从而解决一词多义问题。

下面演示如何用 BERT 获取上下文嵌入：

from transformers import BertTokenizer, BertModel
import torch

tokenizer = BertTokenizer.from_pretrained("bert-base-uncased")
model = BertModel.from_pretrained("bert-base-uncased")

inputs = tokenizer("I love apples.", return_tensors="pt")
with torch.no_grad():
    outputs = model(**inputs)

last_hidden = outputs.last_hidden_state  # (1, seq_len, 768)
print(last_hidden.shape)

记住：词嵌入是静态的，上下文嵌入是动态的；位置嵌入负责注入顺序信息。三者共同构成了 LLM 的输入表示层。

训练与推理术语：批处理、学习率、温度与 Top-p 采样

训练和推理阶段有一堆术语，理解它们才能调参和读懂技术文档。

批处理（Batch Size）指一次前向/反向传播处理的样本数量。大批量训练更稳定、GPU 利用率高，但需要更多显存；小批量则噪声大，可能有助于泛化。

学习率（Learning Rate）控制参数更新的步长。太大容易震荡不收敛，太小则训练缓慢。常用预热（warmup）和衰减策略。

推理阶段，温度（Temperature）用于调整 Softmax 输出的概率分布。温度越低（如 0.1），分布越尖锐，模型更倾向于选择概率最高的词，输出更确定；温度越高（如 1.5），分布越平坦，输出更随机、有创意。公式为 softmax(logits / T)。

Top-p 采样（Nucleus Sampling）又称核采样。它从累积概率达到 p（如 0.9）的最小词集合中采样，动态截断尾部。相比 Top-k 固定截断，Top-p 能根据分布形状自适应，避免生成不连贯的文本。

下面用代码模拟温度与 Top-p 对采样分布的影响：

import torch
import torch.nn.functional as F

logits = torch.tensor([2.0, 1.0, 0.5, 0.1, -1.0])

def sample(logits, temperature=1.0, top_p=1.0):
    probs = F.softmax(logits / temperature, dim=-1)
    sorted_probs, sorted_idx = torch.sort(probs, descending=True)
    cumulative = torch.cumsum(sorted_probs, dim=-1)
    mask = cumulative > top_p
    mask[1:] = mask[:-1].clone()
    mask[0] = False
    sorted_probs[mask] = 0.0
    sorted_probs /= sorted_probs.sum()
    idx = torch.multinomial(sorted_probs, 1)
    return sorted_idx[idx].item()

print("T=0.5, top_p=0.9:", sample(logits, 0.5, 0.9))
print("T=1.5, top_p=0.9:", sample(logits, 1.5, 0.9))

总结：温度控制随机性，Top-p 控制候选集大小；两者常配合使用，例如 temperature=0.7, top_p=0.9。

常见误区

  • 自注意力机制中，每个词只关注相邻的词。实际上，自注意力允许每个词关注序列中的所有词，包括它自己。
  • Token 就是单词。实际上，一个单词可能被切分成多个 Token，一个 Token 也可能是一个子词或字符。
  • 温度越高，模型输出越准确。实际上，温度越高输出越随机、有创意，但可能不准确；温度越低输出越确定，但可能缺乏多样性。

自测

请解释 Transformer 中多头注意力的作用，以及为什么需要位置编码？

答案：多头注意力让模型并行地从多个子空间学习不同的注意力模式，从而捕捉更丰富的语义和语法关系。位置编码是因为自注意力本身对序列顺序不敏感，需要额外注入位置信息，让模型知道词的先后顺序。

温度（Temperature）和 Top-p 采样在文本生成中分别起什么作用？

答案：温度调整 Softmax 输出的概率分布：温度低使分布更尖锐，输出更确定；温度高使分布更平坦，输出更随机。Top-p 采样从累积概率达到 p 的最小词集合中采样，动态截断低概率词，避免生成不连贯内容。两者常结合使用以平衡确定性和多样性。

第3章 · 模型评测方法

本章目标：学会阅读和解读LLM模型评测报告与基准

常见评测基准：从GLUE到HELM

要读懂模型评测报告，首先得认识那些反复出现的基准名字。它们就像考试卷，不同试卷考的能力不一样。

  • GLUE（General Language Understanding Evaluation）：2018年推出的自然语言理解“高考”，包含9个任务，如情感分析、句子相似度、自然语言推理。它让不同模型有了统一比较标准。
  • SuperGLUE：GLUE的升级版，任务更难，人类基线更高，用来区分顶尖模型。
  • MMLU（Massive Multitask Language Understanding）：57个学科的选择题，从数学到法律，测的是模型的知识广度和推理能力，是当前大模型常报的指标。
  • HELM（Holistic Evaluation of Language Models）：不只测准确率，还测鲁棒性、公平性、效率等，强调全方位评估。

读报告时，先看它用了哪些基准。基准不同，分数不可直接比较。比如MMLU 80分和GLUE 80分，含义完全不同。

评测指标：准确率、困惑度、BLEU、ROUGE、F1

指标是分数的计算方式，理解它们才能知道分数代表什么。

  • 准确率（Accuracy）：分类任务中最直观，预测对的样本比例。但类别不平衡时会失真。
  • 困惑度（Perplexity）：语言模型常用，衡量模型对文本的“惊讶程度”。越低越好，表示模型越能预测下一个词。
  • BLEU：机器翻译常用，比较生成文本和参考文本的n-gram重叠，越高越好，但只关注精确率。
  • ROUGE：摘要任务常用，关注召回率，看参考文本中有多少被生成文本覆盖。
  • F1：精确率和召回率的调和平均，适合不平衡分类。

下面用Python快速算一下BLEU和困惑度，感受一下。

from nltk.translate.bleu_score import sentence_bleu
import math

# BLEU示例
reference = [['the', 'cat', 'is', 'on', 'the', 'mat']]
candidate = ['the', 'cat', 'is', 'on', 'the', 'mat']
print('BLEU:', sentence_bleu(reference, candidate))  # 完全匹配，接近1

# 困惑度示例：假设模型对4个词的概率
probs = [0.8, 0.6, 0.9, 0.7]
perplexity = math.exp(-sum(math.log(p) for p in probs) / len(probs))
print('Perplexity:', perplexity)  # 越低越好

注意：BLEU和ROUGE都是基于表面重叠，不理解语义，所以现在大模型评测更看重人工评估或更强指标。

评测方法：零样本、少样本、微调评测

同一个模型，用不同方式提问，分数可能差很多。评测方法决定了模型“开卷”程度。

  • 零样本（Zero-shot）：不给任何示例，直接问。考验模型的泛化能力。
  • 少样本（Few-shot）：在问题前给几个示例，让模型模仿。通常能提升分数，但示例选择会影响结果。
  • 微调评测（Fine-tuning）：用任务数据训练后再测。分数最高，但不再是“通用能力”的体现。

读报告时，一定要看它标注的是zero-shot还是few-shot。不同设定下的分数不能直接比。比如某模型MMLU 5-shot 85分，另一个0-shot 80分，不能简单说前者更强。

下面是一个模拟少样本提示的代码，展示如何构造示例。

def build_few_shot_prompt(question, examples):
    prompt = ''
    for ex in examples:
        prompt += f"Q: {ex['q']}\nA: {ex['a']}\n"
    prompt += f"Q: {question}\nA:"
    return prompt

examples = [
    {'q': '2+2=?', 'a': '4'},
    {'q': '3+5=?', 'a': '8'}
]
print(build_few_shot_prompt('7+1=?', examples))

评测报告解读：如何比较不同模型的性能

拿到一份评测报告，不要只看总分。按下面步骤拆解：

  1. 看基准和指标：是MMLU还是GLUE？是准确率还是F1？
  2. 看评测设定：zero-shot、few-shot还是微调？示例数量多少？
  3. 看数据版本：同一基准可能有不同版本，比如MMLU有原始版和精简版。
  4. 看对比对象：和谁比？是否同规模、同训练数据？
  5. 看细分任务：总分高不代表每个子任务都好，可能偏科。

结论：比较模型时，必须保证基准、指标、评测设定一致，否则分数没有可比性。报告里常说的“SOTA”也要看具体条件。

例如，某报告说模型A在MMLU上达到90%，但没说是5-shot还是0-shot，也没说是否用了外部工具，这种分数就要谨慎看待。

常见误区

  • 困惑度越低越好，但不同词表大小的模型困惑度不可直接比较。
  • BLEU分数高不代表翻译质量一定好，它只衡量n-gram重叠，忽略语义和流畅度。
  • 零样本分数低不代表模型差，可能只是不擅长该提示格式；少样本分数高也可能因为示例泄露了答案。

自测

MMLU和GLUE的主要区别是什么？

答案：MMLU是57个学科的选择题，侧重知识广度和推理；GLUE是9个自然语言理解任务，侧重句子级理解。两者基准不同，分数不可直接比较。

为什么说不同评测设定下的分数不能直接比较？

答案：因为零样本、少样本、微调评测给模型的信息量不同。少样本通常比零样本分数高，微调更高，所以必须看报告标注的设定是否一致。

第4章 · 硬件评测实战

本章目标：能看懂GPU等硬件评测指标并选型

关键硬件指标：算力、显存、带宽、功耗

选GPU就像选车，不能只看马力（算力），还要看油箱大小（显存）、输油管粗细（带宽）和油耗（功耗）。这一节我们把四个核心指标拆开讲清楚。

算力 (FLOPS)：每秒浮点运算次数，衡量GPU做数学计算的速度。常见单位有TFLOPS（万亿次/秒）和PFLOPS（千万亿次/秒）。注意：算力分精度，比如FP32、FP16、BF16、INT8。LLM训练和推理常用FP16/BF16，所以看算力时要确认精度。例如NVIDIA A100的FP16算力约312 TFLOPS（带稀疏），而FP32只有19.5 TFLOPS，差距巨大。

显存 (VRAM)：GPU自带的内存，用来放模型权重、激活值、优化器状态等。显存不够，模型根本跑不起来。粗略估算：推理时，FP16模型每1B参数约需2GB显存；训练时，因为要存优化器状态和梯度，每1B参数约需16-20GB。所以7B模型推理至少14GB显存，训练则要100GB以上。

内存带宽 (Memory Bandwidth)：GPU从显存读写数据的速度，单位GB/s。LLM推理是内存带宽瓶颈型任务：每生成一个token，都要把整个模型权重从显存读一遍。所以推理速度 ≈ 内存带宽 / 模型大小。例如A100带宽约2000GB/s，7B模型FP16约14GB，理论速度约143 token/s。

功耗 (TDP)：热设计功耗，单位瓦特。功耗决定散热和电费，也影响能否塞进机箱。数据中心GPU如H100功耗可达700W，消费级RTX 4090约450W。

下面用Python快速估算一个模型需要多少显存和理论推理速度：

def estimate_gpu_requirements(params_billion, precision_bytes=2, batch_size=1):
    """
    估算LLM推理的显存需求和理论速度
    params_billion: 模型参数量（十亿）
    precision_bytes: 每个参数的字节数，FP16=2, INT8=1, FP32=4
    """
    model_size_gb = params_billion * precision_bytes
    # 激活值等额外开销，粗略按20%算
    total_vram_gb = model_size_gb * 1.2
    print(f"模型大小: {model_size_gb:.1f} GB")
    print(f"建议显存: {total_vram_gb:.1f} GB")
    
    # 假设GPU内存带宽（GB/s），这里用A100的2000GB/s
    bandwidth = 2000
    tokens_per_sec = bandwidth / model_size_gb
    print(f"理论推理速度: {tokens_per_sec:.1f} token/s")

# 测试7B模型
estimate_gpu_requirements(7, precision_bytes=2)
# 输出：模型大小14.0GB，建议显存16.8GB，理论速度142.9 token/s

记住这个公式：推理速度 ≈ 内存带宽 / 模型大小。这就是为什么大模型推理慢——不是算力不够，是数据搬运太慢。

常见评测工具：MLPerf、DLBench、自定义基准

光看厂商给的峰值算力不靠谱，实际性能要看评测工具。这一节介绍三个层次的评测。

MLPerf：由MLCommons组织维护的行业标准基准，相当于AI硬件界的“奥运会”。它分训练（Training）和推理（Inference）两套，覆盖图像分类、目标检测、语言模型（BERT、GPT-3）等任务。MLPerf的结果可横向对比不同厂商的GPU、TPU、CPU。看MLPerf报告时注意：看场景（Scenario），比如Offline（离线批处理）、Server（在线服务）、SingleStream（单流低延迟），不同场景排名可能完全不同。

DLBench：国内一些机构推出的深度学习基准，更贴近中文场景和国产硬件。它通常包含ResNet、BERT等模型的训练和推理测试。相比MLPerf，DLBench的测试项更少，但部署更简单。

自定义基准：最实用的评测。因为你的模型、数据、框架和MLPerf不一定一样。自定义基准就是拿你自己的模型和真实数据，测延迟、吞吐、显存占用。关键指标：

  • 推理延迟 (Inference Latency)：从输入到输出的时间，单位ms。对在线服务至关重要。
  • 吞吐量 (Throughput)：每秒处理的请求数或token数。对离线批处理重要。
  • 首token延迟 (TTFT)：生成第一个token的时间，影响用户感知。

下面是一个自定义基准的简单示例，用PyTorch测推理延迟：

import torch
import time

# 假设有一个简单的模型
def create_model():
    return torch.nn.Sequential(
        torch.nn.Linear(768, 3072),
        torch.nn.ReLU(),
        torch.nn.Linear(3072, 768)
    )

model = create_model().cuda().half()  # 用FP16
input_tensor = torch.randn(1, 128, 768).cuda().half()

# 预热
for _ in range(10):
    _ = model(input_tensor)
torch.cuda.synchronize()

# 测延迟
latencies = []
for _ in range(100):
    start = time.perf_counter()
    _ = model(input_tensor)
    torch.cuda.synchronize()
    latencies.append(time.perf_counter() - start)

avg_latency = sum(latencies) / len(latencies) * 1000  # 转ms
print(f"平均延迟: {avg_latency:.2f} ms")
print(f"P99延迟: {sorted(latencies)[98]*1000:.2f} ms")

评测时一定要预热（warm-up），因为GPU首次运行会有初始化开销。另外要测P99延迟，而不只是平均延迟，因为用户体验由最慢的请求决定。

硬件与模型匹配：如何根据模型大小选择GPU

知道了指标和评测工具，现在来解决实际问题：给定一个模型，该选什么GPU？我们分推理和训练两种情况。

推理场景：主要看显存和带宽。步骤：

  1. 算模型大小：参数量 × 精度字节数。例如7B模型FP16约14GB，INT8约7GB。
  2. 加额外开销：激活值、KV Cache等。KV Cache随序列长度和batch size增长，长上下文时可能比模型还大。粗略加20%-50%。
  3. 选显存足够的GPU：7B FP16建议16GB以上，如RTX 4090（24GB）、A10（24GB）。13B FP16建议32GB以上，如A100 40GB。70B FP16需要140GB，单卡放不下，需多卡或量化。
  4. 看带宽：带宽越高，推理越快。同价位选带宽大的。

训练场景：显存需求暴增，因为要存优化器状态、梯度、激活值。粗略公式：训练显存 ≈ 参数量 × (2 + 2 + 4 + 4) 字节 = 参数量 × 12字节（FP16混合精度：权重2、梯度2、优化器动量4、方差4）。再加上激活值，实际约16-20字节/参数。所以7B模型训练需要约112-140GB显存，至少2张A100 80GB。全量微调13B模型需要8张A100 80GB是常见配置。

下面用Python写一个选型助手：

def recommend_gpu(params_billion, mode='inference', precision='fp16'):
    """
    根据模型大小推荐GPU配置
    mode: 'inference' 或 'training'
    precision: 'fp16', 'int8', 'fp32'
    """
    bytes_per_param = {'fp16': 2, 'int8': 1, 'fp32': 4}[precision]
    model_size = params_billion * bytes_per_param
    
    if mode == 'inference':
        vram_needed = model_size * 1.3  # 加30%开销
        print(f"推理模式：模型{model_size:.1f}GB，建议显存{vram_needed:.1f}GB")
        if vram_needed <= 24:
            print("推荐：RTX 4090 / A10 (24GB)")
        elif vram_needed <= 48:
            print("推荐：A6000 (48GB) / L40S (48GB)")
        elif vram_needed <= 80:
            print("推荐：A100 80GB / H100 80GB")
        else:
            print(f"需要多卡：至少{int(vram_needed//80)+1}张80GB GPU")
    else:
        # 训练：约16字节/参数（混合精度+激活值）
        vram_needed = params_billion * 16
        print(f"训练模式：建议显存{vram_needed:.1f}GB")
        num_gpus = int(vram_needed // 80) + 1
        print(f"推荐：{num_gpus}张A100 80GB或H100 80GB")

# 测试
recommend_gpu(7, 'inference', 'fp16')
recommend_gpu(7, 'training', 'fp16')
recommend_gpu(70, 'inference', 'int8')

关键结论：推理选显存够用且带宽高的；训练选显存大且支持多卡互联的（如NVLink）。不要用消费级显卡做多卡训练，因为PCIe带宽和NVLink差距巨大。

成本与性能权衡：云GPU vs 本地GPU

最后我们来算账。云GPU和本地GPU各有优劣，选择取决于使用频率、预算和隐私要求。

云GPU：按需付费，灵活。优点：无需前期投入，随时升级到最新硬件，适合短期项目、实验、突发流量。缺点：长期使用成本高，数据隐私风险，网络延迟。主流云GPU价格（2024年参考）：

GPU型号显存按需价格（美元/小时）适合场景
T416GB0.35-0.5轻量推理
A10G24GB1.0-1.5中等推理
A100 40GB40GB2.5-4.0训练/大模型推理
H100 80GB80GB8.0-12.0大模型训练

本地GPU：一次性购买，长期使用成本低。优点：数据安全，无网络延迟，可深度定制。缺点：前期投入大，硬件贬值快，维护麻烦。参考价格：RTX 4090约1600美元，A100 80GB约15000美元，H100约30000美元。

盈亏平衡点计算：假设云GPU每小时3美元，本地GPU购买价15000美元，电费和维护每月200美元。则回本时间 = 15000 / (3*24*30 - 200) ≈ 7.5个月。如果每天使用超过8小时，本地更划算；如果只是偶尔用，云更划算。

下面用Python算一下：

def cost_comparison(cloud_price_per_hour, local_gpu_price, local_power_cost_per_month, hours_per_day):
    """
    比较云GPU和本地GPU的月成本
    """
    cloud_monthly = cloud_price_per_hour * hours_per_day * 30
    local_monthly = local_power_cost_per_month
    # 本地GPU折旧，按3年直线折旧
    depreciation = local_gpu_price / 36
    local_total = local_monthly + depreciation
    
    print(f"每天使用{hours_per_day}小时：")
    print(f"云GPU月成本: ${cloud_monthly:.2f}")
    print(f"本地GPU月成本（含折旧）: ${local_total:.2f}")
    if cloud_monthly > local_total:
        print("结论：本地更划算")
    else:
        print("结论：云更划算")

# 测试不同使用时长
for hours in [2, 8, 24]:
    cost_comparison(3.0, 15000, 200, hours)
    print()

混合策略：很多团队采用“本地推理+云训练”或“云突发+本地常驻”的混合模式。例如，用本地RTX 4090做日常推理，需要训练时租用云A100集群。这样兼顾成本和灵活性。

最终建议：初学者先用云GPU（如Colab、AutoDL）练手；团队有稳定需求且预算充足时，考虑本地GPU；对数据隐私要求高的场景，必须本地部署。

常见误区

  • 算力（FLOPS）越高，LLM推理越快。实际上LLM推理是内存带宽瓶颈，带宽比算力更重要。
  • 显存只要装下模型权重就够了。实际上KV Cache、激活值、框架开销都会占用显存，通常需要额外20%-50%的余量。
  • 云GPU一定比本地GPU便宜。长期高负载使用时，本地GPU的折旧后成本可能更低，需要根据使用时长计算盈亏平衡点。

自测

一个13B参数的模型，使用FP16精度进行推理，至少需要多少显存？如果GPU内存带宽是1000GB/s，理论推理速度是多少token/s？

答案：模型大小 = 13B × 2字节 = 26GB。加上约30%开销，建议显存至少34GB。理论推理速度 = 带宽 / 模型大小 = 1000GB/s / 26GB ≈ 38.5 token/s。

MLPerf推理基准中的Offline和Server场景有什么区别？分别适合评估什么类型的应用？

答案：Offline场景模拟离线批处理，所有数据一次性可用，追求最大吞吐量，适合评估批量推理任务。Server场景模拟在线服务，请求按泊松分布到达，有延迟约束，适合评估在线推理服务的延迟和吞吐平衡。

模型量化与剪枝：减少显存占用与加速推理

大模型动辄几十 GB 显存，普通显卡跑不动。量化与剪枝是两大压缩技术。

量化 (Quantization)：把模型权重从高精度（如 FP32）转换为低精度（如 INT8、INT4）。精度越低，显存占用越小，推理越快，但可能损失一点准确率。常见方法有训练后量化（PTQ）和量化感知训练（QAT）。Hugging Face 的 bitsandbytes 库支持 8-bit 和 4-bit 量化，一行代码就能加载。

剪枝 (Pruning)：移除模型中不重要的权重（置零或删除），减少计算量。分为非结构化剪枝（单个权重）和结构化剪枝（整个神经元/注意力头）。剪枝后通常需要微调恢复性能。

最小示例：使用 4-bit 量化加载模型。

from transformers import AutoModelForCausalLM, AutoTokenizer
import torch

model_name = "meta-llama/Llama-2-7b-chat-hf"  # 需申请权限，可换成其他小模型如 "gpt2"
tokenizer = AutoTokenizer.from_pretrained(model_name)
model = AutoModelForCausalLM.from_pretrained(
    model_name,
    load_in_4bit=True,                # 4-bit 量化
    device_map="auto",                # 自动分配设备
    torch_dtype=torch.float16
)
print(model.device)  # 查看模型所在设备

注意：量化需要安装 bitsandbytes：pip install bitsandbytes。量化后显存占用可减少 50%~75%。

推理优化：批处理、KV缓存、Flash Attention

部署时不仅要跑起来，还要跑得快。三个关键优化技术：

批处理 (Batching)：一次处理多个输入，提高 GPU 利用率。但要注意序列长度对齐，避免 padding 浪费。动态批处理（如 vLLM 的 continuous batching）能进一步提升吞吐。

KV缓存 (KV Cache)：自回归生成时，每次预测新 token 都要重新计算之前所有 token 的 Key/Value 矩阵。KV 缓存把这些中间结果存下来，避免重复计算。没有 KV 缓存，生成速度会慢几倍。但缓存会占用显存，需权衡。

Flash Attention：一种注意力计算优化算法，通过分块计算和重计算，减少显存访问，提升速度。PyTorch 2.0+ 已内置支持，只需在加载模型时设置 attn_implementation="flash_attention_2"（需安装 flash-attn）。

示例：启用 Flash Attention 并生成文本。

from transformers import AutoModelForCausalLM, AutoTokenizer
import torch

model_name = "gpt2"  # 小模型演示，实际可用 Llama 等
tokenizer = AutoTokenizer.from_pretrained(model_name)
model = AutoModelForCausalLM.from_pretrained(
    model_name,
    torch_dtype=torch.float16,
    attn_implementation="flash_attention_2"  # 启用 Flash Attention
).to("cuda")

input_text = "The future of AI is"
inputs = tokenizer(input_text, return_tensors="pt").to("cuda")

# 生成时使用 KV 缓存（默认开启）
outputs = model.generate(**inputs, max_new_tokens=50, use_cache=True)
print(tokenizer.decode(outputs[0], skip_special_tokens=True))

如果 flash_attention_2 报错，可先安装：pip install flash-attn --no-build-isolation。注意：Flash Attention 需要 Ampere 架构以上 GPU（如 RTX 30 系、A100）。

实战：使用 Hugging Face 部署一个 LLM 并评测

现在我们把前面知识串起来，部署一个 LLM 并做简单评测。

步骤：1. 加载模型和分词器；2. 编写推理函数；3. 用几个 prompt 测试生成质量；4. 测量推理速度（吞吐量、延迟）。

完整代码示例（使用 gpt2 避免权限问题，可替换为其他模型）：

from transformers import AutoModelForCausalLM, AutoTokenizer
import torch
import time

model_name = "gpt2"
tokenizer = AutoTokenizer.from_pretrained(model_name)
model = AutoModelForCausalLM.from_pretrained(
    model_name,
    torch_dtype=torch.float16,
    device_map="auto"
)

def generate(prompt, max_new_tokens=50):
    inputs = tokenizer(prompt, return_tensors="pt").to(model.device)
    start = time.time()
    outputs = model.generate(
        **inputs,
        max_new_tokens=max_new_tokens,
        do_sample=True,
        temperature=0.7,
        use_cache=True  # 启用 KV 缓存
    )
    end = time.time()
    text = tokenizer.decode(outputs[0], skip_special_tokens=True)
    return text, end - start

# 测试多个 prompt
prompts = [
    "The capital of France is",
    "Explain quantum computing in simple terms:",
    "Write a short poem about AI:"
]

for p in prompts:
    output, latency = generate(p)
    print(f"Prompt: {p}")
    print(f"Output: {output}")
    print(f"Latency: {latency:.2f}s\n")

评测指标：延迟 (Latency) 指生成一个回复的时间；吞吐量 (Throughput) 指每秒生成的 token 数。你可以调整 max_new_tokens 观察变化。如果显存不足，尝试量化或换更小模型。

进阶：使用 text-generation-inference 或 vLLM 部署为 API 服务，支持高并发。

常见误区

  • 量化一定会显著降低模型准确率——实际上，4-bit 量化对大多数任务影响很小，甚至可忽略。
  • KV 缓存会一直占用显存，无法释放——可以通过设置 use_cache=False 关闭，或使用分页注意力（如 vLLM）动态管理。
  • Flash Attention 在所有 GPU 上都可用——它需要 Ampere 架构以上（如 RTX 30 系、A100），旧卡不支持。

自测

KV 缓存的作用是什么？为什么它能加速推理？

答案：KV 缓存存储了自回归生成过程中之前 token 的 Key 和 Value 矩阵，避免每次生成新 token 时重新计算所有历史 token 的注意力，从而大幅减少计算量，加速推理。

模型量化有哪些常见精度？各有什么优缺点？

答案：常见精度有 FP32（全精度，显存大，速度慢）、FP16/BF16（半精度，平衡）、INT8（8位整数，显存减半，速度提升，精度略降）、INT4（4位整数，显存减至1/4，速度更快，精度损失稍大）。选择取决于硬件和任务对精度的要求。
