数据准备与预处理

本章目标：掌握构建高质量训练数据集的方法

数据采集明确来源，收集原始样本→数据清洗去噪去重，修正错误值→特征工程提取转换，构造有效特征→数据划分分训练验证测试集→质量校验评估分布，反馈迭代
从原始数据到高质量训练集的闭环流程，校验结果反哺前序环节。

数据收集：来源与版权考量

训练一个LLM，第一步不是写模型代码，而是找数据。可以把数据比作模型的“食物”：食材不新鲜，再好的厨师也做不出好菜。数据质量直接决定模型的上限，而数据来源的合法性则决定模型能否被安全地使用和发布。常见的数据来源包括公开网页（如Common Crawl）、书籍、学术论文、代码仓库、对话数据等。但收集数据时，版权和合规性是必须优先考虑的问题，而不是事后补救的环节。

你需要关注四个维度：许可证决定数据能否商用，例如CC-BY-NC禁止商用，而MIT、Apache 2.0则相对宽松；隐私要求识别并脱敏个人身份信息（PII），如姓名、电话、地址；偏见与毒性要求过滤歧视性言论；来源可信度要求排除内容农场等低质量网站。一个具体的对比是：同样10GB网页文本，来自维基百科的部分通常可直接使用，而来自未知论坛的部分可能需要过滤掉30%以上的噪声和违规内容（比例因语料而异，待核实）。

实际操作中，可以优先使用已清洗的开源数据集（如The Pile、C4、Wikipedia），或使用爬虫时遵守robots.txt并记录来源。下面是一个从Hugging Face Datasets加载公开数据集的最小示例，输入是数据集名称和配置，预期输出是一条文本样本：

python
from datasets import load_dataset

# 加载wikitext-2数据集作为示例
dataset = load_dataset('wikitext', 'wikitext-2-raw-v1', split='train')
print(dataset[0])
# 输出: {'text': '\n = Valkyria Chronicles III = \n'}

记住：数据收集不是越多越好，而是越相关、越干净越好。在训练前，务必确认数据集的许可证和隐私政策，并保留来源记录，以便后续审计。

数据清洗：去重、过滤与格式化

原始数据往往包含重复、噪声、格式混乱等问题。可以把清洗想象成淘金：矿石（原始网页）里大部分是沙子，你要筛掉沙子、留下金粒。清洗的目标是得到干净、一致、高质量的文本。主要步骤包括去重、过滤和格式化。去重删除完全重复或近似重复的文档，因为重复数据会导致模型过拟合、降低泛化能力；常用方法有精确哈希（MD5）、SimHash、MinHash。过滤移除低质量内容，如过短文本、乱码、HTML标签、广告等，可以基于规则（长度、特殊字符比例）或模型（质量分类器）。格式化则统一文本格式，如去除多余空格、换行，标准化Unicode字符。

为什么去重如此关键？假设一个数据集有100万条样本，其中20%是重复的，那么模型在这20%上会反复学习相同模式，相当于变相增加了这些样本的权重，而其他80%的多样性被稀释。一个直观的前后对比是：清洗前样本可能包含大量空行和短碎片，清洗后每条样本都是完整段落，训练时的有效token比例显著提升。

下面是一个简单的清洗示例，使用Python进行去重和过滤。输入是wikitext数据集，预期输出是原始样本数与清洗后样本数的对比：

python
import hashlib
from datasets import load_dataset

def clean_text(text):
    # 去除首尾空白，替换多个空格为单个
    text = ' '.join(text.split())
    return text

def is_quality(text, min_len=50):
    # 过滤过短文本
    return len(text) >= min_len

dataset = load_dataset('wikitext', 'wikitext-2-raw-v1', split='train')
seen_hashes = set()
cleaned = []
for example in dataset:
    text = clean_text(example['text'])
    if not is_quality(text):
        continue
    # 精确去重
    h = hashlib.md5(text.encode()).hexdigest()
    if h in seen_hashes:
        continue
    seen_hashes.add(h)
    cleaned.append(text)

print(f'原始样本数: {len(dataset)}, 清洗后: {len(cleaned)}')

去重和过滤是数据清洗的核心，能显著提升训练效率和模型质量。对于大规模数据，可以使用Spark或Dask进行分布式处理，但清洗规则的设计仍需人工审核，避免误删有价值的长尾内容。

分词器原理与训练

分词器（Tokenizer）负责将文本转换为模型可处理的数字序列（token IDs）。可以把分词器想象成模型的“字典”：字典的收词方式决定了模型阅读文本的颗粒度。分词器的选择直接影响模型效果和推理速度。主流的分词算法有BPE（Byte Pair Encoding）、WordPiece和SentencePiece。以BPE为例，它从字符开始，反复合并出现频率最高的相邻字符对，直到达到预设的词表大小。这样既能处理未登录词，又能控制词表规模。

词表大小是一个需要权衡的超参数。词表过小，很多词被拆成多个子词，序列变长，计算负担增加；词表过大，嵌入矩阵变大，低频词训练不充分。例如，词表从500扩大到50000，嵌入矩阵参数量会成比例增长，而低频词的更新次数可能只有个位数。训练一个分词器通常使用Hugging Face的tokenizers库。下面是一个训练BPE分词器的最小示例，输入是清洗后的文本列表，预期输出是编码后的token列表和ID列表：

python
from tokenizers import Tokenizer
from tokenizers.models import BPE
from tokenizers.trainers import BpeTrainer
from tokenizers.pre_tokenizers import Whitespace

# 初始化BPE分词器
tokenizer = Tokenizer(BPE(unk_token='[UNK]'))
tokenizer.pre_tokenizer = Whitespace()

# 训练器：词表大小1000，特殊token
trainer = BpeTrainer(special_tokens=['[UNK]', '[CLS]', '[SEP]', '[PAD]', '[MASK]'], vocab_size=1000)

# 使用清洗后的文本训练
tokenizer.train_from_iterator(cleaned, trainer=trainer)

# 测试编码
output = tokenizer.encode('Hello, world!')
print(output.tokens)  # ['Hello', ',', 'world', '!']
print(output.ids)     # [123, 45, 678, 90]

训练完成后，保存分词器供后续使用：tokenizer.save('tokenizer.json')。分词器必须与模型训练时使用的保持一致，否则会导致性能下降。一个常见的错误是训练时用BPE、推理时换用WordPiece，结果同一个词被切成完全不同的ID序列，模型无法理解。

数据集划分与批处理

在训练前，需要将数据集划分为训练集、验证集和测试集。通常比例为80/10/10或90/5/5。验证集用于调参和早停，测试集用于最终评估。划分时要确保数据分布一致，避免泄漏。可以把测试集想象成考场的密封试卷：如果你提前偷看并据此调整答案，最终成绩就失去了客观性。同理，测试集一旦参与调参，模型评估结果就会偏乐观。

批处理（Batching）是将数据分成小批次输入模型，以提高训练效率和内存利用率。对于变长文本，需要填充（padding）到相同长度，或使用动态批处理（按长度分组）。动态批处理能减少填充，提升训练速度。例如，一个批次中文本长度从10到128不等，若统一填充到128，有效token比例可能只有40%；按长度分组后，有效token比例可提升到80%以上（具体数值取决于数据分布，待核实）。

使用Hugging Face Datasets的map和DataLoader可以方便地实现。下面示例的输入是清洗后的文本列表，预期输出是各数据集大小和一个批次的input_ids形状：

python
from datasets import Dataset
from transformers import DataCollatorWithPadding
from torch.utils.data import DataLoader

# 假设cleaned是清洗后的文本列表
dataset = Dataset.from_dict({'text': cleaned})

# 划分数据集
train_test = dataset.train_test_split(test_size=0.2, seed=42)
train_val = train_test['train'].train_test_split(test_size=0.1, seed=42)
train_dataset = train_val['train']
val_dataset = train_val['test']
test_dataset = train_test['test']

# 使用分词器编码
def tokenize_function(examples):
    return tokenizer(examples['text'], truncation=True, padding=False, max_length=128)

train_dataset = train_dataset.map(tokenize_function, batched=True)
val_dataset = val_dataset.map(tokenize_function, batched=True)

# 动态填充的collator
data_collator = DataCollatorWithPadding(tokenizer=tokenizer)

# 创建DataLoader
train_loader = DataLoader(train_dataset, batch_size=8, shuffle=True, collate_fn=data_collator)

# 查看一个批次
batch = next(iter(train_loader))
print(batch['input_ids'].shape)  # torch.Size([8, 128])

动态批处理能减少填充，提升训练速度。对于大规模数据，可以使用IterableDataset流式加载，避免内存不足。但流式加载时要注意shuffle的实现方式，否则可能破坏数据随机性。

常见误区

  • 错误理解：数据越多越好，只要堆量模型就会变强。→ 后果：低质量或重复数据会稀释有效信号，导致模型过拟合、泛化能力下降，同时浪费计算资源。→ 正确做法：先清洗、去重、过滤，再评估数据质量，清洗和去重比单纯增加数据量更重要。
  • 错误理解：分词器可以随意选择，反正都是把文本转成数字。→ 后果：分词器与模型预训练时使用的不一致，token分布不匹配，模型效果大幅下降，甚至无法正常推理。→ 正确做法：分词器必须与模型训练时使用的保持一致，并在训练前验证编码结果。
  • 错误理解：验证集和测试集可以混用，反正都是评估。→ 后果：测试集参与调参会导致过拟合，最终评估结果偏乐观，失去客观性。→ 正确做法：验证集用于调参和早停，测试集只在最终评估时使用一次。

自测

为什么数据去重对LLM训练很重要？请结合训练过程说明。

答案：推理过程：训练时模型按批次采样数据，如果同一文档重复出现，模型会在不同批次中反复看到相同样本，相当于变相增加了这些样本的权重。这会导致模型过度拟合重复内容，降低对未见数据的泛化能力，同时浪费计算资源。去重后数据多样性提升，每个样本的贡献更均衡，训练效率和模型质量都会改善。

训练分词器时，词表大小（vocab_size）设置过小或过大分别有什么问题？

答案：推理过程：词表过小，很多词无法作为整体token，会被拆分成多个子词，序列变长，增加计算负担，同时长距离依赖更难学习；词表过大，嵌入矩阵参数量成比例增长，模型复杂度增加，且低频词在训练中更新次数少，可能训练不充分。因此需要根据任务和语料规模权衡，常见做法是在验证集上比较不同词表大小对序列长度和模型效果的影响。

数据集划分时，为什么测试集不能用于调参？如果用了会有什么后果？

答案：推理过程：测试集的目的是模拟模型在未见数据上的表现，提供无偏的最终评估。如果根据测试集结果调整超参数，模型就会间接“看到”测试集信息，相当于提前偷看试卷并据此修改答案。后果是评估结果偏乐观，无法反映真实泛化能力。正确做法是使用验证集调参，测试集只在最终评估时使用一次。

python
import hashlib
from datasets import load_dataset, Dataset
from tokenizers import Tokenizer
from tokenizers.models import BPE
from tokenizers.trainers import BpeTrainer
from tokenizers.pre_tokenizers import Whitespace
from transformers import DataCollatorWithPadding
from torch.utils.data import DataLoader

# 1. 加载数据
dataset = load_dataset('wikitext', 'wikitext-2-raw-v1', split='train')

# 2. 清洗与去重
cleaned = []
seen = set()
for example in dataset:
    text = ' '.join(example['text'].split())
    if len(text) < 50:
        continue
    h = hashlib.md5(text.encode()).hexdigest()
    if h in seen:
        continue
    seen.add(h)
    cleaned.append(text)

print(f'清洗后样本数: {len(cleaned)}')

# 3. 划分数据集
dataset = Dataset.from_dict({'text': cleaned})
train_test = dataset.train_test_split(test_size=0.2, seed=42)
train_val = train_test['train'].train_test_split(test_size=0.125, seed=42)  # 0.125*0.8=0.1
train_dataset = train_val['train']
val_dataset = train_val['test']
test_dataset = train_test['test']
print(f'训练集: {len(train_dataset)}, 验证集: {len(val_dataset)}, 测试集: {len(test_dataset)}')

# 4. 训练分词器
tokenizer = Tokenizer(BPE(unk_token='[UNK]'))
tokenizer.pre_tokenizer = Whitespace()
trainer = BpeTrainer(special_tokens=['[UNK]', '[CLS]', '[SEP]', '[PAD]', '[MASK]'], vocab_size=500)
tokenizer.train_from_iterator(cleaned, trainer=trainer)

# 5. 编码与DataLoader
def tokenize_function(examples):
    return tokenizer(examples['text'], truncation=True, padding=False, max_length=128)

train_dataset = train_dataset.map(tokenize_function, batched=True)
val_dataset = val_dataset.map(tokenize_function, batched=True)
test_dataset = test_dataset.map(tokenize_function, batched=True)

data_collator = DataCollatorWithPadding(tokenizer=tokenizer)
train_loader = DataLoader(train_dataset, batch_size=4, shuffle=True, collate_fn=data_collator)

batch = next(iter(train_loader))
print(batch['input_ids'].shape)  # 例如 torch.Size([4, 128])
