预训练与分布式训练

本章目标：理解预训练目标、分布式训练策略与优化技巧

预训练目标：自回归语言建模

预训练是LLM获得通用语言能力的基石，而自回归语言建模（Autoregressive Language Modeling）是其中最主流的目标。它的核心思想很简单：给定前文，预测下一个token。形式化地，对于序列 \(x_1, x_2, ..., x_T\)，模型最大化对数似然：

\[\sum_{t=1}^{T} \log P(x_t | x_1, ..., x_{t-1}; \theta)\]

训练时，我们通常使用教师强制（teacher forcing）：将真实的前缀作为输入，并行计算所有位置的预测，并与真实的下一个token计算交叉熵损失。这样，一次前向传播就能得到所有位置的损失，效率很高。

下面是一个最小示例，展示如何用PyTorch实现自回归语言建模的损失计算：

import torch
import torch.nn as nn

# 假设词表大小为1000，批次大小2，序列长度5
vocab_size = 1000
batch_size = 2
seq_len = 5

# 模拟模型输出logits: (batch, seq_len, vocab_size)
logits = torch.randn(batch_size, seq_len, vocab_size)
# 真实标签: (batch, seq_len)
targets = torch.randint(0, vocab_size, (batch_size, seq_len))

# 自回归语言建模损失：预测下一个token
# 将logits和targets展平，计算交叉熵
loss_fn = nn.CrossEntropyLoss()
loss = loss_fn(logits.view(-1, vocab_size), targets.view(-1))
print(f"Loss: {loss.item():.4f}")

# 注意：实际中，模型输出logits[:, :-1]对应targets[:, 1:]
# 这里简化演示，假设已经对齐

关键点：自回归建模天然适合生成任务，但训练时每个位置只能看到左侧上下文，因此需要因果掩码（causal mask）防止信息泄露。此外，这种目标也常用于零样本和少样本学习。

分布式训练：数据并行、模型并行与流水线并行

当模型参数量达到数十亿甚至千亿时，单卡显存无法容纳，训练时间也难以接受。分布式训练成为必选项。主要策略有三类：

  • 数据并行（Data Parallelism）：每张卡持有完整的模型副本，但处理不同的数据批次。梯度通过AllReduce同步。适合模型能单卡放下，但数据量大的场景。PyTorch的DistributedDataParallel（DDP）是标准实现。
  • 模型并行（Model Parallelism）：将模型的不同层或同一层的不同部分拆分到不同设备。例如，将Transformer的注意力头拆分到多卡（张量并行）。适合单层参数过大，单卡放不下的情况。
  • 流水线并行（Pipeline Parallelism）：将模型按层切分成多个阶段，每个阶段放在不同设备上，数据像流水线一样依次通过。为了减少气泡，通常采用微批次（micro-batch）和调度策略（如GPipe、PipeDream）。

实际训练中，常结合多种并行策略，如3D并行（数据+模型+流水线）。下面是一个使用PyTorch DDP的简单示例：

import torch
import torch.distributed as dist
import torch.nn as nn
import torch.optim as optim
from torch.nn.parallel import DistributedDataParallel as DDP

def setup(rank, world_size):
    dist.init_process_group("gloo", rank=rank, world_size=world_size)

def cleanup():
    dist.destroy_process_group()

def train(rank, world_size):
    setup(rank, world_size)
    model = nn.Linear(10, 10).to(rank)
    ddp_model = DDP(model, device_ids=[rank])
    loss_fn = nn.MSELoss()
    optimizer = optim.SGD(ddp_model.parameters(), lr=0.001)
    
    # 模拟数据
    inputs = torch.randn(20, 10).to(rank)
    outputs = torch.randn(20, 10).to(rank)
    
    optimizer.zero_grad()
    preds = ddp_model(inputs)
    loss = loss_fn(preds, outputs)
    loss.backward()
    optimizer.step()
    print(f"Rank {rank}, Loss: {loss.item()}")
    cleanup()

# 启动方式：torchrun --nproc_per_node=2 script.py
# 每个进程调用train(rank, world_size)

关键点：数据并行通信开销大，模型并行和流水线并行则更复杂但能突破单卡显存限制。选择策略需权衡模型大小、集群网络和开发成本。

混合精度训练与梯度累积

混合精度训练（Mixed Precision Training）通过结合FP16和FP32来加速训练并减少显存占用。核心思想：前向和反向传播使用FP16计算，但保留一份FP32的模型权重副本用于更新，避免舍入误差累积。同时，使用损失缩放（loss scaling）防止梯度下溢。

PyTorch提供了torch.cuda.amp自动混合精度：

import torch
from torch.cuda.amp import autocast, GradScaler

model = torch.nn.Linear(10, 10).cuda()
optimizer = torch.optim.SGD(model.parameters(), lr=0.001)
scaler = GradScaler()

for data, target in dataloader:
    optimizer.zero_grad()
    with autocast():
        output = model(data)
        loss = loss_fn(output, target)
    scaler.scale(loss).backward()
    scaler.step(optimizer)
    scaler.update()

梯度累积（Gradient Accumulation）是另一种节省显存的技巧：当显存不足以容纳大batch时，可以多次前向/反向传播，累积梯度，再一次性更新。这等价于增大batch size，但不会增加显存峰值。

accumulation_steps = 4
optimizer.zero_grad()
for i, (data, target) in enumerate(dataloader):
    output = model(data)
    loss = loss_fn(output, target) / accumulation_steps
    loss.backward()
    if (i+1) % accumulation_steps == 0:
        optimizer.step()
        optimizer.zero_grad()

关键点：混合精度和梯度累积常结合使用，能显著降低显存需求，但需注意数值稳定性（如梯度裁剪）和超参数调整。

训练稳定性：学习率调度与梯度裁剪

大模型训练容易不稳定，表现为损失尖峰或发散。两个关键技巧是学习率调度和梯度裁剪。

学习率调度：常用预热（warmup）和余弦衰减。预热让学习率从0线性增加到峰值，避免早期梯度噪声导致的不稳定；随后余弦衰减到接近0，帮助模型收敛到更平坦的极小值。

from torch.optim.lr_scheduler import LambdaLR
import math

def lr_lambda(step):
    warmup_steps = 1000
    total_steps = 10000
    if step < warmup_steps:
        return step / warmup_steps
    else:
        progress = (step - warmup_steps) / (total_steps - warmup_steps)
        return 0.5 * (1 + math.cos(math.pi * progress))

scheduler = LambdaLR(optimizer, lr_lambda)

梯度裁剪：将梯度向量的范数限制在一个阈值内，防止梯度爆炸。通常按全局范数裁剪：

torch.nn.utils.clip_grad_norm_(model.parameters(), max_norm=1.0)

关键点：预热步数通常为总步数的1%-10%，梯度裁剪阈值常设为1.0。这些技巧能显著提升训练稳定性，尤其对于大模型。

常见误区

  • 自回归语言建模训练时，每个位置可以同时看到左右上下文，因此不需要因果掩码。
  • 数据并行中，每张卡持有模型的一部分，因此可以训练任意大的模型。
  • 混合精度训练会降低模型精度，因此不能用于最终部署。

自测

自回归语言建模中，为什么需要因果掩码（causal mask）？

答案：因果掩码确保模型在预测第t个token时只能看到前t-1个token，防止信息泄露，使训练目标与生成时的自回归特性一致。

数据并行和模型并行的主要区别是什么？各自适用什么场景？

答案：数据并行中每张卡有完整模型副本，处理不同数据批次，通过AllReduce同步梯度，适合模型能单卡放下但数据量大的场景；模型并行将模型拆分到不同设备，适合单卡显存不足以容纳整个模型的情况。

参考方案：

import torch import torch.nn as nn import torch.optim as optim from torch.cuda.amp import autocast, GradScaler from torch.optim.lr_scheduler import LambdaLR import math # 超参数 vocab_size = 1000 embed_dim = 128 hidden_dim = 256 batch_size = 32 seq_len = 20 accum_steps = 4 num_epochs = 2 # 模型 class LSTMModel(nn.Module): def __init__(self): super().__init__() self.embed = nn.Embedding(vocab_size, embed_dim) self.lstm = nn.LSTM(embed_dim, hidden_dim, num_layers=2, batch_first=True) self.fc = nn.Linear(hidden_dim, vocab_size) def forward(self, x): x = self.embed(x) out, _ = self.lstm(x) return self.fc(out) model = LSTMModel().cuda() optimizer = optim.Adam(model.parameters(), lr=1e-3) scaler = GradScaler() # 学习率调度：预热+余弦衰减 def lr_lambda(step): warmup_steps = 100 total_steps = 1000 if step < warmup_steps: return step / warmup_steps progress = (step - warmup_steps) / (total_steps - warmup_steps) return 0.5 * (1 + math.cos(math.pi * progress)) scheduler = LambdaLR(optimizer, lr_lambda) # 模拟数据 data = torch.randint(0, vocab_size, (batch_size, seq_len)).cuda() targets = torch.randint(0, vocab_size, (batch_size, seq_len)).cuda() # 训练循环 model.train() for epoch in range(num_epochs): optimizer.zero_grad() for i in range(0, batch_size, accum_steps): # 取微批次 input_batch = data[i:i+accum_steps] target_batch = targets[i:i+accum_steps] with autocast(): output = model(input_batch) loss = nn.CrossEntropyLoss()(output.view(-1, vocab_size), target_batch.view(-1)) loss = loss / accum_steps scaler.scale(loss).backward() if (i // accum_steps + 1) % accum_steps == 0: scaler.unscale_(optimizer) torch.nn.utils.clip_grad_norm_(model.parameters(), max_norm=1.0) scaler.step(optimizer) scaler.update() optimizer.zero_grad() scheduler.step() print(f"Epoch {epoch}, Loss: {loss.item() * accum_steps:.4f}")
