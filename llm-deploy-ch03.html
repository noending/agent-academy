预训练与分布式训练

本章目标：理解预训练目标、分布式训练策略与优化技巧

预训练目标定任务：预测下一词或掩码→数据与并行切分数据与模型到多卡→分布式策略数据/张量/流水并行组合→优化技巧混合精度、梯度累积、通信优化→稳定训练监控损失与吞吐，反馈调参
从预训练目标出发，经并行切分与优化技巧，形成可稳定扩展的训练闭环。

预训练目标：自回归语言建模

想象你在教一个孩子读书：你指着句子“今天天气真___”，让他猜下一个字。孩子会先看前面的“今天天气真”，再结合经验猜“好”或“热”。自回归语言建模就是让模型做同样的事——给定前文，预测下一个token。这个看似简单的任务，迫使模型学会语法、事实、推理甚至代码逻辑，因为要准确预测下一个词，它必须“理解”上下文。

形式化地，对于序列 \(x_1, x_2, ..., x_T\)，模型最大化对数似然：\[\sum_{t=1}^{T} \log P(x_t | x_1, ..., x_{t-1}; \theta)\]。训练时使用教师强制（teacher forcing）：把真实的前缀作为输入，并行计算所有位置的预测，再与真实的下一个token计算交叉熵损失。例如序列长度为5，模型一次前向就得到5个位置的预测，分别对应第2到第6个token（若输入是前5个）。这样一次前向传播就能得到所有位置的损失，效率远高于逐词生成。

下面是一个最小可运行示例，展示如何用PyTorch实现自回归语言建模的损失计算。输入是随机logits和随机标签，预期输出是一个约等于 \(\ln(1000) \approx 6.9\) 的损失值（因为随机猜测1000个词）：

python
import torch
import torch.nn as nn

# 假设词表大小为1000，批次大小2，序列长度5
vocab_size = 1000
batch_size = 2
seq_len = 5

# 模拟模型输出logits: (batch, seq_len, vocab_size)
logits = torch.randn(batch_size, seq_len, vocab_size)
# 真实标签: (batch, seq_len)
targets = torch.randint(0, vocab_size, (batch_size, seq_len))

# 自回归语言建模损失：预测下一个token
# 将logits和targets展平，计算交叉熵
loss_fn = nn.CrossEntropyLoss()
loss = loss_fn(logits.view(-1, vocab_size), targets.view(-1))
print(f"Loss: {loss.item():.4f}")  # 预期约6.9

# 注意：实际中，模型输出logits[:, :-1]对应targets[:, 1:]
# 这里简化演示，假设已经对齐

关键点：自回归建模天然适合生成任务，但训练时每个位置只能看到左侧上下文，因此需要因果掩码（causal mask）防止信息泄露。如果没有掩码，模型在预测第t个token时会“偷看”到第t个token本身，训练损失会异常低（例如接近0），但生成时性能崩溃。此外，这种目标也常用于零样本和少样本学习。

分布式训练：数据并行、模型并行与流水线并行

当模型参数量达到数十亿甚至千亿时，单卡显存无法容纳，训练时间也难以接受。分布式训练成为必选项。你可以把训练想象成搬砖：数据并行是“多请几个工人，每人搬不同的砖，但都拿着同一张图纸”；模型并行是“把一栋楼分成几段，每个工人只负责一段”；流水线并行则是“把搬砖流程分成几道工序，工人像流水线一样接力”。

具体来说：数据并行（Data Parallelism）中每张卡持有完整的模型副本，但处理不同的数据批次，梯度通过AllReduce同步。适合模型能单卡放下、但数据量大的场景，PyTorch的DistributedDataParallel（DDP）是标准实现。模型并行（Model Parallelism）将模型的不同层或同一层的不同部分拆分到不同设备，例如将Transformer的注意力头拆分到多卡（张量并行），适合单层参数过大、单卡放不下的情况。流水线并行（Pipeline Parallelism）将模型按层切分成多个阶段，每个阶段放在不同设备上，数据像流水线一样依次通过；为了减少气泡，通常采用微批次（micro-batch）和调度策略（如GPipe、PipeDream）。实际训练中常结合多种并行策略，如3D并行（数据+模型+流水线）。

下面是一个使用PyTorch DDP的简单示例。启动方式为 torchrun --nproc_per_node=2 script.py，每个进程调用 train(rank, world_size)，预期输出两行不同rank的损失值：

python
import torch
import torch.distributed as dist
import torch.nn as nn
import torch.optim as optim
from torch.nn.parallel import DistributedDataParallel as DDP

def setup(rank, world_size):
    dist.init_process_group("gloo", rank=rank, world_size=world_size)

def cleanup():
    dist.destroy_process_group()

def train(rank, world_size):
    setup(rank, world_size)
    model = nn.Linear(10, 10).to(rank)
    ddp_model = DDP(model, device_ids=[rank])
    loss_fn = nn.MSELoss()
    optimizer = optim.SGD(ddp_model.parameters(), lr=0.001)
    
    # 模拟数据
    inputs = torch.randn(20, 10).to(rank)
    outputs = torch.randn(20, 10).to(rank)
    
    optimizer.zero_grad()
    preds = ddp_model(inputs)
    loss = loss_fn(preds, outputs)
    loss.backward()
    optimizer.step()
    print(f"Rank {rank}, Loss: {loss.item()}")
    cleanup()

# 启动方式：torchrun --nproc_per_node=2 script.py
# 每个进程调用train(rank, world_size)

关键点：数据并行通信开销大（每步都要AllReduce梯度），模型并行和流水线并行则更复杂但能突破单卡显存限制。选择策略需权衡模型大小、集群网络和开发成本。例如，一个70B参数模型通常需要张量并行（8卡）+流水线并行（多机）+数据并行（多副本）的组合。

混合精度训练与梯度累积

混合精度训练就像用“草稿纸”和“正式账本”记账：草稿纸（FP16）写得快、占地方小，但容易算错小数；正式账本（FP32）精确但慢。核心思想是：前向和反向传播使用FP16计算，但保留一份FP32的模型权重副本用于更新，避免舍入误差累积。同时，使用损失缩放（loss scaling）防止梯度下溢——把损失放大 \(2^{16}\) 倍再反向传播，让微小梯度落在FP16可表示范围内，更新前再缩回去。

PyTorch提供了torch.cuda.amp自动混合精度。下面示例中，模型和优化器初始化后，每个批次在autocast下前向，用scaler缩放损失并反向，最后scaler.step和update完成更新。预期输出是正常的损失值，且显存占用比纯FP32降低约30%-50%（待核实具体比例，取决于模型）。

python
import torch
from torch.cuda.amp import autocast, GradScaler

model = torch.nn.Linear(10, 10).cuda()
optimizer = torch.optim.SGD(model.parameters(), lr=0.001)
scaler = GradScaler()

for data, target in dataloader:
    optimizer.zero_grad()
    with autocast():
        output = model(data)
        loss = loss_fn(output, target)
    scaler.scale(loss).backward()
    scaler.step(optimizer)
    scaler.update()

梯度累积（Gradient Accumulation）是另一种节省显存的技巧：当显存不足以容纳大batch时，可以多次前向/反向传播，累积梯度，再一次性更新。这等价于增大batch size，但不会增加显存峰值。例如，目标batch size为32，但单卡只能放8，就累积4步。注意损失要除以累积步数，保证梯度尺度正确。

python
accumulation_steps = 4
optimizer.zero_grad()
for i, (data, target) in enumerate(dataloader):
    output = model(data)
    loss = loss_fn(output, target) / accumulation_steps
    loss.backward()
    if (i+1) % accumulation_steps == 0:
        optimizer.step()
        optimizer.zero_grad()

关键点：混合精度和梯度累积常结合使用，能显著降低显存需求，但需注意数值稳定性（如梯度裁剪）和超参数调整。例如，使用混合精度时，梯度裁剪前需要先调用 scaler.unscale_(optimizer) 把梯度还原到真实尺度，否则裁剪阈值会失效。

训练稳定性：学习率调度与梯度裁剪

大模型训练就像在暴风雨中开船：学习率太大，船会翻（损失尖峰或发散）；学习率太小，船走不动（收敛慢）。两个关键技巧是学习率调度和梯度裁剪。学习率调度常用预热（warmup）和余弦衰减：预热让学习率从0线性增加到峰值，避免早期梯度噪声导致的不稳定；随后余弦衰减到接近0，帮助模型收敛到更平坦的极小值。例如，总步数10000，预热1000步，前1000步学习率从0升到峰值，后9000步按余弦曲线下降。

下面是一个可运行的学习率调度示例，使用LambdaLR。预期输出是前几步学习率逐渐增大，之后逐渐减小：

python
from torch.optim.lr_scheduler import LambdaLR
import math

def lr_lambda(step):
    warmup_steps = 1000
    total_steps = 10000
    if step < warmup_steps:
        return step / warmup_steps
    else:
        progress = (step - warmup_steps) / (total_steps - warmup_steps)
        return 0.5 * (1 + math.cos(math.pi * progress))

scheduler = LambdaLR(optimizer, lr_lambda)

梯度裁剪则是给梯度向量“限速”：将梯度向量的范数限制在一个阈值内，防止梯度爆炸。通常按全局范数裁剪，阈值常设为1.0。例如，某步梯度范数为10.0，裁剪后变为1.0，方向不变。这能显著提升训练稳定性，尤其对于大模型。

python
torch.nn.utils.clip_grad_norm_(model.parameters(), max_norm=1.0)

关键点：预热步数通常为总步数的1%-10%，梯度裁剪阈值常设为1.0。这些技巧能显著提升训练稳定性，尤其对于大模型。但注意，梯度裁剪应在优化器step之前、梯度计算之后调用；若使用混合精度，需先unscale梯度。

常见误区

  • 错误理解：自回归语言建模训练时，每个位置可以同时看到左右上下文，因此不需要因果掩码。→ 会导致什么后果：模型在训练时“偷看”到未来token，训练损失异常低（例如接近0），但生成时无法获得未来信息，性能崩溃。→ 正确做法：在注意力计算中加入因果掩码，确保第t个位置只能关注前t-1个位置，使训练目标与生成时的自回归特性一致。
  • 错误理解：数据并行中，每张卡持有模型的一部分，因此可以训练任意大的模型。→ 会导致什么后果：误以为数据并行能解决显存不足，实际每张卡仍需完整模型副本，模型稍大就会OOM。→ 正确做法：数据并行要求模型能单卡放下；若单卡放不下，需结合模型并行或流水线并行，将模型拆分到多卡。
  • 错误理解：混合精度训练会降低模型精度，因此不能用于最终部署。→ 会导致什么后果：放弃使用混合精度，训练变慢、显存占用高，或者错误地认为部署也必须用FP32。→ 正确做法：混合精度训练保留FP32主权重，精度损失通常很小；部署时可根据硬件选择FP16/BF16或FP32，需通过评估验证精度。

自测

自回归语言建模中，为什么需要因果掩码（causal mask）？请结合训练和生成两个阶段说明。

答案：训练时，模型并行计算所有位置的预测，如果不加掩码，第t个位置会通过注意力看到第t个及之后的token，相当于直接看到答案，损失会异常低但学不到真实规律。生成时，模型只能基于已生成的左侧上下文逐词预测，无法获得未来token。因果掩码确保训练时每个位置只能关注前t-1个位置，使训练目标与生成时的自回归特性一致，避免信息泄露。

数据并行和模型并行的主要区别是什么？各自适用什么场景？

答案：数据并行中每张卡持有完整模型副本，处理不同数据批次，通过AllReduce同步梯度，适合模型能单卡放下但数据量大的场景；模型并行将模型拆分到不同设备，适合单卡显存不足以容纳整个模型的情况。数据并行通信开销主要在梯度同步，模型并行则涉及层间或张量间的通信，实现更复杂。

混合精度训练中，为什么需要损失缩放（loss scaling）？如果不做会怎样？

答案：FP16的表示范围有限，梯度值很小时容易下溢为0，导致参数无法更新。损失缩放将损失放大（如乘以 \(2^{16}\)），使梯度也相应放大，落在FP16可表示范围内；更新前再缩回去。如果不做损失缩放，小梯度会丢失，训练可能停滞或收敛变差。

练习 · 使用PyTorch实现一个简单的自回归语言模型训练循环，包含混合精度训练和梯度累积。要求：模型为一个两层LSTM，词表大…

任务：使用PyTorch实现一个简单的自回归语言模型训练循环，包含混合精度训练和梯度累积。要求：模型为一个两层LSTM，词表大小1000，嵌入维度128，隐藏层维度256。使用随机生成的数据模拟训练，批次大小32，序列长度20，梯度累积步数4，使用Adam优化器和余弦学习率调度（带预热）。

参考方案：

python
import torch
import torch.nn as nn
import torch.optim as optim
from torch.cuda.amp import autocast, GradScaler
from torch.optim.lr_scheduler import LambdaLR
import math

# 超参数
vocab_size = 1000
embed_dim = 128
hidden_dim = 256
batch_size = 32
seq_len = 20
accum_steps = 4
num_epochs = 2

# 模型
class LSTMModel(nn.Module):
    def __init__(self):
        super().__init__()
        self.embed = nn.Embedding(vocab_size, embed_dim)
        self.lstm = nn.LSTM(embed_dim, hidden_dim, num_layers=2, batch_first=True)
        self.fc = nn.Linear(hidden_dim, vocab_size)
    def forward(self, x):
        x = self.embed(x)
        out, _ = self.lstm(x)
        return self.fc(out)

model = LSTMModel().cuda()
optimizer = optim.Adam(model.parameters(), lr=1e-3)
scaler = GradScaler()

# 学习率调度：预热+余弦衰减
def lr_lambda(step):
    warmup_steps = 100
    total_steps = 1000
    if step < warmup_steps:
        return step / warmup_steps
    progress = (step - warmup_steps) / (total_steps - warmup_steps)
    return 0.5 * (1 + math.cos(math.pi * progress))
scheduler = LambdaLR(optimizer, lr_lambda)

# 模拟数据
data = torch.randint(0, vocab_size, (batch_size, seq_len)).cuda()
targets = torch.randint(0, vocab_size, (batch_size, seq_len)).cuda()

# 训练循环
model.train()
for epoch in range(num_epochs):
    optimizer.zero_grad()
    for i in range(0, batch_size, accum_steps):
        # 取微批次
        input_batch = data[i:i+accum_steps]
        target_batch = targets[i:i+accum_steps]
        with autocast():
            output = model(input_batch)
            loss = nn.CrossEntropyLoss()(output.view(-1, vocab_size), target_batch.view(-1))
            loss = loss / accum_steps
        scaler.scale(loss).backward()
        if (i // accum_steps + 1) % accum_steps == 0:
            scaler.unscale_(optimizer)
            torch.nn.utils.clip_grad_norm_(model.parameters(), max_norm=1.0)
            scaler.step(optimizer)
            scaler.update()
            optimizer.zero_grad()
            scheduler.step()
    print(f"Epoch {epoch}, Loss: {loss.item() * accum_steps:.4f}")
