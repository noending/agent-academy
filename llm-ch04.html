微调与对齐

本章目标：使用微调技术适配下游任务

预训练模型通用能力底座，尚未适配任务→微调适配用下游数据调整参数→对齐调优让输出符合人类偏好→评估反馈检验效果并回补数据
从通用底座出发，经微调与对齐落地到下游任务，再用评估反馈闭环。

4.1 全参数微调 vs 参数高效微调：为什么需要 LoRA？

想象你有一本写满通用知识的百科全书，现在要让它专门回答你公司内部的产品问题。最彻底的办法是把整本书重写一遍——这就是全参数微调（Full Fine-tuning）：拿预训练权重，在下游数据上继续用较小的学习率训练所有参数。效果通常最好，但代价也最大。以一个 7B 模型为例，参数本身用 fp16 存储约 14GB，训练时还要保存梯度（约 14GB）和 Adam 优化器状态（通常约为参数量的 2 倍，即约 28GB），再加上激活值，显存轻松超过 80GB。而且每个下游任务都要存一份完整权重，10 个任务就是 10 份 14GB 的副本，管理和部署都极其笨重。

更聪明的办法是给百科全书贴便签：书本身不动，只在旁边加一小叠注释。这就是参数高效微调（PEFT），代表方法是 LoRA（Low-Rank Adaptation）。它的核心思想是：冻结原模型权重，只在旁边插入一小对低秩矩阵，训练时只更新这对小矩阵。对于原权重 W ∈ R^{d×k}，LoRA 不直接改 W，而是学习一个增量 ΔW = B·A，其中 A ∈ R^{r×k}，B ∈ R^{d×r}，秩 r 远小于 d、k。前向计算变为：

python
h = Wx + (alpha / r) * B(Ax)

这里 alpha / r 是缩放系数，用来控制增量相对于原权重的幅度。初始化时 A 用高斯随机，B 全零，所以训练开始时 ΔW=0，模型行为与原始模型完全一致，不会一上来就破坏预训练知识。训练完只需要保存 A 和 B：一个 7B 模型若 r=8、只加在注意力层，LoRA 权重可能只有几十 MB，而全量权重是 14GB 量级，相差两三个数量级。

下面是一个用 HuggingFace PEFT 库给模型加 LoRA 的最小可运行示例。输入是一个已加载的因果语言模型，输出是可训练参数统计：

python
from transformers import AutoModelForCausalLM
from peft import LoraConfig, get_peft_model

model = AutoModelForCausalLM.from_pretrained("gpt2")

lora_config = LoraConfig(
    r=8,                      # 低秩维度
    lora_alpha=16,            # 缩放系数
    target_modules=["c_attn"], # 对哪些层加 LoRA
    lora_dropout=0.05,
    bias="none",
    task_type="CAUSAL_LM"
)

model = get_peft_model(model, lora_config)
model.print_trainable_parameters()
# 输出类似: trainable params: 294,912 || all params: 124,734,720 || trainable%: 0.24%

运行后你会看到可训练参数只有 0.24% 左右。LoRA 用极小的训练成本，换来了接近全量微调的效果，这就是它成为当前微调事实标准的原因。当然，LoRA 并非万能：当任务与预训练分布差异极大、或需要注入大量新知识时，全参数微调仍可能更优；但在绝大多数下游适配场景中，LoRA 的性价比难以撼动。

4.2 QLoRA：把大模型塞进单卡

LoRA 已经省了很多，但基座模型本身还是要占显存。一个 7B 模型用 fp16 加载就要约 14GB，加上训练时的激活值和临时缓冲，单张 24GB 卡仍然紧张。这就像你虽然只带了一小叠便签，但那本百科全书本身还是得搬进房间——房间不够大就进不去。于是 QLoRA（Quantized LoRA） 登场了：它先把百科全书压缩成缩印本再搬进来。

QLoRA 做了三件事：4-bit 量化基座模型，用 NF4（Normal Float 4）这种对正态分布权重信息论上较优的 4-bit 数据类型加载原模型，显存直接降到约 1/4；双重量化，对量化常数再量化一次，进一步省显存；分页优化器，借助 NVIDIA 统一内存，在显存尖峰时把部分状态换出，避免 OOM。关键点在于：基座是 4-bit 冻结的，只有 LoRA 适配器用 bf16 训练。所以梯度精度不受量化影响，效果几乎不掉——便签上的字仍然是高清的，只是书本身变成了缩印版。

用 bitsandbytes + PEFT 实现 QLoRA 的最小代码如下。输入是模型名和量化配置，输出是可训练参数统计：

python
import torch
from transformers import AutoModelForCausalLM, BitsAndBytesConfig
from peft import LoraConfig, get_peft_model

bnb_config = BitsAndBytesConfig(
    load_in_4bit=True,
    bnb_4bit_quant_type="nf4",
    bnb_4bit_compute_dtype=torch.bfloat16,
    bnb_4bit_use_double_quant=True,
)

model = AutoModelForCausalLM.from_pretrained(
    "meta-llama/Llama-2-7b-hf",
    quantization_config=bnb_config,
    device_map="auto",
)

lora_config = LoraConfig(
    r=16, lora_alpha=32,
    target_modules=["q_proj", "v_proj"],
    lora_dropout=0.05, bias="none", task_type="CAUSAL_LM"
)
model = get_peft_model(model, lora_config)
model.print_trainable_parameters()

这样一张 24GB 的 4090 就能微调 7B 模型，更大模型在 48GB 卡上也有机会跑起来（具体上限取决于序列长度和 batch size，待核实）。QLoRA 让“个人开发者微调大模型”从不可能变成了日常。实践建议：r 一般取 8~64，任务越复杂取越大；target_modules 至少覆盖 q_proj 和 v_proj，追求效果可以加上 k_proj、o_proj 和 MLP 层。注意量化会带来少量精度损失，若任务对数值极其敏感，应做 A/B 对比再决定。

4.3 指令微调与 RLHF：让模型“听懂人话”

光会续写的模型不是好助手。你给它“把下面句子翻译成英文”，它可能接着续写出更多中文句子，因为它只学过“预测下一个词”，没学过“执行指令”。要让它遵循指令，需要指令微调（Instruction Tuning）：用大量“指令-回答”对训练，让模型学会看到指令就给出对应回答。格式通常长这样：

python
### Instruction:
把下面的句子翻译成英文。
### Input:
今天天气很好。
### Response:
The weather is nice today.

指令微调让模型学会“看到指令就执行”，这是 ChatGPT 类模型对齐的第一阶段，通常称为 SFT（监督微调）。但 SFT 只告诉模型“什么是好回答”，没告诉它“两个回答哪个更好”。第二阶段是 RLHF（Reinforcement Learning from Human Feedback，基于人类反馈的强化学习），经典三步：监督微调（SFT）用高质量示范数据打底；训练奖励模型（RM）让人类对同一问题的多个回答排序，训练一个模型去预测“人类更喜欢哪个回答”；PPO 强化学习用奖励模型当裁判，让语言模型生成更受偏好的回答，同时加 KL 惩罚防止跑偏。类比来说，SFT 是老师示范标准答案，RLHF 是请一位评委给学生的多种解法打分，再让学生朝着高分方向练习。

RLHF 效果很好但工程复杂、不稳定，PPO 调参 notoriously 困难。现在更流行 DPO（Direct Preference Optimization）：跳过奖励模型和 PPO，直接用偏好数据对优化策略，简单又稳定。很多开源模型（如 Zephyr、Llama-3-Instruct）都用 DPO 或类似方法（具体配方待核实）。一个用 TRL 做 DPO 的极简片段如下，输入是含 prompt/chosen/rejected 的偏好数据集，输出是训练好的模型：

python
from trl import DPOTrainer, DPOConfig

config = DPOConfig(
    beta=0.1,               # KL 约束强度
    learning_rate=5e-5,
    per_device_train_batch_size=2,
    num_train_epochs=1,
)

trainer = DPOTrainer(
    model=model,
    ref_model=None,         # 用 PEFT 时可传 None
    args=config,
    train_dataset=preference_dataset,  # 含 prompt/chosen/rejected
    tokenizer=tokenizer,
)
trainer.train()

一句话总结：SFT 教模型“怎么做”，RLHF/DPO 教模型“做什么更好”。实际项目中，通常先做 SFT 把格式和基本能力教会，再用 DPO 做偏好对齐；跳过 SFT 直接 DPO 往往效果不佳。

4.4 如何评估微调效果？

训练完不是结束，评估才是决定能不能上线的关键。这就像学生考完试不能只看他作业写完了没有，还要看考试成绩、会不会偏科、答题格式规不规范。微调评估分三个层次：任务指标，分类任务看准确率/F1，生成任务看 ROUGE、BLEU、BERTScore，代码任务看 pass@k；通用能力，用 MMLU、GSM8K 等基准检查是否“灾难性遗忘”——微调后模型变笨了没有；人工/模型评估，用 GPT-4 或人工对回答打分，看有用性、安全性、格式遵循度。

一个常见的坑：只看训练 loss 下降就以为成功了。实际上小数据集上 loss 很快降到接近 0，但模型可能只是背下了答案，泛化很差。比如你只有 100 条翻译数据，训练 loss 从 2.0 降到 0.1，但换一句没见过的中文，模型可能输出乱码。所以必须留出验证集，并做基线对比。推荐做法：留出验证集，训练时监控验证 loss；用 lm-evaluation-harness 跑标准基准，对比微调前后；准备 20~50 条真实业务问题，人工盲评；检查输出格式是否稳定，比如 JSON 是否总能解析。

下面用 lm-eval 跑一个基准的例子。输入是合并后的模型路径和任务列表，输出是各任务得分：

python
# 命令行方式
# lm_eval --model hf \
#   --model_args pretrained=./my-lora-merged \
#   --tasks mmlu,gsm8k \
#   --batch_size 8

# Python 方式
import lm_eval
results = lm_eval.simple_evaluate(
    model="hf",
    model_args="pretrained=./my-lora-merged",
    tasks=["mmlu", "gsm8k"],
    batch_size=8,
)
print(results["results"])

记住：没有评估的微调等于赌博。每次微调都要有基线对比，才能知道改动到底有没有用。评估集要尽量贴近真实使用分布，否则分数再高也可能上线翻车。

常见误区

  • 错误理解：LoRA 只能加在注意力层。→ 后果：target_modules 只写 q_proj/v_proj，在需要较强适配的任务上效果受限，误以为 LoRA 本身不行。→ 正确做法：LoRA 也可以加到 MLP、输出投影等模块，target_modules 的选择会显著影响效果，应结合任务做消融对比。
  • 错误理解：QLoRA 的 4-bit 量化会严重损失效果。→ 后果：不敢用 QLoRA，白白放弃单卡微调大模型的机会，或用了之后过度怀疑结果。→ 正确做法：NF4 + 双重量化在多数任务上损失很小，因为 LoRA 适配器仍以 bf16 训练；但仍应在自己的任务上做量化前后 A/B 对比，敏感任务谨慎使用。
  • 错误理解：RLHF 一定比 DPO 好。→ 后果：盲目上 PPO 导致训练不稳定、调参成本高、项目延期。→ 正确做法：DPO 在很多场景下效果相当甚至更稳定，且实现简单得多，是当前主流选择；应先跑通 SFT + DPO 基线，确有需要再考虑 RLHF。

自测

LoRA 为什么能大幅减少可训练参数量？它的前向计算是如何进行的？请结合维度说明参数量对比。

答案：推理过程：原权重 W 是 d×k，全量微调要训练 d×k 个参数。LoRA 冻结 W，只训练 A（r×k）和 B（d×r），参数量为 r×(d+k)。因为 r 远小于 d、k，所以参数量大幅下降。例如 d=k=4096、r=8 时，全量是约 1678 万，LoRA 是 8×(4096+4096)=65536，约为原来的 0.39%。前向为 h = Wx + (alpha/r)·B(Ax)，训练开始时 B 为零，增量 ΔW=0，不破坏原模型。

QLoRA 相比 LoRA 多了哪些关键技术？为什么它能在单卡上微调 7B 模型？

答案：推理过程：LoRA 只减少了可训练参数，但基座模型仍以 fp16 占约 14GB（7B 模型）。QLoRA 在此基础上增加：4-bit NF4 量化基座，使基座显存降到约 1/4；双重量化，对量化常数再量化，进一步省显存；分页优化器，避免显存尖峰 OOM。同时 LoRA 适配器仍用 bf16 训练，保证梯度精度。因此 24GB 单卡即可容纳 7B 基座加训练开销，实现单卡微调。

微调后训练 loss 降到接近 0，是否说明模型效果好？应该怎样评估？

答案：推理过程：训练 loss 低只说明模型拟合了训练集，小数据集上很容易背下答案，泛化可能很差。正确评估应分三层：任务指标（准确率/F1/ROUGE/pass@k）、通用能力基准（MMLU、GSM8K 检查灾难性遗忘）、人工或模型盲评（有用性、安全性、格式遵循）。同时要留验证集监控验证 loss，并与微调前基线对比，检查输出格式稳定性。只看训练 loss 等于赌博。

动手练习（带参考方案）

练习 · 使用 HuggingFace 生态，对一个开源小模型（如 gpt2 或 TinyLlama）进行 LoRA 微调，完成一…

任务：使用 HuggingFace 生态，对一个开源小模型（如 gpt2 或 TinyLlama）进行 LoRA 微调，完成一个简单的指令跟随任务（例如：给定中文句子，输出英文翻译）。要求：1) 构造至少 50 条指令-回答数据；2) 配置 LoRA 并训练；3) 保存适配器；4) 加载适配器进行推理，对比微调前后的输出。验收标准：微调后模型在训练集内指令上能输出英文翻译，且适配器文件成功保存到本地目录。

参考方案：

python
import torch
from datasets import Dataset
from transformers import AutoTokenizer, AutoModelForCausalLM, TrainingArguments, Trainer
from peft import LoraConfig, get_peft_model, PeftModel

# 1. 构造数据（示例 3 条，实际需至少 50 条）
data = [
    {"instruction": "把下面的句子翻译成英文。", "input": "今天天气很好。", "output": "The weather is nice today."},
    {"instruction": "把下面的句子翻译成英文。", "input": "我喜欢吃苹果。", "output": "I like eating apples."},
    {"instruction": "把下面的句子翻译成英文。", "input": "他正在读书。", "output": "He is reading a book."},
    # ... 至少 50 条
]

def format_example(ex):
    return {"text": f"### Instruction:\n{ex['instruction']}\n### Input:\n{ex['input']}\n### Response:\n{ex['output']}"}

dataset = Dataset.from_list(data).map(format_example)

# 2. 加载模型和 tokenizer
tokenizer = AutoTokenizer.from_pretrained("gpt2")
tokenizer.pad_token = tokenizer.eos_token
model = AutoModelForCausalLM.from_pretrained("gpt2")

# 3. 配置 LoRA
lora_config = LoraConfig(
    r=8, lora_alpha=16,
    target_modules=["c_attn"],
    lora_dropout=0.05, bias="none", task_type="CAUSAL_LM"
)
model = get_peft_model(model, lora_config)
model.print_trainable_parameters()

# 4. tokenize
def tokenize(ex):
    out = tokenizer(ex["text"], truncation=True, padding="max_length", max_length=128)
    out["labels"] = out["input_ids"].copy()
    return out

tokenized = dataset.map(tokenize, remove_columns=dataset.column_names)

# 5. 训练
training_args = TrainingArguments(
    output_dir="./lora-out",
    per_device_train_batch_size=2,
    num_train_epochs=5,
    learning_rate=2e-4,
    logging_steps=10,
    save_strategy="epoch",
    report_to="none",
)

trainer = Trainer(
    model=model,
    args=training_args,
    train_dataset=tokenized,
)
trainer.train()

# 6. 保存适配器
model.save_pretrained("./lora-adapter")

# 7. 推理对比
prompt = "### Instruction:\n把下面的句子翻译成英文。\n### Input:\n今天天气很好。\n### Response:\n"

# 微调前
base = AutoModelForCausalLM.from_pretrained("gpt2")
inputs = tokenizer(prompt, return_tensors="pt")
print("微调前:", tokenizer.decode(base.generate(**inputs, max_new_tokens=30)[0], skip_special_tokens=True))

# 微调后
peft_model = PeftModel.from_pretrained(base, "./lora-adapter")
print("微调后:", tokenizer.decode(peft_model.generate(**inputs, max_new_tokens=30)[0], skip_special_tokens=True))
