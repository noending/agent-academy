训练环境搭建：GPU与分布式

把训练大模型想象成盖一栋摩天大楼：单张GPU就像一台小型搅拌机，能处理小工程，但面对千亿参数的大楼，它很快就会“转不动”。这时我们需要多台搅拌机（多卡）甚至多个工地（多机）协同工作，这就是分布式训练的直觉来源。核心矛盾在于：单卡显存有限（例如24GB的RTX 4090），而一个7B参数的模型仅权重就需要约14GB（FP16），加上梯度、优化器状态和激活值，很容易爆显存。因此，环境搭建的第一步是确认硬件能力。

在代码层面，先用PyTorch检查GPU是否可用、数量与型号。下面这段代码是任何训练脚本的“体检”步骤，预期输出类似True、4、NVIDIA A100-SXM4-40GB。如果is_available()返回False，说明驱动或CUDA安装有问题，后续训练无从谈起。

python
import torch
print(torch.cuda.is_available())          # 预期输出: True
print(torch.cuda.device_count())          # 预期输出: 4（假设有4张卡）
print(torch.cuda.get_device_name(0))      # 预期输出: NVIDIA A100-SXM4-40GB

确认硬件后，分布式训练最常用的是数据并行（Data Parallelism）：每张GPU持有一份完整的模型副本，各自处理不同的数据批次，然后通过通信同步梯度。PyTorch的DistributedDataParallel（DDP）是官方推荐实现。启动时用torchrun指定每台机器的进程数，例如单机4卡：

python
# 命令行启动示例：单机4卡
torchrun --nproc_per_node=4 train.py

在train.py内部，需要初始化进程组、绑定当前进程到对应GPU，并用DDP包装模型。注意LOCAL_RANK由torchrun自动注入，代表当前进程在本机上的GPU编号。下面是最小初始化骨架：

python
import os
import torch
import torch.distributed as dist

dist.init_process_group(backend='nccl')          # NCCL是NVIDIA GPU间通信后端
local_rank = int(os.environ['LOCAL_RANK'])
torch.cuda.set_device(local_rank)
model = torch.nn.parallel.DistributedDataParallel(model, device_ids=[local_rank])

关键结论：分布式训练能显著提升吞吐，但并非无条件线性加速。当全局批次大小（每卡批次×卡数）变化时，学习率通常需要按比例调整（例如线性缩放规则），否则可能破坏训练稳定性。此外，通信开销、数据加载瓶颈都会影响实际加速比，需要结合监控判断。

损失函数与优化器选择

语言模型训练的本质是“猜下一个词”。想象你在读一本小说，每读到一个词之前，模型都要根据前文预测这个词是什么。预测得越准，损失越小。这个“准不准”的度量就是交叉熵损失（CrossEntropyLoss）。它衡量的是模型预测的概率分布与真实下一个token之间的差异。在PyTorch中，交叉熵损失内部已经包含了softmax，所以模型输出logits即可，不需要额外加softmax层。

实际训练中，序列会有padding（填充）部分，这些位置不参与损失计算。通过ignore_index=-100告诉损失函数忽略标签为-100的位置，这是Hugging Face等库的常见约定。下面代码展示了损失函数的定义方式：

python
import torch.nn as nn
criterion = nn.CrossEntropyLoss(ignore_index=-100)  # 忽略padding位置

优化器方面，Transformer类模型首选AdamW。标准Adam将权重衰减混入梯度更新，而AdamW将权重衰减与梯度更新解耦，更符合正则化的本意，训练更稳定。学习率策略上，常用“预热+余弦衰减”：训练初期用较小的学习率逐步升高（预热），避免早期梯度剧烈更新；后期余弦式下降，帮助模型收敛到更平坦的极小值。例如，总训练步数10000步，预热1000步，初始学习率5e-5：

python
from transformers import AdamW, get_cosine_schedule_with_warmup
optimizer = AdamW(model.parameters(), lr=5e-5, weight_decay=0.01)
scheduler = get_cosine_schedule_with_warmup(
    optimizer,
    num_warmup_steps=1000,
    num_training_steps=10000
)

关键结论：损失函数选交叉熵并忽略padding，优化器选AdamW，学习率采用预热加衰减策略。这三者共同决定了训练能否稳定起步。

训练循环与检查点保存

训练循环就像工厂的流水线：取一批数据（前向传播）、计算损失、反向传播求梯度、更新参数，周而复始。每一步的顺序很重要，尤其是optimizer.zero_grad()的位置——如果忘记清零梯度，梯度会累加，导致更新方向错误。下面是一个标准的训练循环骨架，包含前向、损失、反向、更新和定期保存检查点。

python
model.train()
for epoch in range(epochs):
    for step, batch in enumerate(dataloader):
        inputs = batch['input_ids'].to(device)
        labels = batch['labels'].to(device)
        outputs = model(inputs, labels=labels)
        loss = outputs.loss
        loss.backward()
        optimizer.step()
        scheduler.step()
        optimizer.zero_grad()
        if step % 100 == 0:
            torch.save({
                'epoch': epoch,
                'step': step,
                'model_state_dict': model.state_dict(),
                'optimizer_state_dict': optimizer.state_dict(),
                'scheduler_state_dict': scheduler.state_dict(),
                'loss': loss.item()
            }, f'checkpoint-{step}.pt')

为什么检查点要保存优化器状态和调度器状态？因为AdamW内部维护了每个参数的一阶矩和二阶矩估计，学习率调度器也有当前步数。如果只保存模型权重，恢复训练时优化器会“失忆”，学习率也会从头开始，导致训练曲线出现明显跳变。一个完整的检查点应包含：模型参数、优化器状态、调度器状态、当前epoch和step、以及损失值。这样即使训练中断，也能从断点无缝继续。

关键结论：训练循环的顺序是前向→损失→反向→更新→清零；检查点必须保存模型、优化器、调度器和步数，缺一不可。

常见训练问题与调试

训练大模型时，问题往往不是“能不能跑”，而是“跑得对不对”。最常见的三类问题是：损失不下降、梯度爆炸、显存不足。损失不下降时，先别急着改模型，按顺序排查：学习率是否过大或过小、数据标签是否正确对齐、模型初始化是否合理。一个实用的技巧是先用一个极小批次（例如2条样本）过拟合，如果损失都降不下去，说明代码有bug，而不是数据不够。

梯度爆炸表现为损失突然变成NaN或剧烈震荡。此时可以使用梯度裁剪，将梯度的范数限制在阈值内，例如max_norm=1.0。这相当于给梯度“限速”，防止参数更新步子迈得太大。显存不足则可以通过减小批次大小、使用梯度累积（模拟更大批次）、或混合精度训练来缓解。混合精度用FP16计算前向和反向，用FP32维护主权重，既能省显存又能加速。下面是一个混合精度训练的片段：

python
from torch.cuda.amp import autocast, GradScaler
scaler = GradScaler()
with autocast():
    outputs = model(inputs, labels=labels)
    loss = outputs.loss
scaler.scale(loss).backward()
scaler.step(optimizer)
scaler.update()

注意，使用混合精度时，梯度裁剪应在scaler.unscale_(optimizer)之后进行，否则裁剪的是被缩放过的梯度，阈值会失真。调试时建议打开日志，记录损失、学习率、梯度范数，形成“训练仪表盘”。关键结论：梯度裁剪和混合精度是稳定训练的利器，但要注意使用顺序和缩放细节。

常见误区

  • 错误理解：学习率越大训练越快。→ 后果：过大的学习率会导致损失震荡甚至发散，模型无法收敛。→ 正确做法：使用预热（warmup）让学习率从较小值逐步升高，再配合余弦衰减等策略，并根据全局批次大小调整学习率。
  • 错误理解：检查点只保存模型权重就够了。→ 后果：恢复训练时优化器状态和调度器状态丢失，学习率重置，训练曲线出现跳变，甚至需要从头训练。→ 正确做法：保存模型参数、优化器状态、调度器状态、当前epoch和step，以及损失值。
  • 错误理解：分布式训练一定比单卡快。→ 后果：如果通信开销大或每卡批次太小，加速比可能很低，甚至比单卡还慢。→ 正确做法：监控通信与计算占比，适当增大每卡批次，使用高效的通信后端（如NCCL），并评估实际加速比。

自测

为什么训练大语言模型通常使用AdamW而不是标准Adam？

答案：标准Adam将权重衰减直接加到梯度上，相当于在梯度更新中混入了正则项，这与自适应学习率的缩放耦合在一起，导致权重衰减的效果不纯粹。AdamW将权重衰减与梯度更新解耦，单独对参数做衰减，更符合正则化的本意。对于Transformer类模型，这种解耦能带来更稳定的训练和更好的泛化，因此成为大语言模型训练的默认选择。

保存检查点时除了模型参数，还应该保存什么？为什么？

答案：还应保存优化器状态（如AdamW的一阶矩和二阶矩）、学习率调度器状态、当前epoch和step。因为恢复训练时，优化器需要这些状态来继续正确的参数更新，调度器需要当前步数来计算学习率。如果只保存模型权重，优化器会重新初始化，学习率也会从头开始，导致训练曲线出现跳变，甚至影响最终效果。

在混合精度训练中，为什么梯度裁剪要在scaler.unscale_(optimizer)之后进行？

答案：混合精度训练使用GradScaler对损失进行放大，以避免FP16下梯度下溢。因此反向传播得到的梯度是被放大过的。如果直接对这些梯度做裁剪，裁剪阈值（如1.0）实际上是作用在放大后的梯度上，导致裁剪过猛或失效。正确做法是先调用scaler.unscale_(optimizer)将梯度还原到真实尺度，再进行裁剪，最后调用scaler.step(optimizer)和scaler.update()。

动手练习（带参考方案）

练习 · 编写一个完整的训练脚本，使用PyTorch训练一个线性回归模型。要求：1）生成100条带噪声的线性数据；2）使用均方误差…

任务：编写一个完整的训练脚本，使用PyTorch训练一个线性回归模型。要求：1）生成100条带噪声的线性数据；2）使用均方误差损失和AdamW优化器；3）每10个epoch打印损失并保存检查点（包含模型、优化器状态和epoch）；4）训练100个epoch后，打印最终损失。验收标准：脚本可独立运行，输出损失逐渐下降，并在当前目录生成多个checkpoint文件。

参考方案：

python
import torch
import torch.nn as nn
import torch.optim as optim

# 1. 生成数据：y = 3x + 2 + 噪声
torch.manual_seed(42)
X = torch.randn(100, 1)
y = 3 * X + 2 + 0.1 * torch.randn(100, 1)

# 2. 定义模型、损失函数和优化器
model = nn.Linear(1, 1)
criterion = nn.MSELoss()
optimizer = optim.AdamW(model.parameters(), lr=0.01)

# 3. 训练循环
for epoch in range(100):
    model.train()
    optimizer.zero_grad()
    outputs = model(X)
    loss = criterion(outputs, y)
    loss.backward()
    optimizer.step()

    if epoch % 10 == 0:
        print(f'Epoch {epoch}, Loss: {loss.item():.4f}')
        torch.save({
            'epoch': epoch,
            'model_state_dict': model.state_dict(),
            'optimizer_state_dict': optimizer.state_dict(),
            'loss': loss.item()
        }, f'checkpoint-{epoch}.pt')

print(f'Final Loss: {loss.item():.4f}')
