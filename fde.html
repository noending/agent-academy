FDE 能力地图

FDE（Forward Deployed Engineer，前置部署工程师）是 OpenAI、Anthropic、Palantir 增长最快的岗位： 驻在客户现场，把通用模型能力转化为可交付、可维护、可续约的智能体系统——工程 50% + 方案设计 25% + 客户沟通 25%。 本页把课程的每一章映射到 FDE 的能力栈，标出课程之外的补齐清单，并给出一个 90 天养成计划。

🎯 目标：课程 → 岗位能力的完整映射 📋 企业级交付清单 🗓 90 天计划

① 什么是 FDE，为什么现在值得成为 FDE

FDE 最早由 Palantir 大规模实践（其 AIP 部署团队就是这个模型），如今 OpenAI 与 Anthropic 的客户成功工程团队都在批量招聘。它与传统后端工程师的分野在于：

传统后端工程师FDE
交付物确定性系统：输入定了输出就定了概率性系统：要为「回答质量」这种模糊指标建立度量与回归
需求来源产品经理转译的 PRD直接面对客户：从模糊的业务诉求中拆出可验收的技术方案
核心难点正确性、性能、并发可靠性、幻觉治理、数据合规、期望管理
护城河架构与编码深度「敢承诺指标」：敢对客户说「准确率 ≥ 85%，达不到不收费」——背后是评估体系（第 8 章）

对标 · 我们站在谁的肩膀上

④ 课程之外的五块拼图

  1. 企业级前端：从 Gradio 到 React + SSE

    课程交付到「内部工具级」。客户级系统还差三步：① 服务端流式——FastAPI 用 SSE 逐 token 推送（代码见下）；② 前端消费流——React 里用 fetch + ReadableStream 渲染打字机效果；③ 会话与权限 UI——登录态（SSO/OAuth）、会话列表、工具审批卡片。前端不必精通，但要能独立交付一个「能流式对话、能审批、能看历史」的界面。

    javascript · 前端消费 SSE 流（20 行核心）
    async function chat(message, onDelta) {
  const res = await fetch("/chat", {
    method: "POST",
    headers: { "Content-Type": "application/json" },
    body: JSON.stringify({ message, session_id }),
  });
  const reader = res.body.getReader();
  const decoder = new TextDecoder();
  let buf = "";
  while (true) {
    const { done, value } = await reader.read();
    if (done) break;
    buf += decoder.decode(value, { stream: true });
    const lines = buf.split("\n\n"); buf = lines.pop();
    for (const line of lines) {
      if (!line.startsWith("data: ")) continue;
      const payload = line.slice(6);
      if (payload === "[DONE]") return;
      onDelta(JSON.parse(payload).delta);   // 逐 token 上屏
    }
  }
}

    服务端对应第 8 章的 StreamingResponse 骨架——前后端合起来就是一条完整的流式链路。

  2. 数据工程基础

    企业知识不躺在 PDF 里，躺在数据库和数仓里。SQL 要能熟练读写（JOIN/窗口函数），了解 CDC 增量同步（Debezium 类工具）与 Airflow 级别的调度概念——FDE 的一半时间在与客户的数据库打交道。

  3. 云与交付基建

    Docker 容器化（把毕业项目写进 Dockerfile）、云函数/容器服务部署、SSO/OAuth 对接（客户的登录体系你无法绕过）、密钥管理（Vault/云 KMS）、日志与告警。这门课刻意零依赖，企业里这些是标配。

  4. 行业纵深

    FDE 的溢价来自「行业 × Agent」的组合。选一个行业深耕半年：金融（合规审查、研报）、医疗（病历结构化、随访）、制造（工单、质检）、法律（合同审查）。行业术语表本身就是一个值得建的小本体（第 6 章练习 1 的放大版）。

  5. 沟通与演示

    FDE 的独特技能：用 demo 卖方案（一个 5 分钟可复现的演示胜过 30 页 PPT）、期望管理（把「准确率 85%」讲成客户能理解的业务语言）、以及把客户的模糊抱怨转写为评估用例的能力（第 8 章「用户反馈 → 回归层」的对外版本）。

⑤ 90 天 FDE 养成计划

  1. 第 1–30 天 · 完成课程主线

    9 章全部学完，练习做一半，自测全过；毕业项目四个里程碑验收通过。产出：ScholarMate 仓库（含评估集与 Trace）。

  2. 第 31–60 天 · 把毕业项目「企业化」

    ① FastAPI 服务化 + SSE 流式 + React（或 Gradio 升级版）前端；② Docker 化 + 云上部署（哪怕一台最便宜的云主机）；③ 加 SSO 登录与操作审计日志；④ CI 里每天自动跑评估集并出报告；⑤ 写一页「部署架构图 + 成本模型」。产出：一个公网可访问、带权限、有评估看板的系统。

  3. 第 61–90 天 · 做一个真实交付

    找一个真实场景（你公司的内部流程、家人的小生意、社团的管理事务），完整走一遍 FDE 流程：客户访谈 → competency questions → 知识库 + Agent → 评估集 → 上线 → 收集反馈迭代两轮。产出：一份 case study（问题 → 方案 → 指标 → 客户证言）——这就是 FDE 岗位面试的核心材料。

✅ 面试准备清单

FDE 面试高频题与你的弹药：①「怎么处理幻觉」→ 第 4 章失败模式 + ReAct 论文的 0% vs 56% 数据；②「怎么保证质量不回退」→ 第 8 章评估集三层结构；③「怎么算成本」→ CostMeter + 前缀缓存；④「数据安全怎么办」→ 权限分级 + 沙箱 + 自托管；⑤「给我们设计一个 XX Agent」→ 现场走一遍 competency questions 方法论。每一题都有本站的章节与论文背书。

⑦ 能力成绩单：八维雷达（随实训点亮）

进度不该是「读了几章」，而是「能干什么」。八项能力各对应一份实训产出，完成勾选后雷达点亮。数据存浏览器本地。
