推理性能与成本评测

本章目标：能测量TTFT、TPOT、吞吐等指标，计算每次请求成本。

3.1 性能指标：从用户点击到最后一个字

想象你去餐厅点餐：TTFT 是“下单到第一道菜上桌”的时间，TPOT 是“吃完一道菜到下一道菜上桌”的平均间隔，端到端延迟 是“从下单到吃完最后一道菜”的总时间。对 LLM 推理来说，用户感知的“快”往往由 TTFT 决定，而“完成快”则由 TPOT 和输出长度共同决定。

具体定义：

  • TTFT (Time to First Token)：从发送请求到收到第一个输出 token 的时间，包含网络、排队、prefill 计算。
  • TPOT (Time per Output Token)：生成阶段每个输出 token 的平均耗时，通常等于 (端到端延迟 - TTFT) / (输出 token 数 - 1)。
  • ITL (Inter-Token Latency)：相邻两个输出 token 之间的时间间隔，TPOT 是 ITL 的平均值。
  • 吞吐量 (Throughput)：单位时间内系统处理的 token 总数或请求数，常用 tokens/s 表示。
  • 并发 (Concurrency)：同时处理的请求数量，直接影响吞吐和延迟。
  • P50/P95/P99：延迟的百分位数，P95 表示 95% 的请求延迟低于该值，比平均值更能反映尾部体验。
  • 成功率/错误率/超时率：成功完成的请求比例、返回错误的比例、超过设定时限的比例。

下面是一个最小可运行示例，用 Python 模拟测量这些指标（实际中需替换为真实 API 调用）：

import time
import random

def mock_llm_call(prompt, max_tokens=50):
    """模拟一次流式 LLM 调用，返回每个 token 的时间戳。"""
    # 模拟 prefill 和排队
    ttft = random.uniform(0.1, 0.5)
    time.sleep(ttft)
    timestamps = [time.time()]
    # 模拟生成 token
    for _ in range(max_tokens - 1):
        time.sleep(random.uniform(0.01, 0.05))
        timestamps.append(time.time())
    return timestamps

def measure(prompt):
    start = time.time()
    timestamps = mock_llm_call(prompt)
    end = time.time()
    ttft = timestamps[0] - start
    tpot = (end - timestamps[0]) / (len(timestamps) - 1) if len(timestamps) > 1 else 0
    e2e = end - start
    return {"ttft": ttft, "tpot": tpot, "e2e": e2e, "output_tokens": len(timestamps)}

# 模拟 10 次请求
results = [measure("你好") for _ in range(10)]
for i, r in enumerate(results):
    print(f"请求{i+1}: TTFT={r['ttft']:.3f}s, TPOT={r['tpot']:.3f}s, E2E={r['e2e']:.3f}s")

# 计算 P50/P95
import statistics
ttfts = sorted([r['ttft'] for r in results])
p50 = ttfts[len(ttfts)//2]
p95 = ttfts[int(len(ttfts)*0.95)]
print(f"TTFT P50={p50:.3f}s, P95={p95:.3f}s")

关键结论：首字快不等于完成快，单用户快不等于并发快。 评估时必须同时看 TTFT、TPOT 和吞吐，并在目标并发下测量。

3.2 评测条件记录：让结果可复现

性能数字脱离条件毫无意义。就像说“我跑得很快”，必须说明是百米还是马拉松、顺风还是逆风。LLM 推理评测必须记录以下条件：

  • 模型版本：具体到 commit 或日期，如 llama-3-8b-instruct-2024-04。
  • 硬件：GPU 型号、数量、显存、互联方式（NVLink/PCIe）。
  • 推理框架：vLLM、TensorRT-LLM、TGI 等及版本。
  • 精度：FP16、BF16、INT8、INT4 等。
  • 输入/输出长度：平均和分布，如输入 512 tokens、输出 128 tokens。
  • 并发与批处理：并发请求数、最大 batch size、是否启用 continuous batching。
  • 缓存：是否启用 KV Cache、prefix caching。
  • 预热：是否预热、预热次数，避免冷启动影响。
  • 测试次数：至少 100 次以上，报告 P50/P95/P99。

下面是一个记录评测条件的 JSON 模板，可直接用于实验日志：

import json

config = {
    "model": "meta-llama/Llama-3-8B-Instruct",
    "model_revision": "main@2024-04-18",
    "hardware": "NVIDIA A100 80GB x1",
    "framework": "vLLM 0.4.2",
    "dtype": "bfloat16",
    "input_length": {"mean": 512, "p95": 1024},
    "output_length": {"mean": 128, "p95": 256},
    "concurrency": 10,
    "max_batch_size": 32,
    "enable_prefix_caching": True,
    "warmup_runs": 5,
    "test_runs": 200,
    "timeout_seconds": 30
}
print(json.dumps(config, indent=2))

关键结论：没有条件记录的 benchmark 等于没有 benchmark。 报告结果时，必须附带上述条件，否则无法横向比较。

3.3 成本计算：从每百万 Token 到每个成功任务

云厂商常标“每百万 Token 价格”，但业务成本要看每个成功任务花了多少钱。类比：买菜看单价，但请客吃饭要看“一桌菜总价”，还要算上烧焦重做的成本。

成本计算步骤：

  1. 每百万 Token 价格：输入和输出通常不同价，如输入 $0.5/M，输出 $1.5/M。
  2. 每次请求成本 = (输入 tokens / 1e6) * 输入单价 + (输出 tokens / 1e6) * 输出单价。
  3. 考虑重试：如果失败率 5%，则平均请求次数 = 1 / (1 - 0.05) ≈ 1.053。
  4. 工具调用和额外推理：Agent 场景可能多次调用 LLM，需累加。
  5. 每个成功任务成本 = 总成本 / 成功任务数。

下面是一个计算示例：

def cost_per_request(input_tokens, output_tokens, price_in_per_m, price_out_per_m):
    return (input_tokens / 1e6) * price_in_per_m + (output_tokens / 1e6) * price_out_per_m

def cost_per_success(input_tokens, output_tokens, price_in, price_out, success_rate, retries_per_failure=1):
    base = cost_per_request(input_tokens, output_tokens, price_in, price_out)
    # 平均尝试次数 = 1 + (1 - success_rate) * retries_per_failure
    avg_attempts = 1 + (1 - success_rate) * retries_per_failure
    total_cost = base * avg_attempts
    return total_cost / success_rate  # 分摊到每个成功任务

# 示例：输入 500 tokens，输出 200 tokens，输入 $0.5/M，输出 $1.5/M，成功率 95%
base = cost_per_request(500, 200, 0.5, 1.5)
print(f"单次请求成本: ${base:.6f}")
per_success = cost_per_success(500, 200, 0.5, 1.5, 0.95)
print(f"每个成功任务成本: ${per_success:.6f}")

关键结论：最低单价不等于最低业务成本。 必须把重试、工具调用、超时和失败率纳入计算。

常见误区

  • 首字快（TTFT 低）不等于完成快，如果 TPOT 很高，长输出的端到端延迟仍然很大。
  • 单用户测试快不等于并发快，高并发下排队和批处理会导致延迟显著上升。
  • Tokens/s 不可直接比较，必须结合输入输出长度、并发数、硬件和精度等条件。
  • 最低单价不等于最低业务成本，需考虑重试、工具调用、超时和失败率。

自测

某模型 TTFT=0.2s，TPOT=0.05s，输出 100 个 token，端到端延迟大约是多少？如果 TPOT 变为 0.1s，端到端延迟变为多少？

答案：端到端延迟 ≈ TTFT + TPOT × (输出 token 数 - 1) = 0.2 + 0.05 × 99 = 5.15s。若 TPOT=0.1s，则 0.2 + 0.1 × 99 = 10.1s。说明 TPOT 对长输出影响巨大。

为什么报告 P95 延迟比平均延迟更有意义？

答案：平均延迟会被大量快请求拉低，掩盖尾部慢请求。P95 表示 95% 的请求延迟低于该值，能反映最差 5% 用户的体验，对 SLA 和容量规划更关键。

参考方案：

import time import random import statistics def mock_llm_call(input_tokens, output_tokens): # 模拟 prefill 和排队 ttft = random.uniform(0.1, 0.6) time.sleep(ttft) timestamps = [time.time()] for _ in range(output_tokens - 1): time.sleep(random.uniform(0.01, 0.06)) timestamps.append(time.time()) return timestamps def measure(input_tokens, output_tokens): start = time.time() timestamps = mock_llm_call(input_tokens, output_tokens) end = time.time() ttft = timestamps[0] - start tpot = (end - timestamps[0]) / (len(timestamps) - 1) if len(timestamps) > 1 else 0 e2e = end - start return ttft, tpot, e2e results = [measure(800, 300) for _ in range(100)] ttfts = sorted([r[0] for r in results]) tpots = sorted([r[1] for r in results]) e2es = sorted([r[2] for r in results]) def percentile(data, p): idx = int(len(data) * p) return data[min(idx, len(data)-1)] print(f"TTFT P50={percentile(ttfts,0.5):.3f}s, P95={percentile(ttfts,0.95):.3f}s, P99={percentile(ttfts,0.99):.3f}s") print(f"TPOT P50={percentile(tpots,0.5):.3f}s, P95={percentile(tpots,0.95):.3f}s, P99={percentile(tpots,0.99):.3f}s") print(f"E2E P50={percentile(e2es,0.5):.3f}s, P95={percentile(e2es,0.95):.3f}s, P99={percentile(e2es,0.99):.3f}s") # 成本计算 input_tokens = 800 output_tokens = 300 price_in = 0.6 # $/M price_out = 1.8 # $/M success_rate = 0.98 retries_per_failure = 1 base_cost = (input_tokens / 1e6) * price_in + (output_tokens / 1e6) * price_out avg_attempts = 1 + (1 - success_rate) * retries_per_failure total_cost = base_cost * avg_attempts cost_per_success = total_cost / success_rate print(f"单次请求成本: ${base_cost:.6f}") print(f"每个成功任务成本: ${cost_per_success:.6f}")
